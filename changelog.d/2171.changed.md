- **feat(modules): every route belongs to a module; all optional modules can be switched off (#2171, spec #2166).** The module registry (`internal/featureflag` `Modules`) now lists every module, core and optional, and the module gate covers every route. Optional modules: Risk (with action plans, org units, themes, aggregation rules and the decision log), Third-party risk, Policies, Questionnaires, Personnel security (new switch `personnel.enabled`, on), Exceptions and Board reporting (still off by default). A nested route belongs to the module whose data it returns: `/v1/controls/{id}/risks` and `/action-plans` are Risk, `/v1/controls/{id}/policies` is Policies. Core modules have no switch. **Breaking for API clients:** the flag key `oscal.export` is renamed `vendor.claims` (a feature of Third-party risk; migration `20261130000000` moves each tenant's stored value), and `GET /v1/me/modules` now reports Third-party risk with Vendor claims nested under `features` instead of a top-level `vendor_claims` module. The OSCAL SSP and POA&M export becomes the `audit.oscal_export` feature of Audit periods, on by default. `risk.enabled`, `vendor.enabled`, `policy.enabled` and `exceptions.enabled` were stored but read by nothing; they now hide their module, so the migration sets any stored `false` on them back to `true` (with an audit-log row) and no tenant loses a module on deploy. Note from #2170: `GET /v1/features/enabled` was removed in favour of `GET /v1/me/modules`. Guard test `TestEveryRouteBelongsToAModule` fails CI on a route no module owns.
