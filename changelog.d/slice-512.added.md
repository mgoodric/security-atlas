- **feat(oscal): slice 512 — OSCAL component-definition import (vendor control-implementation claims as evidence).** Slice 492 shipped OSCAL _catalog_ import and slice 511 _profile_ import; this slice adds _component-definition_ import — the inbound complement to the platform's own SSP export. A component-definition is the **vendor-side** artifact: a software/service vendor ships it to assert "this product implements control X this way" (per defined-component, a list of `control-implementations` → `implemented-requirements`, each targeting a control id with an implementation statement). The customer ingests each implemented-requirement as **vendor-attributed control-implementation evidence**. A new `ImportComponentDefinition` RPC extends the existing `oscal-bridge` (never a second process — P0-512-7); the bridge deserializes + validates via compliance-trestle's `ComponentDefinition` model. **The load-bearing invariant (P0-512-1 / threat-model E — elevation): a vendor's implemented-requirement is an ASSERTION, not platform-verified evidence — it does NOT auto-satisfy a control or fabricate coverage.** Imported requirements land as vendor-attributed CLAIMS (`is_vendor_claim=TRUE` CHECK-pinned, `claim_status='asserted'`); the persistence shape carries no satisfied/active boolean an import could flip, and the import writes ZERO `control_evaluations` rows (invariant #2 — ingestion never touches the evaluation surface) and ZERO `accepted` claims — surfacing a claim as satisfied requires the existing operator action, never automatic. This keeps the import inside the CLAUDE.md fabricate-coverage boundary even though no LLM is involved. **No external dereference (P0-512-2 / threat-model I):** `ComponentDefinition(**doc)` is a pure pydantic parse that fetches nothing; the bridge reads only in-document prose (requirement description + statement prose) and treats `links` / `source` / back-matter `href` as opaque metadata — proven by a bridge unit test that monkeypatches `socket.connect` to raise while parsing a document carrying external hrefs. Caps bound the expansion surface (threat-model D / AC-3): 16 MiB byte cap (Go-side before the wire + bridge-side), 1,000-component cap, 50,000 total-claim cap. A Go `internal/oscal/componentimport` caller persists the components + claims **transactionally** (a validation failure commits nothing — AC-5 / P0-512-4); each claim maps its target requirement → SCF anchor only (invariant #7 / P0-512-3), reusing slice-492's deterministic crosswalk (unmatched = `scf_anchor_id NULL`, "needs operator mapping", never dropped). The import-run provenance row + append-only audit log reuse the slice-492/511 tables (new `kind='component_definition'` discriminator value, `source='oscal-component-import'`, audit actions `component_definition_imported` / `component_definition_import_rejected`); the components + vendor claims live in two **new sibling tables** `imported_components` + `imported_component_claims` (migration `20260608010000_oscal_component_definitions.sql`, additive; four-policy FORCE RLS on both), because a component-definition is a vendor-CLAIM hierarchy, not a control set — keeping a claim distinguishable from a control row is what P0-512-1 depends on. `tenant`-scoped + `grc_engineer`-gated (P0-512-6); the bundled SCF spine (`scf_anchors`) is never touched (P0-512-5). CLI `atlas-oscal import-component-definition <file> [--json]` (AC-9). The Go-side reconciliation + no-auto-satisfy logic is testable WITHOUT the bridge (pure-Go `helpers_test.go`); the end-to-end import + the no-auto-satisfy invariant + tenant isolation + malformed-rollback are proven at the Go integration tier (real Postgres + real bridge, self-skipping when the compliance-trestle bridge subprocess is unavailable — slice-030 D2), and the parse + no-deref + cap enforcement at the bridge unit tier (pytest). **Type: JUDGMENT** — the sibling-tables-vs-`kind`-reuse model call, the schema-enforced CLAIM-not-satisfaction shape, the SCF reconciliation, the statement-flattening, and the no-external-deref design recorded with detection-tier in `docs/audit-log/512-oscal-component-definition-import-decisions.md`.
