- **fix(oidc): OIDC sign-in uses the SSO settings an admin saves (#2034).** The production binary used a resolver that knew no IdP, so `/auth/oidc/login` refused every tenant and nothing saved on the SSO page applied. Sign-in now reads the tenant's `oidc_idp_configs` row under RLS: the issuer, client, client secret, `allowed_email_domains` (exact, case-insensitive, verified address only) and `trust_unverified_email_for_link`. An unknown IdP, another tenant's config, or a config that cannot be used (non-https issuer, unreadable secret) is refused, with no fallback. Client secrets are now sealed with AES-256-GCM under the new `ATLAS_OIDC_SECRET_KEY` (or `_FILE`). Upgrade note: set that key, then re-enter the client secret on the SSO page. Secrets saved before this release are refused at sign-in until they are re-entered. `ATLAS_OIDC_LOCAL_MODE=true` (dev only) turns OIDC sign-in off.
