- **feat(connectors): slice 535 — monitoring alert-firing-history (Datadog + Grafana).** Adds the firing-history sibling of slice 488's `monitoring.alert_config.v1` config-inventory kind: a new vendor-neutral evidence kind `monitoring.alert_firing.v1` emitted by **both** the Datadog and Grafana connectors — one record per firing event (`source_vendor`, `rule_id`, `state` [alerting/resolved/no_data/pending], `fired_at`, `resolved_at`, and the routing-target **handle**). Slice 488 reads which alerts are _configured_ (SOC 2 CC7.2); this reads what actually _fired_ and resolved (CC7.3/CC7.4 — the entity evaluates events and responds). A shared `connectors/monitoring/firing` normalization layer (`firing.Collect` / state folding / email-handle PII drop / `Firing` + `RawFiring` structs) + a shared `connectors/monitoring/firingrecord` builder (mirroring `alertcfg`/`monrecord`) + a new `idem.AlertFiringKey` keyed on `(vendor, rule_id, fired_at)` so overlapping-window re-reads do not double-write. **Datadog** (`connectors/datadog/internal/firingevents`): bounded pull of monitor-alert events via the read-only Events API (`GET /api/v1/events?sources=monitor_alert`, new `events_read` scope) with a bounded time-windowed page loop (`maxPages=50`×`pageLimit=100` ⇒ 5,000 events, 60s timeout, `--datadog-firing-lookback` default 24h). **Grafana** (`connectors/grafana/internal/alerthistory`): bounded pull of alert-instance state-history via the read-only state-history API (`GET /api/v1/rules/history`, Viewer role) capped at `maxTransitions=5000` (`--grafana-firing-lookback` default 24h). **Profile JUDGMENT: bounded pull, honestly named** — neither vendor source offers a first-class push the connector receives (Datadog Events API + Grafana state-history are both query surfaces), so `profiles_supported=[pull]` is accurate; no "continuous monitoring"/"event-driven" mislabel (P0). **Information Disclosure (DOMINANT) structural guard:** the `firing.RawFiring`/`Firing` structs physically cannot hold the alert message body, the triggering metric values, the secret webhook URL, or recipient PII — a reflection guard (`TestStructuralOverCollectionGuard`) fails the build if a forbidden field is added, and per-vendor drop tests feed a source event carrying all four and assert none reaches a record. **DoS (load-bearing):** bounded per-run window + event/transition cap + run timeout on both vendors. No platform-side wire change (push only — invariant #3); read-only least-privilege source scope per vendor; no source key/token logged. Registered in `DefaultSeed` with schema `monitoring.alert_firing/1.0.0.json`; anchors **MON-01 + IRO-09** (the spec candidate IRO-02 is absent from the bundled SCF fixture, so IRO-09 — the closest present incident anchor — is used; see decisions log D3). **Type: JUDGMENT** — the profile-shape call, the `(vendor, rule_id, fired_at)` dedup key, the anchor substitution, and the firing-events-only structural guard are recorded in `docs/audit-log/535-monitoring-alert-firing-decisions.md`.
