- **fix(auth): alert super-admins when SCIM deprovisions a tenant's last admin; lock the admin roster at OIDC login only when an admin role is revoked; move every advisory lock onto a namespaced registry (#2273).** A SCIM `active=false` (PUT or PATCH) or `DELETE` that leaves a tenant with no active admin still succeeds. In the same transaction it now writes a `tenant_last_admin_deprovisioned` row to `scim_audit_log` and sends every active super-admin an in-app `tenant.last_admin_deprovisioned` notification in their own tenant, which the email, Slack and webhook digests deliver. The `scim_audit_log.action` CHECK gains the new value and keeps the existing six (migration `20261242000000`). The group-role resolver takes the tenant's admin-roster lock only when the derived plan would revoke the user's `admin` role, so ordinary OIDC logins no longer serialise. Every Postgres advisory lock now uses the two-int form `pg_advisory_xact_lock(ns, key)` with a namespace registered in `internal/db/advisorylock`, and a test fails on any single-bigint or unregistered lock in the tree.
