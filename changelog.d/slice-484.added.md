- **feat(catalog): slice 484 — framework-versioning capability (version lifecycle + exact-code migration-suggest + version-aware reads).** Ships the capability layer the canvas §3.3 commits to: multiple live versions of ONE framework, with the version pin as an audit-correctness boundary. A new admin-gated version lifecycle promotes a version to `current` and demotes the prior current version to `legacy` (the ADR's "superseded" semantic, reusing the existing enum value — there is no `superseded`/`deprecated` value on `main`, so `legacy` = replaced-but-still-valid, distinct from `withdrawn`), repoints `frameworks.latest_version_id`, writes an append-only `framework_version_audit` row in the same transaction, and is reversible (`POST /v1/admin/framework-versions/{id}/promote` + `.../revert`). A migration-suggest job (`POST /v1/admin/framework-versions/migrations:suggest`) compares two adjacent versions of the same framework and writes EXACT requirement-code 1:1 carryovers into a human-reviewed `framework_version_migrations` queue, flagging the added/removed remainder; it NEVER auto-applies — a human approves/rejects each suggestion one at a time, audited (`.../migrations/{id}/decision`), operationalizing the "no auto-approve its own mappings" AI-assist boundary (P0-484-1). A `current` version's requirements are immutable: a DB trigger (`trg_framework_requirement_immutability`) rejects an in-place UPDATE of a frozen (current/legacy/withdrawn) version's requirement (§3.3 / P0-484-2), layered with a grant backstop (`atlas_app` holds SELECT-only on `framework_requirements`); DELETE is allowed so version teardown/GC still works. Version-aware reads: `GET /v1/anchors/{id}/requirements` + `/coverage` pinned with `?framework_version=slug:version` return ONLY that version's requirements with no cross-version bleed (the load-bearing P0-484-5 property), absent the pin default to each framework's `current` version (new `ListRequirementsForAnchorCurrentVersions` query), and `legacy` versions are readable only when explicitly pinned (never the default, never hidden). The SCF anchor-detail page (`web/`) gains a framework-version selector that drives the pinned re-fetch. The new catalog tables carry no tenant RLS (the gate is admin-role authz + append-only audit, mirroring slice 483); the version-migration queue's intra-framework requirement→requirement FKs are NOT an invariant-#1 crosswalk (P0-484-4 / invariant #7) and the slice-007 FK guard was refined to recognize that. The proof loads a synthetic adjacent SOC 2 revision (`2017-synthetic-rev`) alongside SOC 2:2017 and demonstrates coexistence + suggest + no-bleed pinned reads against real Postgres. Migration `20260612090000_framework_versioning.sql` is additive + reversible (down→up round-trip verified). Implements [ADR 0019](docs/adr/0019-framework-versioning-capability.md).
