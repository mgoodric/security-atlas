- **fix(ci): scheduler `TestRun_FiresInlineSweepAndExitsOnCancel` deadline race (chronic integration flake).** The metrics-scheduler Run-loop integration test (`internal/metrics/scheduler/integration_test.go`) intermittently failed on the `Go · integration (Postgres RLS)` job with `post-Run observations = 0; want >= 1` and was always just rerun (~10+ occurrences across sessions, blocking unrelated PRs). **Root cause:** the test handed `Run(ctx, 5s)` a single `context.WithTimeout(..., 500ms)` and then asserted on the DB row count. `Run` fires its inline pre-tick sweep SYNCHRONOUSLY on that same caller context (`worker.go`), so the 500ms deadline had to cover the entire `ListTenantsForMetricsScheduler` → per-tenant `BEGIN` → N-evaluator `Compute` → `InsertMetricObservation` → `COMMIT` cycle. Under the serialized `-p 1 -race` job that work routinely exceeds 500ms; the deadline fired mid-sweep, the `COMMIT` returned `context.Canceled`, the sweep wrapper swallowed it (`!errors.Is(err, context.Canceled)`), zero rows landed, and the `>= 1` assert failed. **Fix (decouples inline-sweep COMPLETION from the cancel DEADLINE):** a minimal additive production hook on `Scheduler` (`onInlineSweep func(SweepReport, error)`, set via the in-package `setInlineSweepHook`, bridged to the external test package by `export_test.go`'s `SetInlineSweepHookForTest`) surfaces the inline sweep's RETURNED `SweepReport`. The production caller (`cmd/atlas/main.go` `ms.Run`) never sets it — `Run`'s signature, cron cadence, and error-swallowing are byte-for-byte unchanged. The test now runs `Run` against a plain `context.WithCancel(context.Background())` (no wall-clock), waits for the hook to report the sweep's `ObservationsWritten >= 1` (deterministic ground truth, no timeout-vs-DB-latency race), THEN cancels separately to prove the ticker loop exits cleanly. Added `TestRun_InlineSweepStress` (5× replay of the full Run→inline-sweep→cancel lifecycle, asserting each iteration's report wrote ≥1 and the append-only DB total tracks the running sum) per the slice-340 5×-stress precedent. Removes the race rather than widening the window (cf. slice 381: no single-sample wall-clock asserts).
