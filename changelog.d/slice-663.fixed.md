- **fix(risks): slice 663 — risk-create fresh-tenant mitigate dead-end (closes 663).** The Add-risk form (`/risks/new`) opened on **Treatment = "mitigate"**, which makes **Linked controls** required (canvas §6.1: mitigate ⇒ ≥1 linked control). On a **fresh tenant with zero instantiated controls** there is nothing to link ("No active controls in this tenant yet"), so the primary create flow **dead-ended for a brand-new operator** — a mitigate-treatment risk could not be created at all (UI-audit **ATLAS-006**). **JUDGMENT D1 — AC-2 option (a):** the form's _opening default_ treatment now lands on **`avoid`** instead of `mitigate`. `avoid` is the only treatment with **zero required satellite fields** (canvas §6.1: `accept` needs accepter + accepted_until; `transfer` needs instrument_reference; `mitigate` needs a linked control; `avoid` is status-only), and it matches the **server's own omitted-treatment safe-default** (`internal/api/risks/handlers.go` falls back to `RiskTreatmentAvoid`), so the default is consistent client-to-server with **no backend change**. Defaulting to `accept` was rejected because the form omits the accept satellite inputs, so it would just move the dead-end (server rejects `accept` without accepted_until + accepter); option (b) — relaxing the mitigate rule when zero controls exist — was rejected because it would diverge client validation from the server's still-strict `ValidateTreatment` (submit-then-500) and weaken a canvas §6.1 invariant for a problem a default solves. **AC-3 preserved:** the mitigate-requires-control rule is UNCHANGED — an operator who selects `mitigate` in any tenant still must link ≥1 control (client `validateRiskForm` + server `ValidateTreatment`), and the existing empty-state affordance in `control-multi-select.tsx` still guides a fresh operator to switch treatment. The opening default is pinned as an exported, documented `DEFAULT_TREATMENT` constant (`web/app/(authed)/risks/new/validate.ts`) so it is unit-testable without the React tree. **Proof:** vitest `web/app/(authed)/risks/new/validate.test.ts` pins that the default is not `mitigate`, is `avoid`, that an empty-tenant default-flow submit (zero linked controls) is valid (AC-1), and that switching to mitigate still requires a control (AC-3); Playwright `web/e2e/risks-create.spec.ts` adds an AC-1 regression guard — a fresh tenant (zero controls, `/api/controls-list` mocked empty) creates a risk through the **untouched** default flow (the control picker is not even rendered), posting `treatment=avoid` and routing back with the new row; the existing `risks-create-control-link.spec.ts` specs are updated to select `mitigate` explicitly now that it is no longer the opening default. **No wire/schema/backend change:** `git diff --stat origin/main...HEAD -- proto/ migrations/ internal/` is empty (client-default fix only). **Type: JUDGMENT.** Decisions log: `docs/audit-log/663-risk-create-dead-end-decisions.md`.
