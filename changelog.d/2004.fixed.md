- **fix(risk): retry a deadlock between a child link and a risk delete (#2004).** `POST /v1/risks/{id}/children` and `DELETE /v1/risks/{id}` now retry their transaction, up to three attempts, when Postgres aborts it as a deadlock victim (40P01), rather than returning a 500. This covers the window where a risk write takes the tenant's hierarchy lock after its row lock: a rule activated mid-write, or a theme change let through on the last lock-check attempt. Each attempt is a fresh transaction holding every write, so nothing runs twice. The link cap of 100 children now counts distinct ids in the API as it already did for MCP, so a request that only repeats ids is no longer refused for size. A new integration test pins which paths wait on the hierarchy lock and that they take it before any meta-risk key. The risks docs page notes that rule-matched risk writes queue per organisation, which affects bulk importers and connectors. Decisions D11 and D12 in `docs/audit-log/1748-risk-hierarchy-links-decisions.md`.
