- **fix(oauth): rate-limit client authentication on `/oauth/introspect` and `/oauth/revoke` (#2041, follow-up to #1913).** Both endpoints ran an argon2id client-secret verify for any presented `client_id` with no limit. They now apply the token endpoint's per-`client_id` token bucket (default 60/min, `ATLAS_OAUTH_CLIENT_AUTH_RATE_PER_MIN`) and a per-IP bucket (default 120/min, `ATLAS_OAUTH_CLIENT_AUTH_IP_RATE_PER_MIN`, IP resolved through `TRUSTED_PROXY_CIDRS`) before any lookup, answering 429 with `Retry-After`. Unknown and registered `client_id`s are throttled alike. The limiter's memory is bounded too: a `client_id` over 256 bytes is refused 401 `invalid_client` on all three endpoints, refilled buckets are pruned (the token endpoint's limiter included), and the form body on `/oauth/token`, `/oauth/revoke` and `/oauth/introspect` is capped at 64 KiB. Requests within the limit keep their RFC 7009 / RFC 7662 responses. **Upgrade note:** a resource server introspecting more than 60 times a minute under one `client_id` should raise `ATLAS_OAUTH_CLIENT_AUTH_RATE_PER_MIN`.
