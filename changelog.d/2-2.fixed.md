- **feat(demoseed): slice 671 — the demo seed now drives the real evaluator, so a seeded tenant shows real control state instead of "—" (closes 671).** A fully-seeded demo tenant showed **every** control with STATE / FRESHNESS / LAST-OBSERVED = "—", metrics at 0, and an empty "Framework posture", even though 200 evidence records existed (UI-audit ATLAS-019; cascades 022/020/037-posture). **Root cause (by design, not an evaluator bug):** `internal/demoseed` writes the evidence ledger via direct `BYPASSRLS` INSERTs and deliberately does NOT write the `control_evaluations` / `evidence_freshness` read models (seeder.go:31) — those are downstream artifacts of the slice-012/016 evaluator, which in production is driven off the evidence-ingest JetStream stream plus the hourly recompute. The seed bypasses that stream, so nothing ever evaluated the seeded evidence. **Fix:** a shared `demoseed.EvaluateSeededTenant(ctx, appPool, tenantID)` helper drives the REAL evaluator as a SEPARATE stage AFTER `Seeder.Apply` commits — it builds a per-tenant RLS-bound `Engine` via `eval.NewEngineFactory(appPool)`, runs `EvaluateAll(TriggerManual, FarFuture)`, then `freshness.Store.Refresh` — scoped to the seeded tenant via `app.current_tenant` on the app-role pool. Both seed call sites adopt it: the `atlas-cli demo seed` command (new `--app-database-url` flag / `DATABASE_URL_APP` env) and the admindemo "Generate demo data" HTTP handler (new `SetAppPool(s.dbPool)` wiring); it runs on the idempotent re-seed path too. **Invariant #2 held:** evaluation never runs inside the seed's `BYPASSRLS` write tx and never fabricates eval-table rows — it reads the append-only ledger and writes only the read models, so demo state == production semantics. **Invariant #6 held:** evaluation runs as the app role under RLS, scoped to the one seeded tenant. **Proof:** an integration test (`internal/demoseed/evaluate_integration_test.go`) reproduces the symptom (0 `control_evaluations` / 0 `evidence_freshness` / all controls "—" immediately after `Apply`) and asserts the fix (one evaluation row per active control, controls with in-window evidence resolve to concrete pass/fail, idempotent across a second pass); it fails decisively without the fix.
