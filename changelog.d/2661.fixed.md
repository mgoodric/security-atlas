- **fix(authz): `user_roles.user_id` must be canonical when it is a uuid (#2661).** A new CHECK (`user_roles_user_id_canonical_uuid`, migration `20261279000000`) refuses a `user_id` that reads as a uuid (upper-case, braced, `urn:uuid:`, 32-hex or oddly hyphenated) unless it is the lowercase hyphenated form, so the `u.id::text = ur.user_id` deactivation guard in the bulk role query (`internal/moduleaccess/owners.go`) can never miss a disabled user's row. Non-uuid principals (`key_...`, `bootstrap-admin`, `oauth_client:<id>`, `user:<uuid>`) are unaffected. **Upgrade note:** the migration fails loudly, naming the count, if any existing row violates it; no write path produces such rows, so none is expected.
