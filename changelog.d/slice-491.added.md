- **feat(connectors): slice 491 — Rippling + BambooHR HRIS joiner/mover/leaver connectors.** Two read-only HRIS connectors (`connectors/rippling/`, `connectors/bamboohr/`) bring the **authoritative worker roster + joiner/mover/leaver lifecycle** into the evidence ledger — the spine of the access-review (slice 374) + deprovisioning controls (SOC 2 CC6.1/CC6.2/CC6.3). Both follow the locked connector pattern (register-per-run, stable `actor_id`, hour-truncated `observed_at`, scope minimums, vendor-native read-only auth) and emit ONE shared evidence kind, `hris.worker_lifecycle.v1`, built once in a shared `connectors/hris/{worker,workerrecord,idem}` package (the slice-490 MDM two-connector precedent) with a `source_hris` discriminator. **The load-bearing P0 (the HRIS holds the most sensitive PII the platform will ever touch):** the connectors collect **worker-lifecycle facts ONLY** — worker id, employment status, start/end dates, title, department, the opaque manager assignment id, and work email (the only contact field, for the access-review join) — and **structurally exclude** SSN / national id, compensation / salary, home address, bank / payment, benefits / health, performance, date of birth, personal phone, and protected-class data at three layers: (1) the API request asks for only the minimal field set (Rippling `fields=` selector; BambooHR a custom report scoped to the lifecycle fields, never the full-PII directory/employee endpoints), (2) the raw + normalized structs have no field for any excluded value so a leak is a compile error, and (3) tests assert no excluded-PII key/substring reaches an emitted payload AND the request never asks for a banned field (AC-10), plus the credential-never-logged guard (AC-11). Auth is a read-only minimal-field HRIS credential, redacted on every format path; the `permissions` subcommand prints the documented minimum with a no-full-PII / no-write warning. Pull-only profile with an honest interval (NOT "continuous monitoring"); push-only platform wire (invariant #3); no migration (evidence flows through the existing ledger). Schema `hris.worker_lifecycle.v1` lands in the schema-registry tree with `x-default-scf-anchors = [IAC-22, IAC-09, HRS-04]` (mirroring `okta.user_lifecycle.v1`) and is wired into `DefaultSeed`. **Type: JUDGMENT** — the shared-vs-per-connector kind, the included-vs-excluded field set (the PII boundary), the worker-identity choice, the anchors, the scope minimum, and per-HRIS least-privilege scope recorded in `docs/audit-log/491-hris-connectors-decisions.md`.
