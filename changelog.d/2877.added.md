- **feat(policies): a synced page whose properties changed without a version bump is reported as drift, naming the changed keys (#2877).** Before, `POST /v1/policies:sync` compared only a page's version and body, so a property-only edit on the page (next review date, owner role, approver role, audience, approver name, approval or effective date, title) was reported `unchanged` and dropped. Now the run compares the synced properties too. A property-only change writes no version, applies nothing in place and writes no audit row. It is reported as `drift` with `property_drift_keys` and `property_drift_detected_at`, and recorded on the policy as `sync_property_drift` (`detected_at`, `keys`) on `GET /v1/policies/{id}` and `GET /v1/policies`. This is separate from body drift (`sync_drift`): a run can report either or both. Property drift clears when the properties match again or the page arrives with a new version. A first sync that takes over an imported policy in place reports its differing properties the same way. The synced policy page shows a "properties have changed" notice. Migration `20261296000000_policy_sync_property_drift` adds the two columns, under a CHECK that allows them only on synced rows, only together and with at least one key.
