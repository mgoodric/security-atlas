- **fix(auth): slice 385 — demo-seed 500 on "user:" JWT subject prefix.** The admin demo-seed button returned HTTP 500 `{"error":"internal error"}` on every click because `internal/api/admindemo/handler.go` `resolveActor` parsed `claims.Subject` as a bare UUID, but the auth-substrate-v2 JWT subject is `"user:<uuid>"` (per `internal/api/auth/http.go` LocalLogin and `internal/api/oauth/pkce.go`). The parse failed, the actor resolved to `uuid.Nil`, and the handler returned `"actor user_id missing"` before any seeding ran. Added a `subjectUserID` prefix-strip applied to both the jwtmw subject and the credstore fallback (jwtmw sets `cred.UserID = claims.Subject`, so it carries the prefix too); a bare UUID survives `TrimPrefix` unchanged. Diagnosed by live reproduction against `atlas-edge`. Regression tests drive the real JWT path (`TestResolveActor_JWTSubjectCarriesUserPrefix`) — the prior unit/integration tests only set the actor via the legacy bare-UUID credstore path, which is why CI was green while the deployment 500'd. Decisions log at `docs/audit-log/385-demo-seed-actor-subject-prefix-decisions.md`.
