- **feat(connectors): slice 523 — Kubernetes NetworkPolicy coverage evidence.** Adds a third evidence kind to the Kubernetes connector (slice 487): `k8s.networkpolicy_coverage.v1`. A new `connectors/k8s/internal/netpol` collector reads, read-only via the Kubernetes API (`get,list` on `networking.k8s.io/v1` networkpolicies + core namespaces), the per-namespace NetworkPolicy segmentation posture: how many NetworkPolicies exist, a per-policy SPEC summary (name, the directions it governs, whether its `podSelector` is empty i.e. selects every pod, and a **count** of its ingress/egress rule blocks), and the derived **default-deny** assessment per direction. The recurring SOC 2 CC6.6 / ISO A.8 "prove network segmentation between workloads" demand previously needed a manual upload. **Coverage assessment (JUDGMENT):** a namespace is default-deny in a direction when at least one all-pods (empty-`podSelector`) policy governs that direction with **zero** allow rules — the Kubernetes canonical default-deny shape; `PASS` when default-deny holds for at least one direction, `FAIL` when none (unprotected or per-pod-allow-only), `INCONCLUSIVE` on a per-namespace read error; the platform evaluator owns the final (control, namespace) call. **Over-collection guard (structural, the locked pattern):** NetworkPolicy SPEC metadata **only** — the netpol HTTP client **counts** ingress/egress rule blocks but decodes them as opaque `json.RawMessage`, so the peer / CIDR / namespaceSelector / port contents inside a rule block are never materialized into Go memory; the `RawPolicy` / `Coverage` structs carry **no field** for a peer or selector value, and the connector reads **no** pod contents / env / Secret / ConfigMap / log / exec / traffic. The netpol client test serves a policy embedding a podSelector label, an ingress peer namespaceSelector label, a CIDR, and a port and asserts none escapes; the integration over-collection test allow-lists top-level **and** nested per-policy keys. The connector's documented read-only ClusterRole gains exactly one rule — `networking.k8s.io: networkpolicies` verbs `get,list` (no write verb, no `secrets`, no wildcard); the `DocumentedClusterRole` least-privilege test + `atlas-k8s permissions` render + README stay in sync. Schema `k8s.networkpolicy_coverage/1.0.0.json` carries `x-default-scf-anchors` `["NET-04", "NET-01"]` (boundary-protection + network-security) and is wired into `schemaregistry.DefaultSeed` (drift bijection passes). Push-only (invariant #3); `profiles_supported` stays `[pull]`; stable `actor_id` `connector:k8s:netpol@<version>`; hour-truncated `observed_at`; new `idem.NetpolCoverageKey`; per-namespace `namespace` scope dimension (one record per namespace); `--netpol-control` (default `scf:NET-04`) + `--skip-netpol`. New `connectors/k8s/internal/netpol` coverage floor (93). **Type: JUDGMENT** — the evidence-kind shape, the scf-anchor pair, the default-deny coverage-assessment call, and the SPEC-metadata-only over-collection scope-minimum are recorded with detection-tier in `docs/audit-log/523-k8s-networkpolicy-decisions.md`.
