- **fix(mcp): `create_risk` scores take the same rule as `POST /v1/risks` (#2502).** The MCP `create_risk` applier inserted with raw SQL and never ran the methodology schema or the #2490 numeric-score check, so an MCP client could store a numeric string or out-of-range score that REST refuses. Both paths now call `risk.PrepareCreateScores`. A bad score is refused when the proposal is filed, with REST's status (422 for a non-numeric or out-of-range score field, 400 for a schema or methodology failure) and message, and again on confirm. A FAIR score is now normalised and copied to the residual, as REST does. A refused score field's message names its JSON type rather than echoing the value. An omitted `inherent_score` still files an unscored risk.
