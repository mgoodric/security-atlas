- **fix(infra): slice 461 — integration suite no longer order-coupled on shared SCF-catalog seed state.** The Go integration suite (`go test -tags=integration -p 1 ./internal/...`) passed only because CI's `tests-integration` package list in `.github/workflows/ci.yml` is hand-ordered so the full SCF import runs before any package that partially mutates `scf_anchors`. Run over a broad wildcard (`./internal/api/...`, alphabetical) the coupling surfaced: a package that imported a partial "new release" catalog (or scoped-DELETEd anchors) left the CURRENT SCF framework version missing `GOV-01`, the lazy-seed guards (`if anchorCount == 0`) counted the leftover rows as "already seeded" and skipped their reseed, and the next package's SOC 2 crosswalk import failed with `scf_anchor "GOV-01" not found`. **Root-cause fix:** a new test-only helper `internal/api/scfseed` (`EnsureFullCatalog` / `EnsureSCFCatalog`) replaces the row-count guards with a **completeness probe** — it asks the exact query the SOC 2 importer uses ("does the sentinel anchor `GOV-01` resolve in the CURRENT SCF version?") and does a full clean reseed when the catalog is absent OR partial, making each consumer self-correcting regardless of invocation order. Consumers converted: `anchors`, `ucfcoverage`, `soc2import` (the last via the SCF-only variant, since it imports the crosswalk under test). The seed wipes also `TRUNCATE controls CASCADE` first so a leftover `controls.scf_anchor_id` (`ON DELETE RESTRICT`) FK from an earlier alphabetical package cannot block the anchor reseed. **Guard against silent regression:** a new CI step (`scripts/check-integration-seed-order-independence.sh`) re-runs the catalog-sensitive packages in a deliberately NON-curated order against a freshly-truncated catalog and asserts green, so a reintroduced order-coupled seed fails CI even though the curated-order run passes. **Proof:** `go test -tags=integration -p 1 ./internal/api/...` is green on a pristine DB in full alphabetical order (57 packages, exit 0). **Spillover (slice 462):** the `internal/api/admindemo` suite leaves a `demo` tenant when an earlier test in a shared DB aborts, a separate self-cleanup fragility unrelated to the seed coupling — filed, not fixed here. **Type: JUDGMENT.** Decisions log: `docs/audit-log/461-integration-seed-order-coupling-decisions.md`.
