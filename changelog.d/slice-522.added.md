- **feat(connectors): slice 522 — Azure Event Grid event-driven (subscribe) profile.** Adds a `subscribe` profile to the Azure connector (slice 486 shipped it pull-only): `profiles_supported` becomes **`[pull, subscribe]`**, named honestly — `subscribe` is **event-driven** Azure Event Grid receipt (Event-Grid delivery latency plus a short coalescing window), **NOT** "continuous monitoring" and not a relabeled poll; the pull profile remains the **reconciliation backstop**. A new `eventgrid` subcommand runs a **source-side** receiver **inside the connector process** that receives Event Grid change events for in-scope resources, **authenticates the per-delivery key before any work**, and — treating the event as a **TRIGGER, never the data** — **re-reads** the changed resource via the **same read-only Graph/ARM path the pull profile uses**, emitting the **same** existing kind via the **unchanged** record builder (with its existing over-collection guard). A **forged or payload-only event cannot fabricate a record**: the record's data comes entirely from the re-read of real Azure state, so an event whose resource id resolves to nothing yields **zero** records (test-asserted). **Builds onto `connectors/shared/webhookrecv` (slice 656) without modifying it:** a new `connectors/azure/internal/eventgrid` package wires a delivery-key `Verifier` + the re-read routing onto the shared `NewServer` (gosec-G112 timeouts) / `Serve(ctx)` / `Handle(...)` verify-first skeleton (method→405, size→413, **verify-FIRST→401**). **Delivery auth (D1):** Event Grid does not HMAC-sign bodies, so a constant-time **delivery-key** `Verifier` requires the operator-configured credential (`AZURE_EVENTGRID_DELIVERY_KEY`, in a header or query param) before any re-read; a missing/forged key is rejected **`401` before any work** (test-asserted). **SubscriptionValidation handshake (D2, mirrors slice 557's Intune precedent):** when Event Grid validates the webhook it POSTs a `Microsoft.EventGrid.SubscriptionValidationEvent` carrying a `validationCode`; a `ValidationHandler` wrapping the receiver handles this **FIRST**, responds **`200 {"validationResponse":"<code>"}`**, and **builds NO record / triggers NO re-read** (test-asserted). **Event→reader routing (D3):** the changed resource id's ARM provider segment routes to the existing storage / aks / nsg / keyvault / firewall / entra reader; an unmapped resource type is **dropped honestly** (acked `200`, no re-read). **Cross-profile dedup (D5):** a subscribe-emitted record and a pull-emitted record for the same resource in the same UTC hour derive the **same** idempotency key (the slice-486 `sha256("<kind>|<resource_id>|<hour>")`, unchanged via the same builders), collapsing to one ledger row (test-asserted subscribe-key == pull-key). **DoS bounding (D6):** a bounded event queue + a coalescing window collapse an event storm into one re-read per resource; body size-bounded (256 KiB → `413`); loopback-default bind (`127.0.0.1:8485`, TLS at a reverse proxy). **No new Azure permission:** the re-read uses the slice-486 read-only Graph + ARM Reader set (plus the operator's Event-Grid subscription read); no write path, no new evidence kind. **Log-injection hardened (b245 CodeQL):** every user-tainted log arg (resource id, resource type, wrapped error) is `%q`-escaped. **Invariant #3 honored — push only; ZERO `internal/api/` / `migrations` / `proto` / `schemaregistry` changes:** the receiver stays source-side in the connector. **Type: JUDGMENT** — the delivery-auth scheme, the SubscriptionValidation handshake placement, the event→reader routing table, the dedup confirmation, the coalescing window, and the receiver lifecycle/bind config are recorded in `docs/audit-log/522-azure-eventgrid-decisions.md`.
