- **feat(connectors): slice 526 — K8s watch-based event-driven (subscribe) profile.** Adds a `subscribe` profile to the Kubernetes connector (slice 487 shipped it pull-only): `profiles_supported` becomes **`[pull, subscribe]`**, named honestly — `subscribe` is **event-driven via the Kubernetes `watch` API**, **NOT** "continuous monitoring" and not a relabeled poll; the pull profile remains the **reconciliation backstop**. A new `subscribe` subcommand consumes a long-lived, **source-side** Kubernetes watch against the **same read-only surfaces the pull path reads** (`rolebindings` for RBAC, `deployments` for workloads), building the **same two evidence kinds** (`k8s.rbac_binding.v1`, `k8s.workload_security_context.v1`) via the **unchanged** rbac/workload record builders — **no new kind, no schema change** — and pushing through the existing `IngestEvidence`/`Push` path. The load-bearing novelty is the **watch lifecycle** (the reflector pattern, hand-rolled against a fakeable seam — **no `client-go` dependency**): bootstrap a **LIST** for the starting `resourceVersion`, **WATCH** from it with **`allowWatchBookmarks=true`** (Bookmark events advance the resume point cheaply with no re-LIST), **re-watch** from the last RV on stream close, and on a **410 Gone** (`resourceVersion too old`) **re-LIST** for a fresh RV and **resume** (the re-list emits — it IS fresh state, and the hour-window key makes re-emission safe). **Cross-profile dedup + DoS coalescing:** every event-built record carries the **same slice-487 hour-window idempotency key** the pull path uses, so a watch-emitted record and a pull-emitted record for the same resource in the same hour — and a **burst** of edits to one binding within the hour — collapse to one ledger row (threat-model D); a bounded in-process per-hour key set (default cap 100 000) sheds the burst before it reaches the platform. **Least-privilege:** adds **at most a `watch` verb** alongside the existing `get,list` on **exactly** the rbac + apps surfaces — **no new resource, never `secrets`, never a write verb, never a wildcard** (a least-privilege test pins the exact rule set; `permissions --subscribe` prints it). **Config-only:** the watch decode adapters model only binding-identity / security-context fields — env / Secret / ConfigMap refs are never modeled, so no payload material can reach a record (a no-leak test asserts it). **Invariant #3 preserved:** the watch is **source-side** (how the connector retrieves data FROM the cluster); the platform-side wire stays push — **zero** `internal/api/` / `migrations/` / `proto/` / `schemaregistry/` changes. Graceful shutdown via `SIGINT`/`SIGTERM` (signal context + `errgroup`). The audit-log consumer is documented as a future / fallback option (managed clusters frequently lack control-plane audit access; the `watch` is portable). `JUDGMENT` decisions log at `docs/audit-log/526-k8s-watch-decisions.md`.
