- **feat(controls): stock control cc6_1 checks for phishing-resistant MFA on everyone, in SQL over the Okta MFA-policy payload (#2821, part of #1860).** `soc2_cc6_1_logical_access_baseline` is the first stock control whose query reads payload fields (ADR 0028). It passes when the latest in-window `okta.mfa_policy.v1` snapshot of at least one policy has `mfa_required` true, lists `everyone` in `applies_to_groups` and lists `webauthn` in `factors_allowed`. It fails on SMS, voice, email, OTP or push alone, on MFA not required, and on a policy scoped to other groups. It ignores the connector's per-record verdict, which passed any policy requiring MFA with any factor, so a tenant that passed before can fail now. Okta Verify with number matching is not counted, because the snapshot does not record the number-matching setting. The bundle now ships `tests/` cases, which the upload gate runs. The control's title is now "Identity provider requires phishing-resistant MFA for everyone". **Upgrade note:** the query changed, so on the next boot the bundle is superseded by a new version. Owners, evidence, exceptions and risk links stay with the old version and have to be moved by hand.
