- **fix(attest): a future-dated attestation no longer outvotes later ones, and the same text can be attested again (#2509).** `POST /v1/controls/{id}/attestations` refuses an `observed_at` more than five minutes ahead with 422, and "latest attestation wins" orders by `min(observed_at, ingested_at)`, so a record pushed with a future date counts from when it arrived. The default idempotency key now covers a five-minute retry window, so the same statement attested later (pass again after a fail) is recorded instead of refused with 409, while a retry inside the window returns the first receipt. A replayed attestation no longer re-evaluates the control.
