- **feat(connectors): slice 540 — PagerDuty event-driven (webhook) profile.** Adds a `subscribe` profile to the PagerDuty connector (slice 489 was pull-only; this resolves its deferred P0-489-7): `profiles_supported` becomes **`[pull, subscribe]`**, named honestly — `subscribe` is **event-driven** PagerDuty v3 webhook receipt, **NOT** "continuous monitoring" and not a relabeled poll. A new `webhook` subcommand runs a **source-side** receiver (a bounded long-lived `http.Server`) **inside the connector process** that receives PagerDuty v3 incident-lifecycle deliveries (`incident.triggered` / `acknowledged` / `resolved` / `escalated` / …), **verifies the `X-PagerDuty-Signature` HMAC before any work**, and pushes the **same** `pagerduty.incident_summary.v1` record the pull profile emits. **Signature verification (STRIDE Spoofing, dominant):** PagerDuty v3 signs each delivery with HMAC-SHA256 over the **raw request body** keyed by the per-subscription signing secret; the header carries one or more comma-separated `v1=<hex>` signatures (**multiple during a secret-rotation**) and the receiver accepts iff **any** matches (constant-time `hmac.Equal`). An unsigned / forged / wrong-signature delivery is rejected **`401` before any record is built or pushed** (test-asserted; P0 anti-criterion). The signing secret is source-side config (`PAGERDUTY_WEBHOOK_SECRET`, env only), **never a flag, never logged** (test-asserted). **Summary-only (threat-model I):** the v3 `data` block carries the incident's free-text `title`/`description`/`body`, but the decode struct has **no** free-text field **by construction**, so the free-text never reaches a record even though the payload includes it (test-asserted with a free-text sentinel) — reuses `pdrecord.BuildIncident` **unchanged**. **Cross-profile dedup:** a webhook-emitted record and a later pull-emitted record for the same incident in the same UTC hour derive the **same** idempotency key (the slice-489 `incidentKey`), collapsing to one ledger row (test-asserted webhook-key == pull-key). **DoS bounding (threat-model D):** body size-bounded (256 KiB → `413`), verify-first (unverified load shed cheaply), gosec-G112 server timeouts; loopback-default bind (`127.0.0.1:8474`, TLS at a reverse proxy that forwards the verbatim body). **Log-injection hardened (b245 CodeQL):** every user-tainted log arg (incident id + wrapped error) is `%q`-escaped. **Invariant #3 honored — push only; ZERO `internal/api/` changes:** the receiver stays source-side in the connector; no migration, no new evidence kind, no `proto`/`schemaregistry`/`DefaultSeed` change (reuses `pagerduty.incident_summary.v1`). **Type: JUDGMENT** — the per-vendor-receiver vs shared-helper call, the map-payload vs trigger+re-read call, the multi-`v1=` rotation handling, the loopback/lifecycle config, and the dedup confirmation are recorded in `docs/audit-log/540-pagerduty-webhook-decisions.md`.
