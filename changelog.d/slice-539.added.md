- **feat(connectors): slice 539 — PagerDuty responder-performance metrics.** Adds a fourth evidence kind `pagerduty.response_metrics.v1` to the slice-489 PagerDuty connector — the responder-performance surface 489 deliberately deferred (P0-489-7) because per-responder timing data profiles named individuals. A new `connectors/pagerduty/internal/metrics` collector + read-only HTTP client reads `GET /incidents?since=&until=` over the SAME bounded look-back window the incident-summary + postmortem kinds use (`--lookback-days`, default 90) and emits, **per service**, incident-response performance AGGREGATES: `incident_count` / `acknowledged_count` / `resolved_count`, and MTTA (time-to-first-acknowledge) + MTTR (time-to-resolve) each as `mean` + `p50` + `p90` + `p95` in whole seconds. This proves incidents are acknowledged and resolved within target windows at the PROGRAM level for SOC 2 CC7.4 ("responds to identified security incidents") — NOT a per-engineer scorecard. **JUDGMENT — the aggregation altitude (DOMINANT Information-Disclosure threat, the load-bearing call):** metrics are SERVICE-grained, NEVER per-named-responder; the evidence ledger must not become an individual-performance surveillance store (a privacy + works-council concern in some jurisdictions). The connector NEVER decodes which individual acknowledged or resolved an incident — only the acknowledgment `at` timestamp is read, never the `acknowledger`; the assignees and the resolver are never decoded. The boundary is enforced **structurally**: the record types (`RawAck` / `RawTiming` / `ServiceMetrics`) have NO field that can hold a responder identity (name / email / id-as-person / contact) BY CONSTRUCTION — the only string field is the opaque `ServiceID` (the aggregation grain), and `json.Decode` discards JSON keys with no matching struct field (so a responder identity never enters memory even when the payload carries it). A reflection guard (`TestAggregateOnly_StructuralGuard`) FAILS THE BUILD the moment a responder-identity / free-text field is added. A drop test (`TestCollect_DropsResponderIdentity`) feeds a fake API response that deliberately embeds named acknowledgers (`Jane Doe`, `jane.doe@example.com`, `PUSER1`), assignees, and an incident title naming an individual, and asserts NO per-named-responder identity becomes the grain of any emitted metrics record — the grain stays the service id. **JUDGMENT — metric shape (D2):** first-ack drives MTTA (later re-assignment acks don't change responsiveness); nearest-rank percentiles (the result is an actually-observed sample an auditor can reconcile to one incident, not an interpolated value); whole seconds; clock-skew (negative-duration) samples dropped from the aggregate but still counted in `incident_count`. The schema carries `x-default-scf-anchors=[IRO-02, MON-02]` (Incident Handling + Continuous Monitoring — both real, both already used in this repo) and is registered in `DefaultSeed` (the schema-drift bijection passes with the new kind). **Anti-criteria (P0):** push only — no platform-side wire change (invariant #3); read-only PagerDuty token only — NO new credential scope beyond the slice-489 read-only key (the `permissions` subcommand documents it); the token is never logged or placed into a record (`TestClient_TokenNeverLogged`); the `pull` profile is named honestly (NOT continuous monitoring). **Bounded (DoS guard):** bounded look-back window + bounded page loop (`maxPages`) + a hard per-run service-aggregate cap (`metrics.MaxServices`). sha256 content-hash per record; hour-truncated `observed_at`; register-per-run; stable `actor_id=connector:pagerduty:metrics@<version>`; per-service `service` scope dimension; `--metrics-control` (default `scf:IRO-02`). Neutral fixtures only (`test-pd-token` / `test-pd-secret-token-value`; obviously-fake `INC*` / `SVC*` ids; no real-looking PagerDuty tokens). Tests: collector unit (aggregate-by-service / first-ack / percentile nearest-rank + no-mutate / drop-missing-grain / negative-duration-drop / hard-cap), client unit (auth header + query + pagination + page-cap + empty-id-skip + token-never-logged), the structural aggregate-only guard + the responder-identity drop test, the record-builder unit (kind/idempotency/payload allow-list), the `run`-seam push/collect/error tests, and the integration no-per-responder-grain assertion on the metrics path. New `connectors/pagerduty/internal/metrics` coverage floor. **Type: JUDGMENT** — the aggregation altitude, the window/percentile choices, the anchor choice (CC7.4 → IRO-02/MON-02), and detection-tier are recorded in `docs/audit-log/539-pagerduty-responder-metrics-decisions.md`.
