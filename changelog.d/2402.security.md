- **fix(authz): an API key labelled viewer or auditor can no longer write evidence, artifacts or walkthroughs (#2402).** A key's `owner_roles` reached OPA as `control_owner` whenever it was non-empty, so a key minted with `owner_roles = {viewer}` or `{auditor}` could push evidence, upload artifacts and record walkthroughs, and could read evidence records. A key whose label names only `viewer` and/or `auditor` now derives exactly that role when it has no owner, and nothing when it has one: a user-bound key then acts with its owner's live role assignments, like a signed-in session (#2381). Such keys lose evidence, artifact and walkthrough writes and the evidence list and records. An ownerless viewer key also loses artifact and walkthrough reads. A user-bound key whose owner has no live role loses everything. An ownerless viewer key gains `GET /v1/risks`, and an ownerless auditor key gains `GET /v1/dashboard` and `GET /v1/me/audit-periods` (an empty list), reads that its own role grants. Admin, approver and `control_owner`/owner-role-labelled keys, JWT sessions and OAuth clients are unchanged. Upgrade note: `scripts/dry-run-2402-key-roles.sql` counts, per tenant, the keys whose access changes. Re-mint any key that must keep writing with a `control_owner` label first.
