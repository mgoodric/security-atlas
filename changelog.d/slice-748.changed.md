- **feat(audit): slice 748 — ActionPlan participates in the audit-period frozen-view snapshot.** Closes the loop between the slice-384 read-side foundation (`actionplan.Store.ListSnapshot(frozen_at)`) and the slice-028 freeze primitive. A new `period.Store.Snapshot(ctx, periodID, lister)` assembles a period's frozen view (`period.FrozenView`) whose remediation commitments are drawn through `actionplan.Store.ListSnapshot` at the period's `frozen_at` horizon — only plans with `created_at ≤ frozen_at` appear. A plan created or mutated after the freeze is excluded, and a later live edit of a pre-freeze plan never changes a past frozen view's membership (invariant #10 + #2; P0-384-5 re-verified end-to-end). The action-plan read is injected as a function-typed seam (`period.ActionPlanSnapshotLister`, wired via `actionplan.Store.PeriodSnapshotLister()`) so the `period` package never imports `internal/actionplan` — no import cycle, layering preserved. Read-side wiring only: no schema change, no new HTTP route. The OSCAL POA&M aggregate still derives items from failing control evaluations, not action plans (sourcing it from the frozen action-plan snapshot remains the named slice-384 spillover #1 — out of scope here).
