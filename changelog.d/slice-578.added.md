- **feat(oscal): slice 578 — chained OSCAL profile-over-profile resolution.** Slice 511 resolved an OSCAL profile against a supplied catalog, bounding the import chain to a single level (profile → catalog) by construction. This slice lifts that bound to a **bounded chain** (profile → profile → … → catalog): a profile whose `import.href` names ANOTHER supplied profile is resolved recursively until the chain bottoms out at a supplied catalog. **The two load-bearing safety properties are enforced Go-side and pure (no bridge, no Postgres) in `internal/oscal/profileimport/chain.go` so they are unit-testable without compliance-trestle (D1):** (1) **cycle detection** — a profile that imports itself directly (A → A) or transitively (A → B → A) is a structured error, never an infinite loop or fetch (P0-578-2); a depth-first walk tracks the profile keys on the current path and rejects on revisit, popping on exit so a legal diamond is not a false cycle; (2) the **chain-depth bound** `MaxChainDepth = 8` (D2 — the FedRAMP baselines are depth 1, an overlay is depth 2; 8 gives generous headroom while bounding a pathological/malicious chain) rejects a too-deep chain (AC-3). The slice-511 no-external-dereference guard carries forward **at every chain link** (P0-578-1 / P0-511-1): every `import.href` is matched ONLY against supplied documents, an external scheme is rejected before matching, and an href that names no supplied document is a structured error with no fetch. **Resolution stays delegated to compliance-trestle** (D1): once the graph is proven safe the bridge lays every supplied profile + catalog into its isolated sandbox, rewrites every href to a `trestle://` path, and `ProfileResolver` descends the chain natively — no parallel resolver. **Wire shape (D4):** the existing `ImportProfile` RPC gains an additive `repeated SuppliedProfile profiles = 4` field (no new RPC; a slice-511 single-level caller sends an empty list and gets identical behavior); Go bindings via `buf generate`, Python stubs via `uv run --with 'grpcio-tools==1.80.0' bash oscal-bridge/scripts/gen_proto.sh` (verified `GRPC_GENERATED_VERSION = '1.80.0'`). **Persistence reuses slice 511's shape** (`imported_catalogs.kind = 'profile'`, requirement → SCF anchor, transactional all-or-nothing) — no new table, no migration. The **resolved-chain provenance** (D6) is recorded in the `profile_imported` success-audit `detail` JSON: a `chain` array of `{role, sha256, bytes}` for the entry profile + every intermediate profile + every catalog, plus a `chain_depth` count, so an auditor can prove the exact chain material. The `atlas-oscal import-profile` CLI gains a repeatable `--profile` flag for intermediate profiles. The load-bearing properties are proven at BOTH tiers: pure-Go table tests (chained resolve validates, A→B→A rejected, depth-exceeded rejected, deep external href rejected, diamond is not a cycle) AND bridge-gated integration tests against a real Postgres + the real Python bridge (A→B→catalog resolves end-to-end through trestle; A→B→A rejected without loop with a rejection-audit row). **Type: JUDGMENT** — the depth bound, cycle-detection policy, delegation split, and wire shape recorded with detection-tier in `docs/audit-log/578-oscal-chained-profile-decisions.md`.
