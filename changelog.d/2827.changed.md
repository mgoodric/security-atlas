- **feat(controls): the GitHub connector reports status checks, force pushes, topics and deploys-to-production, and both cc8_1 checks are complete (#2827, #1860).** The connector now pushes `github.repo_protection.v2` at schema 2.1.0, which adds `required_status_checks` (every required check context from classic protection and rulesets), `allow_force_pushes` (false when classic protection or a `non_fast_forward` rule blocks force pushes), `topics`, and `deploys_to_production` (the topics include `--production-topic`, default `production`). `soc2_cc8_1_change_management` still requires every repository to have an approving review enforced on admins. A repository that deploys to production must also require at least one status check and block force pushes. `soc2_cc8_1_configuration_change_control` now checks only repositories with the `iac` topic. In both checks a field the connector could not read leaves the control inconclusive, and a known failure still fails it. A record with no numeric `repo_id` is now left out instead of failing the control. Who may bypass a required check or a force-push block is not read. **Upgrade note:** both queries changed, so on the next boot both stock bundles are superseded by new versions. Owners, evidence, exceptions and risk links stay with the old versions and have to be moved by hand. Upgrade the GitHub connector with the platform. Until you do, 2.0.0 records carry no production fields or topics, so change management is inconclusive. Configuration change control is inconclusive for any repository that does not require a review. Tag production repositories with the production topic and IaC repositories with `iac`.
