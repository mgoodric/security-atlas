- **feat(approval): approvals require a second person; self-approval is an organisation opt-in (#2101).**
  - **The rule.** Policies, framework scopes and exceptions share one rule (`internal/approval`, ADR 0024). Only a person approves, and never the person who requested the approval.
  - **The setting.** An admin can turn on **Allow self-approval** with `PATCH /v1/tenants/{id}` `{"allow_self_approval": true}`. Every change is audit-logged. A record approved by its requester is flagged `self_approved`, shown as "Self-approved" in the UI, the exports and the audit log. A database trigger refuses the flag while the setting is off. A machine credential never approves, whatever the setting.
  - **Upgrade note: exception approval is people-only.** An approver-role unbound API key, OAuth client or the bootstrap admin used to be able to approve an exception; it now gets 403. Approve with your own login or with a key bound to your user.
  - **Upgrade note: requesters are stored by person.** New exceptions store `requested_by` as the bare users(id) uuid, as `submitted_by` on policies and framework scopes already does, instead of the per-session `jwt:<token id>`. A machine is recorded by its principal. Anything that matched `requested_by` against credential ids should match the user id.
  - **Upgrade note: framework scopes in review.** A framework scope in review before this release with no recorded submitter, or one recorded by session, must be re-submitted before it can be approved.
  - **Not yet in the UI.** The setting is API-only for now; there is no settings-tab toggle yet.
  - Decisions: `docs/audit-log/2101-self-approval-decisions.md`.
