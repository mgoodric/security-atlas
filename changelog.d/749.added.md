- **feat(ai): slice 750 — portfolio / multi-control evidence summary.** Generalizes slice 502's single-control live evidence summary to a FILTERED control SET (by control-family or by framework version; no filter = the whole program), mounted on the dashboard. For the filtered set it returns the deterministic TWO-LEVEL bounded cross-control rollup ALWAYS (cap controls-per-summary `MaxControlsPerSummary=12` AND records-per-control `MaxRecordsPerControl=4` — the headline JUDGMENT call, P0-750-2; 12×4 cited excerpts + 12 control ids = 60 citable ids keeps the prompt + citation gate bounded while staying portfolio-meaningful), plus a plain-language, cited, NON-BINDING, local-default-Ollama summary of that rollup when generation is available AND every citation resolves to a tenant-owned row in the cross-control grounding set (AC-2) AND every numeric claim matches the deterministic rollup (AC-3 — a fabricated portfolio count like "40 of 40 controls covered" auto-suppresses, via the slice-501 numeric-verification PATTERN lifted locally to avoid an `evidencesummary→boardnarrative` coupling). It is a thin cross-control variant of slice 502: it REUSES the `internal/evidencesummary` citation gate / suppression vocabulary / grounding discipline verbatim and changes only the corpus (a two-level bounded SET of controls), the mount (dashboard), and the added numeric gate. The ONLY new backend pieces are (a) a `PortfolioService` + `PortfolioStore` (the embedded single-control `Store` IS the citation resolver; the cross-control grounding gate scopes citations to the summarized set), and (b) ONE additive sqlc query `ListActiveControlsForPortfolio` (optional `family` + optional `anchor_ids[]` via `sqlc.narg`, capped at `MaxControlsPerSummary+1` for an honest "K of N" label) — the framework filter resolves controls via the EXISTING `ListSCFAnchorsForVersion` framework→anchor→control path, and the per-control evidence reads reuse slice 502's `ListEvidenceRecordsByControl`/`CountEvidenceRecordsByControl`; **no migration**. Cross-tenant isolation is proven across the WHOLE control set against live Postgres + RLS (a Tenant-B portfolio summary cannot cite/quote ANY Tenant-A control or evidence record, seeded with overlapping family structure across two tenants — AC-4, the load-bearing property). New route `GET /v1/evidence-summary/portfolio?framework_version_id=…&family=…` behind the existing program/control-read authz (admin / grc_engineer / control_owner — no new role). The dashboard panel (`web/components/dashboard/portfolio-summary-panel.tsx`) renders the rollup with BOTH bounds labeled honestly ("summarizing the K most-relevant of N controls; up to M records each"), the slice-502 non-binding disclosure, and NO approve/publish/export affordance (AC-5, P0-502-3); generation degrades gracefully to the deterministic rollup so the dashboard stays usable (AC-7). Current live evidence only (no frozen-population mixing — a period-scoped portfolio summary = #749 ∩ #750 is a further follow-on).
