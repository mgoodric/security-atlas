- **feat(connectors/github): the GitHub connector emits `github.repo_protection.v2`, and both cc8_1 stock controls read it (#2925).** v1 pushed a repository whose branch protection it could not read with every field `0` or `false`, so it failed both cc8_1 controls; it ignored rulesets, so a branch protected only by a repository or organization ruleset read as unprotected; it read only the first 100 repositories; and it carried no stable repository id. v2 adds `repo_id` (GitHub's repository id, which survives a rename), merges classic protection with every active ruleset to the strictest setting, takes admin enforcement from classic `enforce_admins` or from a ruleset that only an app or a deploy key may bypass, and follows `Link: rel="next"` when listing repositories. A protection field the connector could not read is omitted, and the record is `inconclusive` with a `reason`. The v1 schema stays registered for existing records. Both cc8_1 controls now key on `repo_id`: a repository observed without the required review (or, for change management, without admin enforcement) fails the control, an unread one leaves it inconclusive instead of failing it, and v1 records are no longer read. **Upgrade note:** both cc8_1 queries changed, so on the next boot both stock bundles are superseded by new versions. Owners, evidence, exceptions and risk links stay with the old versions and have to be moved by hand. Upgrade the GitHub connector with the platform: until then cc8_1 receives no v2 records and is inconclusive.
