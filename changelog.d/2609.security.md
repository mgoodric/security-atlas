- **feat(admin): SSO config changes and SCIM credential issue and revoke are audited (#2609).** Each one writes a `me_audit_log` row in the same transaction as the change, naming the acting user and credential (`actor_principal`). If the audit write fails, the change rolls back. `PATCH /v1/admin/sso` writes `tenant_sso_config_update` with the before and after value of every field, including `trust_unverified_email_for_link`. The client secret is recorded only as `secret_changed: true/false`, never its value, ciphertext, hash or length, and a PATCH that changes nothing writes no row. `POST` and `DELETE /v1/admin/scim-credentials` write `scim_credential_issue` and `scim_credential_revoke` with the credential id, last4 and description, never the token or its hash; revoking an already-revoked credential writes no row. Migration `20261262000000_sso_scim_audit` extends the action CHECK.
