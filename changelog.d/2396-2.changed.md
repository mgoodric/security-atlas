- **fix(connectors): Kubernetes NetworkPolicy evidence defaults to SCF `NET-06` Network Segmentation; ISO 27001 A.8.22 moves to `NET-06` (#2396, follow-up to #1978).** The SCF 2026.3 workbook maps A.8.22 (segregation of networks) to `NET-06`, not to `NET-03` Boundary Protection, so the crosswalk edge moves and no `NET-03` edge stays. **Upgrade note:** the k8s connector's `--netpol-control` default changes from `scf:NET-03` to `scf:NET-06`. The default SCF anchors for `k8s.networkpolicy_coverage.v1` are now `["NET-06", "NET-02"]`, and `azure.nsg_rules.v1` gains `NET-06` (`["NET-03", "NET-06", "NET-02"]`). The Azure `--nsg-control` and `--firewall-control` defaults stay on `scf:NET-03`, and `azure.firewall_rules.v1` is unchanged. A connector run on its defaults stamps the new code once you upgrade it. To keep the old code, pass `--netpol-control scf:NET-03`. Evidence already ingested keeps the `control_id` it was pushed with. An install that has already registered either 1.0.0 schema keeps its stored default anchors, because the boot import skips a kind and version that is already present. On the next boot the bundled ISO crosswalk converges: the `A.8.22 → NET-03` edge is retired and `A.8.22 → NET-06` is added. ISO A.8.22 no longer maps to the stock `soc2_cc6_6_boundary_protection` (NET-03) control. It reports as uncovered until a control is anchored on NET-06. The table is in the upgrade guide.
