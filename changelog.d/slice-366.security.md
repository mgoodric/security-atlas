- **feat(auth): slice 366 — JWT signing key rotation end-to-end.** Closes slice 327 security-audit finding **M-1** (MEDIUM — long-lived static ES256 signing key; compromise blast radius unbounded; NIST SP 800-57 Part 1 §5.3.6 cryptoperiod guidance unmet). The slice-187 keystore shipped multi-key data structures + multi-key JWKS but `fsstore.Store.Rotate` was a stub returning `ErrRotateUnsupported`. This slice lights up the orchestration on top of the existing primitives. **(1) `fsstore.Store.Rotate(ctx)`** generates a fresh ES256 keypair, writes it at mode 0600 via the existing atomic temp+rename `writePrivateKey` path, and reloads so the new (newer-timestamp) KeyID becomes the active signer while every prior key remains in the verification set for the overlap window; a same-second collision bumps the new KeyID to the next second so the chronological-lexicographic "alphabetically-last is active" invariant always holds. **(2) `fsstore.Store.Prune(ctx, cutoff)`** removes keypair files at or before the cutoff EXCEPT the active signer (P0-366-2 — never pruned regardless of age), reloading so pruned keys drop from JWKS; the cutoff is `now − AccessTokenLifetime − RotationOverlap` (`fsstore.PruneCutoff`), structurally guaranteeing no in-flight token is invalidated mid-validation (P0-366-3). **(3) `fsstore.Store.List(ctx)`** returns a minimal `KeyInfo{KeyID, Age, Signing}` per key — no field can carry private material (P0-366-1 defense-in-depth). **(4) `atlas-cli keys list / rotate / prune`** operate directly on the keystore directory (no DATABASE_URL); `prune` is dry-run by default and requires `--confirm` to delete. **(5) scheduled rotation** in `cmd/atlas` rotates on a configurable cadence (annual default via `ATLAS_KEY_ROTATION_INTERVAL`) and prunes after each rotation; every rotation writes a structured platform-level audit line `audit_event=key_rotation` carrying the previous + new signing KeyIDs (never key bytes — P0-366-1 / P0-187-6). **(6)** the JWKS endpoint continues to publish the full verification set; a new test asserts both keys are advertised across the overlap window.
