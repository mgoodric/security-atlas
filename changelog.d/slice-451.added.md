- **ci(release): slice 451 — SLSA provenance + per-artifact SBOM for the binary / CLI / SDK release surface.** Closed the supply-chain asymmetry the project's "diligence the diligence tool" thesis exposes: `container-publish.yml` already gave images a signed SBOM + SLSA provenance, but `release.yml` cosign-signed **only** `checksums.txt` and emitted no SBOM and no provenance for the downloaded binaries/CLI/SDK archives — exactly the gap a GRC diligence questionnaire asks about by name. Now every released archive carries (a) a **per-archive SPDX SBOM** (`<artifact>.spdx.sbom.json`, emitted by GoReleaser's newly-enabled `sboms:` block driving the already-installed `syft`) and (b) a **SLSA build-provenance attestation** binding each artifact's digest individually to this repo's `release.yml` GitHub Actions OIDC identity (`actions/attest-build-provenance`, same pinned SHA the container job uses), NOT just the aggregate checksums file (P0-451-2). **SBOM is gated, not best-effort (AC-4 / P0-451-4):** the syft step drops `continue-on-error`, and a new "Gate SBOMs" step hard-fails the release if any SBOM is invalid SPDX or has zero components (negative path proven locally: an injected empty SBOM exits 1). **Permissions are job-scoped (AC-3 / P0-451-5):** the only new privilege, `attestations: write`, is added to the GoReleaser job's `permissions:` block — the workflow-level block stays `contents: read`; no workflow-level widening. **Self-verify (AC-7):** a new round-trip step runs `gh attestation verify` asserting the workflow identity, mirroring the existing "Self-verify signed checksums" step (which is unchanged — additive only, AC-8). **Edge-signing JUDGMENT (AC-5):** re-confirmed slice 207 D1 — `:edge`/`:main-<sha7>` images stay deliberately unsigned (provenance + SBOM only; cosign signatures bind to release-cut tag identity); `container-publish.yml`'s header comment updated to record the resolved decision. **Diligence-facing verify guide (AC-6):** `docs/RELEASE_READINESS.md` §12 adds a consolidated, independently-runnable supply-chain verification section covering containers + binaries/CLI/SDK + OSCAL bundles with stock `cosign` / `gh attestation verify` / `slsa-verifier` commands for an external auditor. **Validation:** a local GoReleaser snapshot emitted all 10 SPDX SBOMs (19–118 components each, no secrets/build-host/username leakage — P0-451-3);
