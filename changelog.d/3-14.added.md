- **feat(connectors): slice 636 — Datadog Cloud-SIEM signal-history (triage outcomes).** Adds a third evidence kind to the Datadog connector, `datadog.siem_signal.v1`, the CC7.3 sibling of slice 533's `datadog.siem_rule.v1`. Slice 533 reads detection-rule **configuration** (SOC 2 CC7.2 — which rules exist); this surface reads what **fired** and how it was **triaged** (SOC 2 CC7.3 incident response — "rules actually fired and were triaged over the audit period, when, and by whom"). Sourced read-only from the Datadog security-signals search API (`GET /api/v2/security_monitoring/signals`, new `security_monitoring_signals_read` scope) by a new `connectors/datadog/internal/siemsignals` collector mirroring the slice-533 thin-HTTP + register-per-run + hour-truncated-`observed_at` pattern. **JUDGMENT — the over-collection field boundary (the load-bearing call):** a record carries triage **metadata only** — `signal_id`, `rule_id` (ties back to the rule's config record), `rule_name`, `severity`, `status` (normalized to `open` / `under_review` / `triaged` / `archived`), the timeline timestamps (`first_seen_at` / `triaged_at` / `last_updated_at`), and the **opaque** `triager_handle`. It NEVER carries the signal **message body**, the matched log/event **samples**, the matched-event **payload**, the raw detection **query**, signal-body **tags/facets**, or a recipient/triager **email** (PII — an email-shaped triager value is **dropped**). The boundary is **structural**: the `RawSignal` / `Signal` structs have no field that can hold the excluded data — a reflection test (`TestStructuralOverCollectionGuard`) pins the field set, the HTTP client decodes only the body-free fields, and a fixture embedding a message, samples, a query, and a `user.email` tag proves none reaches an emitted record. **JUDGMENT — profile shape + honest naming:** a **bounded pull** of the last-N-hours of signals (`--siem-lookback`, default 24h: `filter[from]=now-lookback`) on the operator's schedule — NOT continuous monitoring and NOT event-driven (Datadog's security-signals API is a search/poll surface with no first-class push the connector receives; signal notifications route to the operator's own integrations). `profiles_supported` stays `[pull]`; the platform-side wire stays push (invariant #3 — no proto/migration change). **JUDGMENT — anchors:** `x-default-scf-anchors` = SCF **THR-01** (detection lineage, slice-635 seed) + **IRO-09** (Incident Reporting); IRO-02 was rejected as not-in-the-bundled-catalog. New evidence kind registered in `DefaultSeed` + a draft-2020-12 JSON Schema (`additionalProperties:false`); the slice-068 drift-guard keeps schema ⇔ seed in sync. A bounded page loop (`maxPages=50` × `pageSize=100` + 60s timeout) caps the read with `ErrSignalCapExceeded`. New `siemsignals` coverage 95.0% (floor 90); the new `datadogauth.RequiredSignalScope` method is covered (the slice-533 0%-covered-method ratchet gotcha avoided). **Type: JUDGMENT** — the field boundary, profile shape, and anchor choice are recorded with detection-tier in `docs/audit-log/636-datadog-siem-signal-history-decisions.md`.
