- **feat(controls): cc6_6 MFA on admin apps counts authentication method chains and a global session policy that requires MFA (#2951).** The Okta connector now pushes `okta.app_assignment.v1` at schema 1.2.0, which is additive. `sign_on_mfa_required` now decides app sign-in rules that use an authentication method chain (`AUTH_METHOD_CHAIN`). Such a rule is 2FA when every path through its chains takes factors of two classes, and 1FA when one path takes a single class. A chain that uses Duo, an external IdP, a smart card or a temporary access code stays undecided. The new `session_mfa_required` field says whether the org's global session policy (`OKTA_SIGN_ON`) requires MFA for every user, with `session_reason` when it is omitted. `soc2_cc6_6_mfa_external_threats` passes an admin or infrastructure app when either policy requires MFA, and fails it only when both say no. The global session verdict covers the whole org. A reachable session rule that lets some users sign in with one factor counts against every app, so require 2FA in the admin app's own sign-in policy if you cannot tighten the session policy. The connector also reads `GET /api/v1/policies?type=OKTA_SIGN_ON` and the Everyone group, under the `okta.policies.read` and `okta.groups.read` scopes it already holds. **Upgrade note:** the query changed, so on the next boot the stock bundle is superseded by a new version. Owners, evidence, exceptions and risk links stay with the old version and have to be moved by hand. A record from an older connector carries no session verdict, so an admin app it reports at 1FA is now inconclusive rather than failing, until the connector is upgraded.
