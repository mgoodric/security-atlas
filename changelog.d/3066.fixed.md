- **fix(audit): creating or deleting a control no longer breaks replay of a frozen audit period (#3066).** The freeze hash's control set was read from the tenant's live catalog at every replay. Freeze now records the exact control list it hashed in `audit_period_frozen_controls` (write-once), and `ReplayHash` and every freeze revision read that list. The hash definition is unchanged, so no stored hash changes. A frozen period with no recorded list fails closed (`ErrNoControlSnapshot`) rather than replaying against the live catalog. Migration `20261311000000_audit_period_frozen_controls` (with down file). **Upgrade note:** the migration records the current catalog for every period already frozen, marked `migration_backfill`. Such a period replays if its catalog has not changed since it was frozen, and from then on stays replayable; one whose catalog had already changed still mismatches, as it did before. The owner-only reopen in `docs/runbooks/audit-period-reopen.md` now also removes the recorded list.
