- **fix(audit): creating or deleting a control no longer breaks replay of a frozen audit period (#3066).** The freeze hash's control set was read from the tenant's live catalog at every replay. Freeze now records the exact control list it hashed in `audit_period_frozen_controls` (write-once), and `ReplayHash` and every freeze revision read that list. The hash definition is unchanged, so no stored hash changes. A frozen period with no recorded list fails closed (`ErrNoControlSnapshot`) rather than replaying against the live catalog. Migration `20261311000000_audit_period_frozen_controls` (with down file). A deferred commit check refuses any transaction that leaves a frozen period without its recorded list, and `atlas_app` may record only `source='freeze'`. **Upgrade note:** deploy the migration and the new binary together. An older binary's freeze is refused at commit, and the period stays open; retry it on the new binary. The migration records the current catalog for every period already frozen, marked `migration_backfill`. Such a period replays if its catalog has not changed since it was frozen, and from then on stays replayable; one whose catalog had already changed still mismatches, as it did before. The owner-only reopen in `docs/runbooks/audit-period-reopen.md` now also removes the recorded list. Detection and recovery of a frozen period without a recorded list: `docs/runbooks/audit-period-frozen-controls.md`.
