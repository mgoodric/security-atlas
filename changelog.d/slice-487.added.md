- **feat(connectors): slice 487 — Kubernetes connector (RBAC + workload security-context), the first non-cloud-IaaS first-class peer.** A new `connectors/k8s/` connector follows the locked slice-004 / slice-486 pattern verbatim (register-per-run, stable `actor_id`, hour-truncated `observed_at`, scope minimums, vendor-native read-only auth) and emits **two evidence kinds**: `k8s.rbac_binding.v1` (Role / ClusterRole + their bindings — who-can-do-what, with the referenced role's rules attached and a connector-side `grants_wildcard` heuristic, read-only Kubernetes API `rbac.authorization.k8s.io/v1`) and `k8s.workload_security_context.v1` (per-workload `runAsNonRoot` / `privileged` / `readOnlyRootFilesystem` / `allowPrivilegeEscalation` / host-namespace posture aggregated across containers, read-only `apps/v1`). Each record is pushed to the platform's single `IngestEvidence` / `Push` API with a sha256 content-hash and stable optional fields — **no platform-side wire change** (invariant #3, P0-487-1); the connector registers `profiles_supported=[pull]` and names its interval honestly (operator-scheduled, recommended 24h — **not** "continuous monitoring", P0-487-6). **The load-bearing scope-minimum guard (P0-487-2 / P0-487-3):** the connector requires a least-privilege read-only ClusterRole granting `get`/`list` only on the RBAC kinds + apps workloads + namespaces — **never write verbs, never wildcards, and critically never `get`/`list` on `secrets`** — and it collects RBAC + security-context **configuration only**, never Secret values, ConfigMap values, container env, or logs (the workload client decodes only the security-context fields, so env / volumes / Secret refs are discarded at the JSON boundary). `internal/k8sauth.DocumentedClusterRole()` is the single source of truth that the README, the `atlas-k8s permissions` subcommand, and a unit test all read; the test fails the build if anyone widens the rule set. The cluster token is read only from the environment / the projected in-cluster ServiceAccount mount (never a CLI flag), is redacted on every credential format path, and never enters an evidence record (P0-487-4). The connector is **API-based, not an in-node agent** (P0-487-5), **OSS and in-tree**, and faked in tests (no live cluster in CI — `client-go` is deliberately not pulled in; a thin read-only HTTP client mirrors the slice-486 dependency discipline). **Two evidence-kind JSON Schemas** land in the schema-registry tree with `x-default-scf-anchors` set (`IAC-21`/`IAC-22` for RBAC, `CFG-02`/`END-04` for workloads) and are registered in `DefaultSeed`; no migration. Tests cover the collect → push round-trip against mocked Kubernetes API surfaces, the no-Secret/ConfigMap/env-leak guard, and the no-token-log guard; new per-package coverage floors added. NetworkPolicy, Pod-Security-Standards admission-config, Secret-inventory (metadata-only), and a watch-based event-driven profile are filed as follow-on slices 523–526 (P0-487-7). **Type: JUDGMENT** — the two evidence-kind shapes, their `x-default-scf-anchors`, and the exact minimal ClusterRole recorded with confidence + detection-tier in `docs/audit-log/487-kubernetes-connector-decisions.md`.
