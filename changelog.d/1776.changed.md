- **feat(catalog): review and apply SCF remap proposals (#1776).** A person now decides each remap proposal that an SCF import queued (#1775), through the API or `atlas-cli catalog remap list | approve | approve-unchanged | reject | keep-legacy`. **Approve** re-anchors the control on a successor in the target release as a new, superseding control revision, through the same upload path as any manifest change. The control's manifest gains that `scf_anchor_id` and `scf_release`. A `split` or `no_successor` proposal needs `scf_id` to name the anchor. **approve-unchanged** approves every open `unchanged` proposal and touches no other class. It refuses with 409 while another run holds the proposals' locks. **Reject** leaves the control on its legacy anchor, and the proposal can be revisited. **Keep legacy** is final. The boot seed no longer undoes a reviewed decision: when the active revision of a stock control is an approved re-anchor, the shipped `controls/soc2/` manifest is kept back, and the upload returns a warning and is logged. Every decision appends a row to the new `scf_remap_decisions` table: old and new release and anchor, the new revision, the deciding person (`PrincipalOf`) and the time. The app role can only append to that table. Deciding needs a person: machine credentials get 403. Only admin and grc_engineer can decide, by the existing control-edit rule. Proposal statuses gain `approved`, `rejected` and `kept_legacy`, and `GET /v1/controls/remap-proposals?status=` accepts them. Migration `20261201000000`; decisions in `docs/audit-log/1776-scf-remap-decisions-decisions.md`.
