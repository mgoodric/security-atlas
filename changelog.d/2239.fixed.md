- **fix(authz): roles assigned in `user_roles` now apply to users signed in with a JWT (#2239).** Authorization and the unified audit-log role check looked roles up by the raw `user:<uuid>` token subject, while role assignment stores the bare uuid, so password, OIDC, PKCE and device-grant sessions were held to their credential-derived role. Both lookups now read the `user:` subject as its uuid. Assigned roles are added to the derived role, never subtracted. API keys and OAuth clients are unchanged, except that the role rows of a user who is not active (for example deactivated through SCIM) are now ignored, so an auditor with a leftover period assignment gets nothing from it. `/v1/activity/unified` now shows a JWT caller their own activity. Upgrade note: before rolling out, run `scripts/dry-run-2239-roles.sql` (read-only, counts only) to see which role sets change per tenant.
