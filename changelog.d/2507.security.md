- **fix(authz): the last role-claim read gates count live roles (#2507).** Sixteen handler gates (action plans, the `/v1/admin/*` exports, control detail, checklists, the dashboard activity feed and posture, evidence summaries, gap explanations, OSCAL reads and personnel security) admitted any credential whose role claim was non-empty. They now count the live `user_roles` authzmw resolves, through the new `authz.HasAnyTenantRole` or a narrower helper matched to the route's OPA rule. A user whose role was revoked can no longer read these surfaces with a token minted before the revoke, and control owners and viewers no longer pass handler gates that OPA already refuses them (for example the `/v1/admin/*` exports, OSCAL and personnel security). `GET /v1/risks/{id}/action-plans` follows the risk register's read gate, so viewers can read it. Action-plan writes are admin only at the handler too, as OPA already had them. **Upgrade note:** an unbound API key or a client_credentials machine token whose `owner_roles` label is free text (not one of the five canonical roles) loses these reads; give it a canonical role label (for example `control_owner` or `viewer`) to keep access.
