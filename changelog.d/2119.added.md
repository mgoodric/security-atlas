- **feat: an Approvals page and sidebar badge (#2119).** A new `GET /v1/approvals` lists what is waiting for the caller's approval: requested exceptions, proposed risk acceptances, policies under review and framework scopes in review. It lists exactly what each type's approve handler would accept from the caller. It checks, in order, that the type's module is on, the approver role (`authz.IsTenantApprover`), the record's state, and the type's own approver check, which the store also runs inside the approve transaction. The caller's own requests appear only when the organisation allows self-approval, and are then marked `self_approval`. A viewer, an auditor, or a credential with no person behind it gets an empty list. Counts per type are computed on the server under RLS, and at most 100 rows per type are listed, oldest first. The new **Approvals** page under Program groups the rows by type, each linking to the record's approval action. The sidebar entry shows the total, from the same query as the page, and every approval flow refreshes it.
