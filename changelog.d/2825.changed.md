- **feat(controls): stock control cc6_7 checks that every S3 bucket has default server-side encryption with AES256, aws:kms or aws:kms:dsse, in SQL over the bucket-encryption payload (#2825, #1860).** `soc2_cc6_7_encryption_in_transit` used to roll up the AWS connector's verdict, which passes any default encryption rule whatever its algorithm. It now takes each bucket's latest `aws.s3.bucket_encryption_state.v1` record, keyed by `bucket_name`. A bucket passes when the record's result is pass, `encryption_enabled` is true and `sse_algorithm` is `AES256`, `aws:kms` or `aws:kms:dsse` (dual-layer SSE-KMS); it fails when the connector found no default encryption, or when the default rule names any other algorithm (`aws:fsx`, `aws:backup`, or one AWS adds later). Any failing bucket fails the control. A bucket the connector could not read, or a record with no algorithm, leaves it inconclusive, as does no record. `encryption_enabled` false alone is not read as unencrypted, because the connector also writes it false when it could not read the bucket. The bundle ships `tests/` cases. The AWS connector README now gives `--control-id`'s default as empty (routed by type, #2924). **Upgrade note:** the query changed, so on the next boot the bundle is superseded by a new version. Owners, evidence, exceptions and risk links stay with the old version and have to be moved by hand.
