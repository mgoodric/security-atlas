- **feat(connectors): slice 657 — webhookrecv shared validation-handshake seam.** Extracts the vendor-specific **validation-handshake-in-adapter** shape — independently hand-rolled by **two** connectors (Intune's Graph `validationToken` query-param echo, slice 557; Event Grid's `SubscriptionValidationEvent` body event, slice 522) — into a **reusable seam** in `connectors/shared/webhookrecv`. A new `ValidationHook` interface (`Detect(req, body) (response []byte, contentType string, ok bool)`) and a new `HandleWithValidation(w, req, max, hook, verifier, build)` entrypoint consult the hook **AFTER** the size-bounded body read but **BEFORE** the verify-first `Verifier.Verify` call: a validation request (**unsigned by design** — it carries no delivery HMAC/secret) is answered with the hook's exact bytes + content-type at `200` and **builds NO record / never calls Verify / never calls BuildAndPush**; a non-handshake delivery falls through to the **UNCHANGED** verify-first path. **Backward-compatible (D1):** the existing `Handle(w, req, max, verifier, build)` becomes a thin wrapper passing a nil hook, so the six existing adapters (mdm Jamf+Intune-delivery, github, hris, pagerduty, eventgrid delivery) keep compiling and behaving **byte-identically** (the existing `handler_test.go` is unmodified and green). **Both handshake connectors adopt the seam:** Intune's `validationTokenHook` echoes the token verbatim as `text/plain` (bounded by `maxValidationTokenLen`) via `mdmwebhook.Receiver.ServeHTTPWithValidation`; Event Grid's `validationCodeHook` echoes `{"validationResponse":"<code>"}` as `application/json` (bounded by `maxValidationCodeLen`, byte-identical trailing-newline shape) via `Receiver.ServeHTTP` — both adapters' slice-557 / slice-522 tests stay green unmodified. **Verify-first invariant preserved (AC-4):** a forged/non-handshake delivery with a bad signature is rejected `401` and **never** reaches BuildAndPush even with a hook configured (no bypass; test-asserted), and a real validation request short-circuits `200` without ever calling Verify/BuildAndPush (test-asserted). **Invariant #3 honored — push only; ZERO `internal/api/` / `migrations` / `proto` / `schemaregistry` changes:** the handshake + receiver stay source-side in the connectors. **Log-injection (b245 CodeQL):** validation tokens/codes are attacker-controllable and are **never logged** raw on the new path. **Type: JUDGMENT** — the backward-compat strategy (new entrypoint vs option), the `ValidationHook` shape, the per-adapter detection + preserved response bytes, and the verify-first ordering proof are recorded in `docs/audit-log/657-validation-handshake-decisions.md`.
