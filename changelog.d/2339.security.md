- **fix(modules): a refused request to a switched-off module is audited, and an unreadable module switch answers 503 (#2339).** The module gate runs before the OPA step, so a request to a switched-off module used to leave no `decision_audit_log` row. It now writes one (`result` `deny`, `reason` `module_disabled`, `resource_type` `module`, the module key, the actor and the switch in `policy_hits`), at most once per tenant, actor and switch every five minutes so a polling client cannot flood the log; a failed write is logged and the 404 stands. When the flag store cannot be read, a request to an optional module now answers `503 {"error":"module_state_unavailable"}` with `Retry-After` instead of falling back to the module's default (which served a module the tenant may have switched off); it is logged and counted on `atlas.module_gate.state_errors`. Core routes are unaffected. Decisions log: `docs/audit-log/2339-module-switch-follow-ups-decisions.md`.
