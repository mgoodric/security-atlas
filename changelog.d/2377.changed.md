- **docs(connectors): upgrade note for the connector control-id defaults the SCF 2026.3 CRY remap changed (#2377, follow-up to #1976).** **Upgrade note:** five connector defaults now stamp a different `control_id`: AWS `--control-id` `scf:CRY-04`→`scf:CRY-07`, Azure `--storage-control` `scf:CRY-04`→`scf:CRY-07`, Azure `--keyvault-control` `scf:CRY-09`→`scf:CRY-10`, GCP `--bucket-control-id` `scf:CRY-04`→`scf:CRY-07`, and k8s `--secret-control` `scf:CRY-01`→`scf:CRY-02`. If you set any of these flags to the old code by hand, change it to the new one; in SCF 2026.3 the old code names a different control. Evidence already ingested keeps the code it was pushed with, so continuity across the change is manual. The table is in the upgrade guide. The walkthrough fixtures and docs, and the web test mocks, that used `CRY-05` to mean encryption at rest now use `CRY-07` (Encrypting Data At Rest); `CRY-05` is Encrypting Data In Transit in 2026.3.
