- **fix(web): slice 691 — refresh vendor detail after recording a review (closes 691).** After an operator recorded a vendor review, the read-only vendor detail (`/vendors/{id}`) the app redirects back to served the **cached pre-review** vendor — the derived review-status badge (`overdue` → `on time`, computed at render from `last_review_date` + `review_cadence`), the "Last review" field, and the slice-688 review-history timeline all stayed stale until a hard reload. **Root cause:** the detail, edit, and record-review surfaces share the TanStack keys `["vendor", id]` + `["vendor-reviews", id]`, the global `QueryClient` default carries `staleTime: 60_000` (`web/lib/queryClient.tsx`), and neither review-recording path invalidated after its mutation — so on nav-back within the 60s window the on-mount refetch was suppressed and the cached body painted. **Fix (frontend-only):** both review-recording surfaces now invalidate the relevant query keys on the mutation success path before `router.push(`/vendors/{id}`)`. The **edit form** (`web/app/(authed)/vendors/[id]/edit/page.tsx` `onSubmit`, the slice-424 path that sets `last_review_date`) and the dedicated **record-review form** (`web/app/(authed)/vendors/[id]/reviews/new/page.tsx`, the slice-688 ledger-append surface) both `await Promise.all([invalidate(["vendor", id]), invalidate(["vendor-reviews", id])])` (awaited so the refetch is in flight before navigation — avoids the slice-424 shared-key read-back race; no fixed timeout) and fire `["vendors"]` + `["vendors-burndown"]` prefix invalidations (the list/burndown keys carry filter params, partial-key match marks every variant stale) without blocking nav, so the list has no stale overdue row on return to `/vendors`. Recording a review updates `vendors.last_review_date` server-side (`internal/vendor/reviews.go`, the most-recent-`reviewed_at` recompute), so the badge re-derives off the refetched row — no schema change. **JUDGMENT D1 — fix BOTH surfaces:** the slice doc named only the edit-form path (filed as a slice-424 spillover, before slice 688's `reviews/new` form landed), but the slice title ("after recording a review") and the audit intent cover the dedicated record-review form too; both append a review and route back, both had the gap, so both are fixed. **AC-1/AC-2/AC-3/AC-4:** the slice-424 e2e (`web/e2e/vendor-review-workflow.spec.ts`) now asserts the post-record refresh as a guaranteed contract — the deferred derived-status flip (`overdue` → `on time`) and the updated Last-review field after the edit-form save, plus a new `slice 691: recording a review on reviews/new refreshes the detail` test that drives the record-review form end-to-end (stateful hermetic mock: `/api/vendors/{id}` flips overdue→on-time and `/api/vendors/{id}/reviews` empty→one-row after the POST) and asserts the flipped badge, updated Last-review date, and the new timeline row appear without a hard reload. **No wire/schema/backend change** (`git diff --stat origin/main...HEAD -- internal/ migrations/ proto/ cmd/` is empty). **Type: JUDGMENT.** Decisions log: `docs/audit-log/691-vendor-detail-refresh-decisions.md`.
