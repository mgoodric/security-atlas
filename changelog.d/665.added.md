- **fix(board): slice 665 — board-pack generate-draft empty-date validation feedback.** Clicking **"Generate draft"** on `/board-packs` with an empty (or malformed) quarter-end date previously **silently no-opped** — the submit handler's `if (periodEnd)` guard swallowed the empty case with no toast or inline message, and the button's `disabled={!periodEnd}` left the operator unsure whether the action failed or was processing (audit **ATLAS-015**, 2026-06-10 empty-tenant UI audit). The fix adopts the canonical `risks/new` client-side-validation pattern: a new pure `validateGenerateForm` fn (`web/app/(authed)/board-packs/validate.ts`, extracted so vitest can pin it without the React tree) returns a field-error map; the page renders an inline `role="alert"` message wired to the date input via `aria-invalid` + `aria-describedby`, validates on submit-attempt, and re-validates live afterward so the error clears as the operator fills in a valid date. **AC-1** empty/invalid date now shows clear inline feedback — no silent no-op; **AC-2** the form blocks submission (the server is never contacted with an empty date) and the submit no longer relies on a silent `disabled` to hide the failure; **AC-3** a valid date still generates the draft (no regression). **Anti-criterion honored:** zero change to board-pack generation semantics — client-side validation/feedback only (no `internal/api/`, `migrations`, `proto`, or wire-shape changes). New vitest pin (`validate.test.ts`, 6 cases) + a per-file coverage floor in `web/coverage-thresholds.json`; new Playwright spec (`web/e2e/board-pack-generate-validation.spec.ts`, hermetic BFF route-mock per the slice-594 lesson) asserts both the empty-date feedback and the happy path. **Type: AFK.** Slice doc: `docs/issues/665-board-generate-draft-empty-date-validation.md`.
