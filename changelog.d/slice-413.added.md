- **feat(oscal): slice 413 — cosign-kms OSCAL bundle signing + retained embedded-ed25519 (368 Phase 1).** Implements Phase 1 of the [ADR-0010](docs/adr/0010-oscal-cosign-signing.md) ADOPT-DEFERRED plan (maintainer-approved 2026-06-03): the **reachable** cosign value with **no Fulcio/Rekor/OIDC dependency**, keeping the in-process ed25519 path as the air-gap default. Keyless (Fulcio + Rekor) stays deferred to slice 414. **New package `internal/oscal/cosign`** — a conservative wrapper around the `cosign sign-blob`/`verify-blob` binary: an injectable `runner` exec boundary (the cosign binary is a swappable, unit-testable dependency — every wrapper branch is covered with no binary, the real-binary path via the integration tier), explicit context timeouts, a **curated env allowlist** (the cosign subprocess inherits ONLY `PATH`/`HOME` + cloud-KMS credential families `AWS_*`/`GOOGLE_*`/`AZURE_*`/`VAULT_*` — never the atlas DSN or OAuth keys; deny-by-default, `WithExtraEnvKeys` for non-standard vars), no shell interpolation (argv slice, never `sh -c`), and structured error mapping (`ErrCosignNotFound`/`ErrSignFailed`/`ErrVerifyFailed`/`ErrTimeout`/`ErrBadConfig`). **`Mode` discriminator** on `oscal.Signature` (`embedded-ed25519` | `cosign-kms`; `cosign-keyless` reserved-not-implemented per P0-413-1) recorded in the export manifest with `omitempty`; **verification dispatches** on it. **`KMSSigner`** signs the same deterministic bundle digest via cosign + a cloud-KMS key reference (`ATLAS_COSIGN_KMS_REF`), recording the `key_ref` in the manifest so an auditor verifies with **stock `cosign verify-blob`** — closing the bulk of the slice-327 M-3 / canvas-§9 auditor friction. **Backward-compat (P0-413-4):** a pre-413 manifest with no `mode` field defaults to `embedded-ed25519` and still verifies (directly tested via `TestBackwardCompat_OldManifestVerifies`, which strips the `mode` key to simulate the old format). `VerifyBundle` (no cosign dep) handles embedded and **fails closed** (`ErrCosignVerifierRequired`) on a cosign bundle rather than silently passing; `VerifyBundleWithCosign` is the cosign-aware superset the CLI uses; both recompute the digest from on-disk member bytes (a member-tamper is rejected before cosign even runs). **Offline guarantee (P0-413-1):** the sign argv pairs `--use-signing-config=false` + `--tlog-upload=false` — empirically load-bearing (cosign v3.0.6 still uploads a Rekor entry with only the former); `TestIntegration_NoTlogEntry` asserts no `tlogEntries` are produced. **CLI** `atlas oscal sign|verify|config-check` (new `oscal` parent; the existing `oscal-export` command is unchanged) with `config-check --probe` running a live KMS test-sign. **Mode resolution** centralized in `ResolveSigningConfig` (`ATLAS_OSCAL_SIGNING_MODE` explicit, a set KMS ref infers `cosign-kms`, else the air-gap-safe embedded default — P0-413-2; `cosign-keyless` rejected). **`ReadBundle`** loads a written bundle for verification (path-traversal-guarded). **Defaults per ADR-0010:** docker-compose self-host → `embedded-ed25519` (unchanged); connected self-host with KMS → `cosign-kms` (opt-in); SaaS/Helm at GA → `cosign-kms` (revised AC-9). **CI:** the `tests-integration` job now installs cosign (`sigstore/cosign-installer@v4.1.2`, v3.0.6 — same pin as release signing) so the Mode-A integration tests run; `internal/oscal/cosign` enrolled in the integration package list (slice-345 guard green) with a hard coverage floor of 88 (merged ~91.5%). The Mode-A integration tests use a locally-generated throwaway cosign key pair as a clearly-marked cloud-KMS stand-in (no real key material — GitGuardian-safe). cosign binary provenance (v3.0.6, Apache-2.0, bundle-clean) recorded in the asset inventory §2.3 + §3.3 per AC-10. Operator runbook at `docs/runbooks/oscal-signing.md`. **Server export wiring stays embedded** (the CLI carries the cosign-kms capability now; threading mode-aware signing through `Exporter` is the top revisit item — D9). **Type: JUDGMENT** — decisions log `docs/audit-log/413-cosign-kms-signing-decisions.md`.
