- **fix(admin): a group-role mapping can only name its own tenant's IdP config (#2643).** `POST /v1/admin/group-role-mappings` now looks `idp_config_id` up among the caller's own `oidc_idp_configs` under RLS and returns the same 400 for another tenant's config and a nonexistent one, so the create is no existence oracle. Migration `20261271000000_group_mapping_idp_config_fk` adds `UNIQUE (tenant_id, id)` on `oidc_idp_configs` and a composite FK `(tenant_id, idp_config_id) -> oidc_idp_configs(tenant_id, id) ON DELETE CASCADE`, so deleting a config removes its mappings; SCIM-source mappings (`idp_config_id` NULL) are unaffected. **Upgrade note:** the migration aborts with counts (`nonexistent=N, cross_tenant=M`) if existing mappings already reference an unresolvable config, and deletes nothing; resolve those rows before re-running it.
