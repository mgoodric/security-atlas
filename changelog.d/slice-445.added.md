- **feat(notify): slice 445 — email/SMTP notification delivery channel (delivery substrate).** A solo security leader lives in their inbox, not the app — so the in-app notification store (slice 029) needed a way to reach email. This slice ships a **delivery sink** (NOT a notification producer — P0-445-5) over a **thin email-provider abstraction** (one `Provider` interface + one stdlib `net/smtp` implementation — no multi-provider plugin system) configured entirely via `ATLAS_SMTP_*` environment variables for the single-VM self-host target (AC-1). An **opt-in per-user email channel** (`internal/notify/email`) reads the opted-in target user's unread notifications **under that notification's own tenant context** (RLS FORCE) and delivers **one digest email** — summary counts grouped by type + a deep-link back into the authenticated app, **minimum-disclosure** (no raw evidence payloads, S3 URLs, or confidential control text — AC-4/AC-7/P0-445-4). Delivery goes **strictly to the user's account email** resolved server-side (no user-controlled recipient field — P0-445-1/AC-3). Two new RLS four-policy tables (`email_channel_optin`, `email_delivery_log`) back the **default-OPTED-OUT** master toggle (P0-445-7) and **idempotent** delivery — a UNIQUE `(tenant_id, recipient_user_id, digest_key)` claim-before-send means a given per-day digest is never double-sent and acts as the 24h per-user rate limit (AC-5); delivery outcome (sent/failed) + attempt count are recorded with an SMTP send timeout and re-attempt-on-next-tick backoff (no hot retry — AC-8). **Load-bearing security guards:** all header fields (subject/recipient) are **CRLF-stripped unconditionally** so notification-derived content can never inject a header or extra recipient (open-relay guard — AC-6/AC-12/P0-445-2), all HTML-body interpolation is `html.EscapeString`-d (AC-14), the type label comes from a closed map (never echoes a raw row value), and SMTP credentials are env-only and never logged (threat-model S). **Cross-tenant email is proven absent** by an integration test that runs each tenant's delivery under its own GUC and asserts Tenant A's notification never reaches Tenant B's user (AC-13/P0-445-3). A new `GET/PUT /v1/me/email-channel` endpoint + BFF route + a minimum-surface Settings → Notifications "Email delivery" toggle expose the opt-in (AC-9). Self-host SMTP env config documented in `deploy/docker/.env.example` (AC-10). Email only — no SMS/Slack/webhook (P0-445-6; filed as follow-ons 541-545). **Type: JUDGMENT** — provider-abstraction shape, minimum-disclosure body, and rate-limit default recorded in `docs/audit-log/445-email-channel-decisions.md`.
