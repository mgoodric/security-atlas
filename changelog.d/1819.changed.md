- **feat(risks): drop the `risk_category` enum; the organisation's category is the only record (#1819, contract step of #1745).** Migration `20261125000000_drop_risk_category_enum` drops `risks.category`, the `risks_category_sync` dual-write trigger and the `risk_category` type; `risks.category_id` is the only record of a risk's category. The migration refuses to run (`check_violation`, naming the count and first risk id) if any risk's reference disagrees with its enum value, so no install loses a category silently. A custom category can now hold risks and be the organisation default (aggregation meta-risks fall back to it). API and MCP clients that send the old enum values keep working: they are the seeded slugs. SQL writers name a category by slug with the new `risk_category_id(tenant, slug)`. **Upgrade note:** the column is dropped, so a SQL script or report that reads `risks.category` must join `org_risk_categories` on `category_id` instead. The down migration is not lossless for risks on custom categories (`docs/audit-log/1819-drop-risk-category-enum-decisions.md` D2).
