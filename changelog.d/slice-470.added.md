What it could NOT prove — because the single-VM seed ships **no proxy container by design** (466 D4) — was the **multi-container topology**: a real header-overwriting proxy process in front of atlas, connecting from a container-network address inside `TRUSTED_PROXY_CIDRS`. This slice lands exactly that e2e. A `nginx:1.27-alpine` proxy (`deploy/docker/proxy/nginx.conf`) that **hard-overwrites** `X-Forwarded-For` with a fixed TEST-NET-3 client IP (`203.0.113.10`) is added in front of atlas via a compose overlay (`deploy/docker/docker-compose.proxy.yml`) on a **fixed-subnet** network (`10.123.0.0/24`, so `TRUSTED_PROXY_CIDRS` is deterministic, not a guess against docker's arbitrary default 172.x subnet). The existing self-host e2e harness (`deploy/docker/test-self-host-bundle.sh`) gains a third mode, `proxy`, with two assertions driving the production `/auth/local/login` → `clientIP(r)` → `sessions.ip_address` path, each pinned to the **exact** session row its login created (captured via the `atlas_session` cookie value = session id, read back as the postgres superuser): **AC-2** — a login THROUGH the proxy records the proxy-supplied client IP (`203.0.113.10`); **AC-3** — a DIRECT login forging `X-Forwarded-For: 198.51.100.66` (TEST-NET-2) records the direct container peer, **NOT** the forged value (the walk stops at the untrusted hop — spoofing rejected). The `proxy` leg is added to the CI `test-self-host-bundle` matrix (`mode: [bundled, external, proxy]`, AC-4); the failure-logs dump step is made overlay-aware so the proxy container's logs surface on a red run. **Does NOT touch the resolver** (`internal/api/auth/clientip.go` — slice 466 shipped + tested it; this slice is the e2e PROOF, not a reimplementation), does NOT change the shipped single-VM seed (no proxy there by design), and adds **no** Go integration package (so `scripts/integration-shards.txt` is untouched). **Validation:** the full proxy-mode harness was run **live** locally against a real multi-container bring-up — both AC-2 and AC-3 assertions passed; `nginx -t` confirms the proxy config syntax; `docker compose config` confirms the overlay merge (proxy service + `atlasnet` fixed subnet + `TRUSTED_PROXY_CIDRS` on atlas) and that the base `bundled`/`external` modes are unchanged. **Type: JUDGMENT** — decisions log `docs/audit-log/470-trusted-proxy-e2e-decisions.md` (placement, image, assertion mechanism, deterministic-CIDR, hard-overwrite, bundled-auth-reuse).
