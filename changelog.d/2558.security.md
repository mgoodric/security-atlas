- **fix(web): every BFF route refuses an unsafe path param before it reaches the platform (#2558).** The 82 dynamic `/api` routes still on the #2312 exemption list now guard every `[param]` before they read the bearer or build the upstream path: UUID params with `rejectNonUUID`, and the rest (slugs, theme and category refs, metric ids, feature keys, session and credential ids, anchor and requirement codes, board-pack section keys, CSF profile kinds) with the new `rejectUnsafeSegment` allowlists in `web/lib/api/bff.ts`. A `..`, `.`, empty, slash, backslash or `%` segment answers 400 with no upstream call, so `/api/x/%2E%2E/verb` can no longer re-target a parent `/v1` path. The ratchet `web/app/api/bff-uuid-guard.test.ts` strips comments, checks every param of every handler (including `route.tsx` and `route.js`) and that the guard precedes the bearer read, drives each handler with `..` in each param, and has no exemption list. Four routes the old ratchet counted as guarded were fixed too: `controls/[id]/bundle` and `controls/imports/[id]/export` guarded after the bearer read, and `policies/[id]` GET had no guard.
