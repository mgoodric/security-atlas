- **fix(audit): LLM settings audit rows name the acting credential and record exact before values; a busy tenant no longer fails another tenant's import suggestions (#2329).** Every `me_audit_log` row written for an LLM routing change, a control import settings change, or a `PATCH /v1/tenants/{id}` change now carries `actor_principal`, the acting credential's id (a user's id, or the key or OAuth client id for a machine credential, never a secret), so a change made with a bootstrap or machine key is attributable. Routing `PUT` and `DELETE` take a per-tenant lock before reading the before value, so concurrent changes record a chained history. Control import suggestion runs share their per-process slots fairly between tenants, and an upload that cannot get a slot within 2 seconds is suggested in the background (returned `pending`) instead of being marked `failed`.
