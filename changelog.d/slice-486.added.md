- **feat(connectors): slice 486 — Azure connector (Entra ID + Storage), bringing the third major cloud to parity with AWS.** A new `connectors/azure/` connector follows the locked slice-004 / slice-045 pattern verbatim (register-per-run, stable `actor_id`, hour-truncated `observed_at`, scope minimums, vendor-native read-only auth) and emits **two evidence kinds**: `azure.entra_role_assignment.v1` (directory-role / RBAC assignments + service-principal / app-registration inventory, read-only Microsoft Graph — `Directory.Read.All` + `Application.Read.All`) and `azure.storage_account_config.v1` (encryption-at-rest, secure-transfer / minimum-TLS, public-blob-access posture, read-only Azure Resource Manager — ARM **Reader** role). Each record is pushed to the platform's single `IngestEvidence` / `Push` API with a sha256 content-hash and stable optional fields — **no platform-side wire change** (invariant #3, P0-486-1); the connector registers `profiles_supported=[pull]` and names its interval honestly (operator-scheduled, recommended 24h — **not** "continuous monitoring", P0-486-6). **Least-privilege (P0-486-2):** only the two read-only Graph application permissions + the ARM Reader role are required and documented; the README and the `atlas-azure permissions` subcommand both render the canonical set and a unit test rejects any future widening into `*.ReadWrite.*` / `*.Manage` / Owner / Contributor / Global Administrator. **Confidentiality (P0-486-3/4):** the connector collects configuration + role-assignment metadata only — never blob/object contents, Key-Vault secret values, storage access keys, SAS tokens, or user PII beyond the assignment's display name — and the Azure credential (Entra app-registration client-credentials or managed identity) stays source-side, redacted on every format path, never logged and never placed in an evidence record (tests assert both). **Two evidence-kind JSON Schemas** land in the schema-registry tree with `x-default-scf-anchors` set (`IAC-21`/`IAC-22` for Entra, `CRY-04`/`NET-04` for Storage) and are registered in `DefaultSeed`. **Tests:** the Graph + ARM surfaces are interface-faked (no live Azure, no real credentials in CI); the in-package bufconn integration test exercises the full collect → build → `Push` → receipt round-trip for both kinds, asserts same-hour idempotency, no-PII/no-secret payloads, and credential redaction. New per-package coverage floors added; no migration (schemas seed via `DefaultSeed`). Does **not** ship AKS / NSG / Key-Vault / Azure-Policy evidence or an event-driven profile (P0-486-7; follow-ons filed in band 519–524). **Type: JUDGMENT** — the two evidence-kind shapes, their `x-default-scf-anchors`, and the scope minimum recorded with confidence + detection-tier in `docs/audit-log/486-azure-connector-decisions.md`.
