- **feat(risks): slice 681 — risk register sortable columns + per-risk detail (closes 681).** Two risk-surface UX gaps from the 2026-06-10 demo-tenant audit (**ATLAS-039**, low/minor enhancement). **(AC-1 — sortable columns)** With 20+ rows the register had **no way to order by the columns an operator triages on**: the RESIDUAL / INHERENT-SEVERITY / REVIEW-DUE headers were inert. They are now **sortable** — a header click toggles `desc`/`asc` (new columns sort descending-first for worst/latest-first triage), the active column shows a direction caret, and the sort round-trips through the URL (`?sort=<key>:<dir>`, bookmarkable; the default **inherent-severity descending** is treated as "no param" so the canonical URL stays clean). The sort is **client-side** — it joins the list view's established fetch-the-full-list-then-filter-and-paginate-in-the-browser pattern (slices 100/244/246), so there is **zero wire/sqlc/migration change** (decisions log D1); a pure comparator (`web/app/(authed)/risks/sort.ts`, mirroring the `filters.ts` per-page seam) holds the ordering + toggle math, with pending (un-evaluated) rows sorting to the END in both directions so a brand-new risk never jumps the triage queue. **(AC-2 — per-risk detail)** The list said per-risk detail was a "future slice" and offered only "View in hierarchy" — no honest drill-in. The misleading banner is **removed** and risk **titles now link to a read-only `/risks/{id}` detail** — exactly the fix slice 672 made for the identical policy finding (ATLAS-024). The backend read API (`GET /v1/risks/{id}` → `GetRisk`) already exists and is **RLS-tenant-scoped** (`store.Get` runs under the cookie session's tenant; a cross-tenant id resolves to 404), so this is a pure consume-what-exists change — a new BFF proxy (`web/app/api/risks/[id]/route.ts`, mirroring `/api/policies/[id]`; bearer-cookie only, never a client `tenant_id`) + `getRisk`/`fetchRiskDetail` fetchers + a client detail page (loading skeleton, 401→/login, 404→in-shell `notFound()`). The detail is **read-only** (no edit/delete/link — anti-criterion) and carries its own "View in hierarchy →" link so the org-tree scoping workflow composes alongside the title drill-in. **Proof (AC-4):** 19 vitest cases pin the comparator + asc/desc toggle + URL round-trip; 5 vitest cases pin the detail BFF (bearer forwarding, no-tenant_id, 404→"risk not found", 5xx scrubbed); a hermetic Playwright spec (route-mocked BFF per slice 594) asserts each header re-orders the rows and a title navigates to its detail; per-file coverage floors added same-PR for `sort.ts` + the detail BFF. **Type: JUDGMENT.** Decisions log: `docs/audit-log/681-risk-register-ux-decisions.md`.
