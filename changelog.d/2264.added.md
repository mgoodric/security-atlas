- **feat(oscal): catalog and profile imports declare their SCF release (#2264).** `atlas-oscal import-catalog` and `import-profile` take `--scf-release`, or read an `scf-release` prop on the document's metadata (the entry profile's, for a profile), and match control ids against that release's SCF codes instead of whatever release is current, as component-definition imports have since #1771. A `--scf-release` that is not loaded fails the import (`unknown SCF release`); a prop that names an unloaded release falls back to the current one with a warning (#1771 D5); a flag that contradicts the prop is refused. With neither, the import matches in the current release as before and reports a deprecation warning, until #1774 makes the declaration required. Both reports (text and `--json`) and the success audit row now carry `scf_release`. The three OSCAL importers share one resolver, `internal/oscal/scfbind`. Decisions in `docs/audit-log/2264-oscal-catalog-profile-scf-release-decisions.md`.
