- **feat(connectors/okta): the Okta connector emits `okta.mfa_policy.v2`, and stock control cc6_1 reads it (#2901).** v1 reported Okta group ids where cc6_1 looked for the name `everyone`, read only the Classic `settings.factors` map (so Identity Engine policies never reported WebAuthn), and dropped the policy status, so cc6_1 failed on every real tenant. v2 adds `status`, `priority` and `applies_to_everyone`, which is true when the policy's group ids include the org's Everyone group (found as the `BUILT_IN` group named Everyone). It reads both Classic and Identity Engine settings, and reports `fido_webauthn`, `fido_u2f` and `webauthn` as `webauthn`. The password no longer counts as an MFA factor. An inactive policy carries the verdict `na`. If Okta hides the Everyone group (a Group Administrator token), the MFA-policy pull stops with an error instead of reporting every policy as not covering everyone. cc6_1 now passes when an ACTIVE policy requires MFA, applies to everyone and allows WebAuthn; it no longer reads v1 snapshots. The v1 schema stays registered for existing records. **Upgrade note:** cc6_1's query changed, so on the next boot the stock bundle is superseded by a new version. Owners, evidence, exceptions and risk links stay with the old version and have to be moved by hand. Upgrade the Okta connector with the platform: until then cc6_1 receives no v2 records and is inconclusive.
