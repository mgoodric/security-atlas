- **fix(demo): a busy demo teardown answers 503 with `Retry-After`, and TRUNCATE can no longer remove a frozen audit's rows (#3094).** `POST /v1/admin/demo/teardown` used to answer a generic 500 when it gave up waiting for the `audit_periods` lock; it now answers 503 with `Retry-After: 5` and `code: "teardown_busy"`, and deletes nothing, so a client can retry. `atlas-cli demo teardown` and `demo teardown-legacy` print "audit_periods is busy; retry" in the same case. Migration `20261316000000` adds a `BEFORE TRUNCATE` guard to `audit_periods`, `populations`, `audit_period_freeze_revisions` and `audit_period_frozen_controls`: a TRUNCATE that reaches any of them, directly or through `CASCADE` (for example `TRUNCATE controls CASCADE`), is refused while that table holds a frozen audit's rows. The table owner can still disable the trigger inside its own transaction.
