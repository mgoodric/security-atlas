- **feat(risks): a risk import brings in each risk's treatment and acceptance under the rules a single create follows (#2842).** `POST /v1/risks/imports` maps a treatment column (`untreated`, `accept`/`accepted`, `mitigate`, `transfer`, `avoid`; an unknown value is rejected with the new `invalid_treatment` reason). An accepted row stages a proposed acceptance with its justification and until-date and is created proposed, never approved, so an approver confirms it in the tool under the usual approval rule; a row without both is rejected with the new `invalid_acceptance` reason. The register's accepter is kept on the staged row and shown as historical, never as the risk's accepter. A linked-controls column resolves to the tenant's active controls by control id or bundle id, and refs that match none are listed on the row. A `mitigate` row with no resolved control, or a `transfer` row with no instrument reference, stages as `untreated` with the `treatment_downgraded` flag and the register's treatment shown beside it. The review page shows these fields. Migration `20261288000000_risk_import_treatment`.
