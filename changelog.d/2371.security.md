- **fix(risks): a risk can no longer be created with its acceptance already approved (#2371).** `POST /v1/risks` and the MCP `create_risk` tool used to accept `treatment=accept` with `acceptance_status=approved` and a free-text `accepter`. That recorded an approval with no separation of duties and an unverified accepter. Both paths now return 400 (`treatment_validation_failed`) for `acceptance_status=approved`, `accepter` or `accepted_until` at create. Create the risk with `acceptance_status=proposed`, then approve the acceptance. Clients that sent an approved acceptance on create must now make that second call.
