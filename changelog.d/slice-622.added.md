- **feat(connectors): slice 622 — Kubernetes CNI-native NetworkPolicy (Cilium / Calico) coverage.** Extends the slice-523 `k8s.networkpolicy_coverage.v1` collector (`connectors/k8s/internal/netpol`) so that segmentation enforced through a CNI's own policy CRDs is no longer a false-FAIL. Many production clusters enforce segmentation entirely through `CiliumNetworkPolicy` / `CiliumClusterwideNetworkPolicy` (`cilium.io`) or Calico `NetworkPolicy` / `GlobalNetworkPolicy` (`crd.projectcalico.org`); under slice 523 such a cluster read as fully unprotected. The collector now detects each CNI CRD by **API discovery** (a new read-only `k8slist.Reader.Probe` — 200 present / 404 absent; **never hard-fails when absent**), reads the present CRD's policy objects (`get,list`, via the shared slice-621 paginating `k8slist.ListAll`), and folds their coverage into the **same** per-namespace default-deny assessment. A cluster-wide CNI policy (`CiliumClusterwideNetworkPolicy` / Calico `GlobalNetworkPolicy`) with an all-endpoints zero-rule shape folds default-deny into every namespace. **AC-2 — source distinction:** each policy summary gains an optional `source` (`networking.k8s.io` / `cilium.io` / `crd.projectcalico.org`) and the namespace record gains an optional `sources` set, so the evaluator can reason about which enforcement plane covers a namespace. **JUDGMENT — per-CNI default-deny field mapping (the load-bearing call):** Cilium counts default-deny when `endpointSelector` is empty (all endpoints) and the direction's `ingress`/`egress` key is present but empty (zero rules); Calico when `selector` is all-endpoints (`""` / `all()`), `spec.types` includes the direction, and there are zero rules — both **conservative under-credit** (a non-empty selector, an allow rule, or Cilium's `specs[]` form is NOT credited; better a false-FAIL the operator fixes than false-credited segmentation). **AC-3 — least privilege:** the documented ClusterRole gains exactly two read-only rules — `cilium.io: ciliumnetworkpolicies,ciliumclusterwidenetworkpolicies` and `crd.projectcalico.org: networkpolicies,globalnetworkpolicies`, verbs `get,list` only (no write verb, no `secrets`, no wildcard); the `DocumentedClusterRole` least-privilege test, `atlas-k8s permissions` render, and README stay in sync. **AC-4 — over-collection guard (slice-523 verbatim):** CRD SPEC metadata only — the Cilium `endpointSelector` / Calico `selector` are read only for their all-vs-narrow disposition, the `ingress`/`egress` rule arrays are counted as opaque `json.RawMessage`, and `source` carried into a record is an API-group string; a dedicated no-leak test embeds selector labels, peer endpoints, a CIDR, and ports in the CNI specs and asserts none escapes, and the integration allow-list test admits only the two new SPEC-metadata keys. **Schema (D5): additive, no version bump** — `source` (per policy) + `sources` (per namespace) are added as **optional** properties to the existing `k8s.networkpolicy_coverage/1.0.0.json` (records predating CNI support stay valid and read as upstream-only); the kind stays `1.0.0` in `DefaultSeed`. Push-only (invariant #3, no platform-side wire change); `profiles_supported` stays `[pull]`. New `netpol` coverage at 97.2% (floor 93). **Type: JUDGMENT** — the CRD-detection approach, the per-CNI default-deny mappings, the cluster-wide-folding rule, the additive-field-vs-bump call, and the CRD-absence fallback are recorded with detection-tier in `docs/audit-log/622-k8s-cni-native-networkpolicy-decisions.md`.
