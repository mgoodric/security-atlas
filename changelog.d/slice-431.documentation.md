- **docs: slice 431 — operator guide for connecting an external IdP (OIDC).** Adds `docs-site/docs/oidc-setup.md`, a published guide that walks an operator through connecting Okta, Entra ID (Azure AD), or Keycloak to a running deployment, plus a nav entry in `docs-site/mkdocs.yml`. The guide is grounded in the **shipped** admin SSO surface: per-tenant DB-backed `oidc_idp_configs` (`issuer_url`, `client_id`, `client_secret_enc`, `redirect_url`, `allowed_email_domains`) set via the `/admin/sso` web UI and `PATCH /v1/admin/sso`, validated with `POST /v1/admin/sso/preflight` — **not** environment variables (there is no `OIDC_ISSUER_URL` env var; that path does not exist and is explicitly corrected). Security guidance is load-bearing (the project's slice 086/161 open-redirect history): the redirect URI is documented as **exact-match, own-origin, fixed at `/auth/oidc/callback`** with an explicit warning against wildcards/foreign hosts, and the client secret is documented as **encrypted at rest, entered via the admin surface, never committed to `.env`/compose/repo**; `allowed_email_domains` is recommended as the principal restriction. Local mode stays available (OIDC is additive). Multi-IdP federation, SCIM, and group-to-role mapping are noted as out of scope. Every endpoint, request field, and column was verified against `internal/api/adminsso/handler.go`, `internal/auth/oidc/oidc.go`, and the `oidc_idp_configs` schema; all example issuer URLs, client IDs, secrets, and redirect URIs are placeholders. Documentation-only: no `internal/`, `web/`, or CI changes. `mkdocs build --strict` passes.
