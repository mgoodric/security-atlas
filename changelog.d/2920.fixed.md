- **fix(controls): stock control cc6_6 is inconclusive, not failed, when a host's firewall state was not read (#2920).** `soc2_cc6_6_boundary_protection` counted a missing `firewall_enabled` as off. Since the osquery connector omits fields it did not read (#2916), and Fleet's host API has no firewall field, every Fleet host failed the control. Now a host whose latest `osquery.host_posture.v1` record has no `firewall_enabled` makes the control inconclusive. A host observed off still fails it, even when other hosts are unread, and the control passes only when every host is observed on. Records without a `host_uuid` are left out, latest-per-host orders by the host's `last_seen_at` before the record's `observed_at`, and records that tie on both count as on only if all say on. The description is rewritten and names `firewall_source` (#2921). **Upgrade note:** the query changed, so on the next boot the bundle is superseded by a new version. Owners, evidence, exceptions and risk links stay with the old version and have to be moved by hand. A Fleet tenant without a firewall Fleet policy named for the connector sees cc6_6 go from fail to inconclusive.
