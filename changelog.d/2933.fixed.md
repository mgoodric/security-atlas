- **fix(connectors/github): an empty ruleset bypass list or an unexplained protection 404 no longer settles `github.repo_protection.v2` (#2933).** GitHub returns a ruleset's `bypass_actors` only to a caller with write access to it, and doesn't say whether others get no field or `[]`. An empty list now counts as "nobody bypasses" only for a repository ruleset on a repo the caller administers; otherwise `enforce_admins` is omitted, so cc8_1 can't pass on a withheld list. A classic branch-protection 404 reads as unprotected only when its message is `Branch not protected` or `GET /repos/{o}/{r}/branches/{b}` reads `protected: false`; any other 404 leaves the repo inconclusive instead of failing it. The README's PAT table now lists the fine-grained permission each endpoint needs, taken from GitHub's permissions page: Administration read for classic protection, Metadata read for rules and rulesets, and optionally Contents read for the branch cross-check.
