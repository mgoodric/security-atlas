- **feat(notify): slice 542 — per-notification-kind email preferences.** Slice 445 shipped a MASTER email opt-in (one toggle: email delivery on/off for the whole user) and deliberately deferred per-kind filtering (445 D7); the slice-108 `user_notification_preferences` table already carried a per-event `email` channel column that 445 never consulted, so an opted-in user received a digest covering ALL their unread kinds with no way to mute a single noisy kind. **This slice makes the 445 digest build CONSULT that existing column** — no new migration. The composition is **master AND per-kind** (D1): the master switch (default OFF) stays the OUTER gate, evaluated first; the per-event `email` pref is the INNER filter, evaluated only after the master gate passes — so a per-kind row can only ever NARROW delivery for an already-opted-in user, never widen it (a master-OR composition would let slice-108's default-`true` per-kind rows silently override the master-off default, regressing P0-445-7). **Default-on-missing-row (D2 — the backward-compatibility call):** an opted-in user with no per-kind row keeps receiving every kind exactly as before; a kind is suppressed only by an EXPLICIT `email=false` row for its mapped event, inheriting slice-108's own default-on policy (108 D3) so the digest and `/v1/me/preferences` agree on what "no row" means. **The type→event mapping is NOT 1:1 (D3):** `control.drift` (dot) maps to slice-108 event `control_drift` (underscore); `audit_note.reply` + `evidence.staleness` have no slice-108 event row and default to included-when-master-on (a future slice adding their event rows MUST add the mapping — documented inline). **Filter location + shape (D4):** the filter is a pure-Go map narrowing applied to the in-memory `counts` map AFTER the RLS-scoped read and AFTER the master gate, BEFORE the empty-digest skip — recipient resolution and tenant scoping are structurally untouched (P0-542-2, threat-model I: the filter can remove a kind's count but never redirect delivery), the total is recomputed so an all-muted digest skips cleanly with no empty email, and the minimum-disclosure body shape is unchanged (P0-542-3). Pure logic in new `internal/notify/email/kindfilter.go` (no DB import; fast table-tests in `kindfilter_test.go` covering master-on+kind-on→send / master-on+kind-off→mute / master-on+no-row→default-on / unmapped→included); two new integration tests (`TestDeliverDigest_PerKindMute_RemovesCountKeepsDelivery` proves a muted kind's count is removed but the same account email still receives the surviving kinds; `TestDeliverDigest_AllKindsMuted_Skips` proves all-muted → skip). **Type: JUDGMENT** — filter composition semantics + default-on/off-per-kind + the type→event mapping recorded with rationale + detection-tier in `docs/audit-log/542-per-notification-kind-email-prefs-decisions.md`.
