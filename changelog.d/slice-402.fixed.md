- **fix(audit): slice 402 — audit-log export silently omitted `feature_flag` + cross-actor `me` rows.** The slice-135 audit-log data-export handler (`internal/api/adminauditlog/export.go`) called the slice-124 `unifiedlog.Query` aggregator without setting `CallerIsPrivileged`, leaving it at the zero value `false`. The slice-270 row-visibility predicate that `false` enables — designed for the non-privileged `/v1/activity/unified` endpoint — hides `feature_flag` audit rows entirely and restricts `me_audit_log` rows to those whose `actor_id` equals the caller's own user id. But the export endpoint is admit-gated to exactly `{admin, auditor, grc_engineer}` (the same `callerAllowedUnified` gate the unified-list handler uses, which sets `CallerIsPrivileged = true` unconditionally at `unified.go:161`), so every caller that reaches the export query is privileged by construction. The defect meant a forensic / audit export silently dropped all feature-flag audit events and every `me` event not authored by the exporting operator — an audit-completeness gap, not a test artifact. Fixed by setting `clampedParams.CallerIsPrivileged = true` before the aggregator call, mirroring the unified-list handler. Surfaced by the never-CI-run slice-135 export integration suite during the slice-402 integration enrolment (three tests failed: the 9-kind reuse assertion saw only 7 kinds, the 100k-row 413 cap never tripped because the `me` rows were filtered out, and the audit-period-freezing test returned an empty body). Decisions log at `docs/audit-log/402-integration-drain-batch-2-decisions.md`.
