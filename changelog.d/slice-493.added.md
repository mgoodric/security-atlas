- **feat(oscal): slice 493 — SSP carries authored control-implementation narratives (not the synthesized placeholder).** Canvas §8.2 specifies the OSCAL SSP is generated from "control implementation narratives," but the exporter shipped a stopgap (slice 030 `D-narrative`): the SSP `ControlImplementation.Statement` was filled twice — first with `c.ApplicabilityExpr` (an explicit placeholder), then overwritten with a templated `"<Title> (control family: <family>). Implementation owned by role <owner>."` string — because the read projection (`ListActiveControls`) exposed `title`/`control_family` but **not** the control bundle's human-authored `description` (slice 009). Every exported SSP therefore had cookie-cutter implementation statements where the narrative that explains _how_ a control is implemented — the single most-read section of an SSP to an auditor — should be. This slice wires the authored narrative through. **(1) Read path (AC-1):** a purpose-built companion query `ListActiveControlsWithDescription` carries the `description` column; `ListActiveControls` is left untouched for its other consumers (pattern-matched to the slice-137 / slice-175 export-projection convention — D-query). **(2) Statement source (AC-2/AC-4):** `ControlImplementation.Statement` is filled **exactly once** with the authored description verbatim; the `ApplicabilityExpr` placeholder write and the double-fill loop are removed. **(3) Fallback (AC-3, P0-493-1):** a control with no authored description (a manual/minimal bundle) falls back to a **clearly-labeled** synthesized summary (`"[Auto-generated summary — no authored implementation narrative on file.] Control \"…\" (family: …); implementation owned by role \"…\". Provide an authored …"`) — **never** an empty statement, and labeled so an auditor is not misled into thinking the boilerplate is authored (D-fallback). No LLM is involved — the statement is the operator's text or a deterministic template, honoring the constitutional AI-assist boundary. **(4) Tenant-scoped + point-in-time consistent (AC-5):** the new read runs under the same `app.current_tenant` RLS context inside the same export transaction as the rest of the aggregate (invariant #6). **Tests:** unit branches at the proto-conversion tier (authored-present verbatim, description-absent labeled fallback, no double-fill) + a real-Postgres integration suite proving the authored description reaches the SSP JSON verbatim (AC-6), the description-less fallback (AC-7), and — load-bearing — **tenant isolation** (Tenant A's control descriptions never appear in Tenant B's SSP, AC-8 / P0-493-2). The content + isolation assertions run through the real DB read path with a capturing fake bridge so they execute on every CI run, not only when the optional Python oscal-bridge is present (D-test); a separate bridge-gated round-trip test covers wire fidelity and skips when the bridge is unavailable (slice-030 D2 precedent). Does **not** change the AP/AR/POA&M serializers (P0-493-3), does **not** alter the cosign signing path (P0-493-5), and does **not** add rich-text rendering or per-component decomposition (scope discipline — follow-on).
