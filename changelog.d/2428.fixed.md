- **fix(authz): tenant admins and grc_engineers who sign in normally pass the approve and tenant-admin handler gates (#2428).** jwtmw sets `IsAdmin`/`IsApprover` from the super-admin claim only, so a tenant `admin` JWT was refused on framework-scope, exception, policy and risk-acceptance approval, audit-period writes (including attaching a population, #2425), metric inputs and more, while OPA admitted it. Handler gates now call `authz.IsTenantAdmin` / `authz.IsTenantApprover`, which read the caller's live `user_roles` as authzmw resolved them for the decision, so a revoked role stops working on the next request even while the token is live. Approver means admin or grc_engineer where OPA grants grc_engineer that action, and admin only on OSCAL component claims, board narratives, questionnaires, MCP write proposals and action-plan verify, where OPA admits admin only. `/v1/admin/*`, install-wide gates and `/v1/me` `is_admin` stay super-admin (#2216). `/v1/me` gains `is_tenant_admin` and `is_approver`; the action-plan Verify button keys off `is_tenant_admin`.
