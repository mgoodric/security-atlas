- **feat(control): slice 574 — control-bundle upload test-gate ("tests must pass to upload").** Slice 496 shipped the control-bundle test runner (`atlas-cli controls test`) but deliberately did NOT wire it into the upload path (P0-496-5). This slice closes that loop: `POST /v1/controls:upload-bundle` now runs a bundle's declared `tests/` cases through the SAME slice-496 runner (`bundletest`) before persisting, and — under the strict v0 policy — REJECTS the upload with a `400` + the per-case test report when any case fails or errors, so a control whose evidence query is provably wrong against its own fixtures never reaches the catalog. `ParseTarball` now captures the archive's top-level `tests/*.yaml` bytes into `control.Bundle.TestFiles`; a new in-memory `bundletest.RunFromFiles` evaluates them without writing the archive to disk. SQL-language fixtures run on the upload path (the handler holds a tenant tx via the new read-only `control.Store.WithReadOnlyTenantTx`, which is always rolled back — constitutional invariant #2: the gate evaluates, it never mutates evidence). A bundle with no `tests/` is accepted with a `gate_warning` (no-tests policy, matching the slice-496 CLI); per-tenant `require_bundle_tests_pass` config is deferred to slice 608. The CLI `controls upload` renders the gate's per-case report on a `400` so the author sees which fixture failed.
