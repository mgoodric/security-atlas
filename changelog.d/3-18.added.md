- **feat(connectors): slice 524 — Kubernetes Pod-Security-Standards admission-config evidence.** Adds a fourth evidence kind to the Kubernetes connector (slice 487): `k8s.pod_security_admission.v1` — the **enforced** side of workload hardening, complementing the **actual**-posture `k8s.workload_security_context.v1` kind. A new `connectors/k8s/internal/pss` collector reads, read-only via the Kubernetes API (`get,list` on **core namespaces** — a rule the base connector already holds, so **NO new ClusterRole rule** is required), the per-namespace Pod-Security-Standards admission configuration: which namespaces carry the `pod-security.kubernetes.io/enforce`, `/audit`, and `/warn` labels and at which level (`privileged` / `baseline` / `restricted`), plus the optional pinned `*-version` label per mode. The recurring "is hardening **enforced at admission**, not just configured per-workload" auditor ask previously needed a manual upload. **Verdict (JUDGMENT, D2):** the connector verdicts the per-namespace admission posture from the `enforce` label — `PASS` when the namespace ENFORCES a hardened level (`baseline` or `restricted`); `FAIL` when no `enforce` label is set (unenforced — **recorded honestly**, not dropped) or when `enforce` is only `privileged`; `audit`/`warn` modes are reported but do not drive the verdict (they observe/warn, they do not block admission); the platform evaluator owns the final (control, namespace) call. **Label-filter / over-collection guard (structural, the locked pattern, LOAD-BEARING):** the namespace object carries arbitrary labels AND annotations — the PSS HTTP client reads **only** the six `pod-security.kubernetes.io/*` label keys off `metadata.labels` and never decodes `metadata.annotations` at all (`metadata.annotations`, `spec`, and `status` have no matching struct field, so Go's JSON decoder discards them); the `RawNamespace` / `Admission` structs carry **no field** for a pod spec, secret, container env, or any other namespace label/annotation, and a reflection guard (`TestStruct_PSSLabelsOnly_NoOverCollectionFields`) FAILS THE BUILD the moment such a field is added. The client test (`TestClient_OnlyPSSLabelsReachRecord`) serves a namespace carrying unrelated labels (a team label, a secret-looking label value) AND annotations (a kubectl last-applied blob with embedded secret material, an owner-email PII annotation) alongside the PSS labels, and asserts only the PSS labels reach a record; the integration over-collection test allow-lists the PSS-only payload keys. **Anti-criteria (P0):** push only — no platform-side wire change (invariant #3); read-only namespace `get,list` only — **NO new ClusterRole rule**, no write verb, no `secrets`, no wildcard (the `DocumentedClusterRole` least-privilege test + `atlas-k8s permissions` render + README stay in sync, the namespaces rule's `Gates` string now documents the PSS kind); the token is never logged or placed into a record; the `pull` profile is named honestly (NOT continuous monitoring). **Bounded (DoS guard):** a bounded namespace page read (`limit=500`) + a per-run namespace cap (`maxNamespaces=5000`). Schema `k8s.pod_security_admission/1.0.0.json` carries `x-default-scf-anchors=["CFG-02"]` (Secure Baseline Configurations) and is wired into `schemaregistry.DefaultSeed` (drift bijection passes with the new kind). sha256 content-hash per record; hour-truncated `observed_at`; register-per-run; stable `actor_id=connector:k8s:pss@<version>`; new `idem.PSSAdmissionKey` (distinct from the netpol key via the kind prefix); per-namespace `namespace` scope dimension (one record per namespace); `--pss-control` (default `scf:CFG-02`) + `--skip-pss`. Scope discipline (D3): namespace PSS **labels only** — does NOT read the cluster's `AdmissionConfiguration` file (out of API reach), validating/mutating webhooks, or third-party policy engines (OPA/Gatekeeper, Kyverno) — those are documented follow-ons (spillover band 652–659). Neutral fixtures only (obviously-fake namespace names; no real-looking kubeconfig/tokens). New `connectors/k8s/internal/pss` coverage floor. **Type: JUDGMENT** — the evidence-kind shape, the label-filter/over-collection-guard mechanism, the scope-minimum (no new ClusterRole rule), the anchor choice (CFG-02), and detection-tier are recorded in `docs/audit-log/524-k8s-pss-decisions.md`.
