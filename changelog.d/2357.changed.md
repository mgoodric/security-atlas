- **chore(changelog): per-PR changelog fragments (#2357).** Unreleased changes now live in `changelog.d/<pr-or-issue>.<type>.md`, one file per PR, instead of at the top of `CHANGELOG.md`, so parallel PRs stop conflicting on it. `scripts/changelog.sh` validates (`check`), previews (`render`) and, at release time, assembles the fragments under a release heading (`assemble <version>`). The new `changelog-fragment` CI check fails a PR that changes code without adding a fragment; the `no-changelog` label, docs-only changes, Dependabot and release-please PRs are exempt. The 403 entries of the former `## Unreleased` section were moved into fragments unchanged.
