- **fix(help): the lifecycle diagram SVG check and browser strip parse the file and allow-list its elements (#2429).** `public/help/diagrams/*.svg` can be opened directly on the app origin, so the Node gate (`unsafeSvgParts`) now parses each file as strict XML instead of matching regexes, and both it and the browser strip (`stripActiveSvg`) keep only an allow-list of static SVG elements. Attributes are judged by local name on their decoded value: an `href` under any namespace prefix must be a `#fragment`, `on*` handlers and entity-encoded `javascript:` values are refused, and CSS escapes and non-fragment `url()` are refused in every attribute value and style sheet, `@import` and `image-set()` in `<style>` and `style=""`, and every `xml:` attribute but `xml:space` and `xml:lang` (so no `xml:base`). `<animate>`, `<set>`, `<foreignObject>`, processing instructions and DOCTYPEs are refused outright. `parseStateDiagram` rejects Mermaid `%%{init}%%` directives, and the renderer parses every block before Mermaid sees it. Every committed diagram still passes; no re-render was needed.
