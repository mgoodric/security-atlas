- **feat(attest): an attestation records pass or fail, and the latest attestation decides (#2111).** `manual.attestation` schema 1.2.0 adds `result` (`pass` / `fail`) and `fail_reason`, which a fail must have; the schema and the attest handler both refuse a fail without one. A 1.0.0 or 1.1.0 attestation, or a request with no `result`, still counts as a pass. The attest handler records the submitted result instead of always recording pass, and evaluates the control as soon as the record lands. In evaluation, only the latest attestation in the freshness window counts toward the attestation outcome (ordered by `observed_at`, then `ingested_at`, then record id); automated evidence keeps "any fail in the window fails". The control page now shows the control's result, has an **Attest** button on manually attested controls, and after an attestation shows "Evaluating…" until the new state arrives, giving up with a message after 30 seconds. Existing ledgers are unaffected: every attestation recorded before this change is a pass.
