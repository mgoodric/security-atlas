- **feat(control): slice 496 — control-bundle test runner (fixture evidence → expected pass/fail).** Canvas §4.4 lists "Tests — fixture evidence + expected pass/fail" as a first-class part of every control bundle and slice 009 promised a tests directory, but there was no runner: a control author writing a Rego/SQL/JSON-path evidence query could not verify it short of uploading the bundle and eyeballing live state. This slice ships the runner — the control-as-code analogue of "tests before code". **(1) Fixture format (AC-1, JUDGMENT call):** a `tests/` directory beside `control.yaml` holds `*.yaml` files of test cases; each case declares a `name`, fixture evidence `records` (`result` + optional `observed_at` + optional `payload`), and an `expected_state` (pass|fail|na|inconclusive). `observed_at` defaults to the case's evaluation instant so a simple case is in-window without freshness reasoning; unknown YAML keys are a loud parse error. **(2) Runner reuses the LIVE engine (AC-2/AC-4, anti-criterion P0-496-1):** a new DB-free seam `eval.EvaluateFixture` runs the SAME freshness-window filter + per-language dispatch (rego|sql|jsonpath) + result-precedence rollup + no_evidence override that the live `eval.computeRow` uses — there is no parallel "test interpreter" that could drift, so a bundle that passes its tests behaves identically when evaluated for real. Rego + JSON-path evaluate fully in-process; SQL runs through the same read-only-subtransaction sandbox when a tx is supplied. **(3) No live ledger (invariant #2 / P0-496-2 / AC-9):** fixtures are presented in-memory; the runner performs no writes and touches no tenant evidence — the Rego/JSON-path path needs no Postgres at all, and a SQL query with no DB connection reports a typed `ErrFixtureSQLNeedsDB` rather than a false pass (fail-loud). **(4) CLI (AC-5/P0-496-6):** `atlas-cli controls test <bundle-dir>` reports per-case PASS/FAIL/ERROR (text + `--json`) and **exits non-zero on any failure or error** so it slots into CI for community-contributed bundles; a bundle with no tests is a stderr warning, not a failure. **(5) Threat model (AC-8/D):** the per-query timeout the live evaluator enforces applies; a cancelled context or broken query surfaces as a test error, never a hang. **Faithful-semantics note (recorded, not "fixed"):** records that EXIST but aged out of the freshness window are `stale` (not `no_evidence`), so the no_evidence override does NOT fire — the query runs over an empty in-window set and returns its default; the runner reproduces this exactly. New package `internal/control/bundletest` (coverage floor 85, Leg-A integration-shard enrolment for the SQL end-to-end test). Does NOT add a control-authoring UI, fixture record-and-replay, or a hard upload-time test gate (P0-496-5; all follow-ons). **Type: JUDGMENT** — fixture-format shape, in-memory evidence-set stubbing, and result rollup recorded with detection-tier in `docs/audit-log/496-control-bundle-test-runner-decisions.md`.
