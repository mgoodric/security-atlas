- **feat(connectors): slice 538 — PagerDuty postmortem/retrospective evidence.** Adds a third evidence kind `pagerduty.postmortem_summary.v1` to the slice-489 PagerDuty connector — the postmortem / retrospective surface 489 deliberately deferred (P0-489-7) because a postmortem is dense free-text routinely embedding customer data, responder PII, and root-cause prose. A new `connectors/pagerduty/internal/postmortems` collector + read-only HTTP client reads `GET /postmortems?since=&until=` over the SAME bounded look-back window the incident-summary kind uses (`--lookback-days`, default 90) and emits, per postmortem, the auditor META-FACTS ONLY: the opaque `postmortem_id`, the linked `incident_id`, the review `status` (normalized enum `not_started`/`in_progress`/`in_review`/`published`), the `created_at` / optional `published_at` timestamps, and the corrective-action ROLLUP (`action_item_count` + `action_items_completed` + `action_items_open`). This proves incidents are reviewed and corrective actions tracked for SOC 2 CC7.5 ("recover from identified security incidents") and the slice-372 IR continuous-improvement loop — NOT the story. **JUDGMENT — the over-collection / redaction boundary (DOMINANT, load-bearing):** the connector NEVER collects the postmortem narrative body, timeline free-text, root-cause prose, an action item's operator-authored title/description, customer data, or responder PII. Action-item titles are operator-authored free-text (they routinely name the affected customer/system/root-cause) and are therefore EXCLUDED — only the item's completion state feeds the count. The boundary is enforced **structurally**: the record types (`RawPostmortem` / `Postmortem` / `RawActionItem`) have NO field that can hold the narrative or a title BY CONSTRUCTION, `json.Decode` discards JSON keys with no matching struct field (so the narrative never enters memory even when the payload carries it), and a reflection guard (`TestMetadataOnly_StructuralGuard`) FAILS THE BUILD the moment a free-text/PII-named field is added (proven: adding a `Body` field trips it). A drop test (`TestClient_ListPostmortems_DropsNarrative`) feeds a fake API response that deliberately embeds a narrative body, root-cause prose, responder PII (`123-45-6789`, `jane@acme.example`), and action-item titles, and asserts none reaches a record. The schema carries `x-default-scf-anchors=[IRO-13, IRO-09]` (Root-Cause Analysis + Incident Reporting) and is registered in `DefaultSeed` (the schema-drift bijection passes with the new kind). **Anti-criteria (P0):** push only — no platform-side wire change (invariant #3); read-only PagerDuty token only — NO new credential scope beyond the slice-489 read-only key (the `permissions` subcommand documents the `/postmortems` GET); the token is never logged or placed into a record; the `pull` profile is named honestly (NOT continuous monitoring). **Bounded (DoS guard):** bounded look-back window + bounded page loop (`maxPages`) + a hard per-run record cap (`postmortems.MaxRecords`); a paginated/pathological source stops at the cap rather than reading forever (`TestClient_ListPostmortems_StopsAtRunCap`). sha256 content-hash per record; hour-truncated `observed_at`; register-per-run; stable `actor_id=connector:pagerduty:postmortems@<version>`. Neutral fixtures only (obviously-fake `PM-FAKE-*` / `INC-FAKE-*` ids; no real-looking PagerDuty tokens). Tests: collector unit (normalize/rollup/drop-blank/hard-cap), client unit (narrative-drop + pagination + run-cap + auth header), the structural metadata-only guard, the record-builder unit (kind/idempotency/payload allow-list/omit-published-when-unpublished), the `run`-seam push/collect/error tests, the integration no-PII/no-free-text assertion on the postmortem path, and the schemaregistry drift/bijection test. New `connectors/pagerduty/internal/postmortems` coverage floor. **Type: JUDGMENT** — the evidence-kind shape, the redaction/over-collection-boundary mechanism (HOW the narrative can't leak), the anchor choice (CC7.5 → IRO-13/IRO-09), and detection-tier are recorded in `docs/audit-log/538-pagerduty-postmortem-decisions.md`.
