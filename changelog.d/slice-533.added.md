- **feat(connectors): slice 533 — Datadog Cloud-SIEM detection-rule evidence.** Adds a second evidence kind `datadog.siem_rule.v1` to the existing `atlas-datadog` connector binary — the Cloud-SIEM / Security-Monitoring detection-rule surface slice 488 deferred (P0-488-7). A new `connectors/datadog/internal/siemrules` collector + Datadog client reads, read-only, the cursor-paginated `GET /api/v2/security_monitoring/rules` (`security_monitoring_rules_read` scope) and captures per rule: name, detection class (log / signal_correlation / threshold), enabled state, highest case severity, and the notification-target HANDLES. **JUDGMENT — sibling kind, NOT reuse (slice-488 D1):** a detection rule carries a severity + a detection-class field the operational `monitoring.alert_config.v1` shape lacks, so it gets its own kind rather than widening the shared monitoring kind into a lowest-common-denominator blob — exactly the split slice-488 D1 reserved. The schema carries `x-default-scf-anchors=[MON-01, THR-01]` and is registered in `DefaultSeed` (the schema-drift bijection passes with the new kind). Push only (invariant #3); `profiles_supported=[pull]`; stable `actor_id=connector:datadog:siemrules@<version>`; register-per-run; hour-truncated `observed_at`; honest 24h operator-scheduled interval. The `run` subcommand threads the SIEM kind alongside the monitor kind (`--siem-control` flag + a seam). **Anti-criteria (P0):** read-only `security_monitoring_rules_read` suffices — no write/admin scope, no new platform-side wire surface (P0); RULE configuration only — NEVER firing signals, the detection query's raw log samples, matched-event payloads, secret webhook URLs, integration tokens, recipient PII, or the raw detection query: the collector record structs (`RawRule` / `Rule`) have NO field capable of holding any of those (a reflection-based structural over-collection test, `TestStructuralOverCollectionGuard`, pins the field set, mirroring the slice-488 / 614 pattern). Bounded cursor loop + hard per-run page cap (`maxPages=50` × `pageSize=100` ⇒ 5,000 rules) + 60s run timeout (DoS guard): an unbounded source stops with `ErrRuleCapExceeded` rather than reading forever. Neutral fixtures only (obviously-fake rule ids/handles; no real-looking Datadog API/app keys). Tests: collector + Datadog-client unit (faked surface, incl. a multi-page cursor case + a cap-termination case), the structural over-collection guard, the schemaregistry drift/bijection test, `run`-seam push/error tests, and the in-package bufconn integration round-trip (descending into notification targets for the no-PII/no-secret allow-list). New `connectors/datadog/internal/siemrules` coverage floor. **Type: JUDGMENT** — the sibling-kind-vs-reuse call, the scope-minimum + over-collection-guard mechanism, the stable-field choices, and the anchor choice are recorded with detection-tier in `docs/audit-log/533-datadog-siem-rules-decisions.md`.
