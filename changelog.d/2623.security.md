- **fix(risks): only a person proposes a risk acceptance (#2623).** **Breaking for machine integrations that proposed acceptances:** `PATCH /v1/risks/{id}/acceptance/propose`, and `POST /v1/risks` with `acceptance_status=proposed`, now return 403 for a credential bound to no user (an unbound `key_…` API key, an OAuth client, the bootstrap admin), and nothing is written. A key bound to a user counts as that user, and a login session is unchanged. A confirmed MCP proposal that proposes an acceptance (`create_risk` with `acceptance_status=proposed`, `update_risk_treatment` with `acceptance_status=proposed`) is refused the same way when the confirmer is a machine (403, code `approval_refused`), and the proposal stays pending. Creating a risk that proposes no acceptance is unaffected. Upgrade note: integrations that proposed acceptances with an unbound key should use a key bound to the person proposing.
