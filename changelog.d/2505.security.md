- **fix(authz): handler checks and device approval use live role assignments, not the role list baked into a session token (#2505).** A revoked role no longer lets its holder export vendors or audit periods, read the demo status, see or record role-targeted policy acknowledgments, or pass the program-read checks. Approving a CLI login (`atlas login`) now gives the device token the approver's current roles. Before, it copied the session's role list, so a revoked role was re-issued with a fresh expiry. A key bound to a user now passes these checks on its owner's current roles, not on the role label copied when the key was minted. A user with no current role gets a device token with no role.
