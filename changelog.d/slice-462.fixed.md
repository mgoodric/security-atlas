- **fix(infra): slice 462 — admindemo integration suite self-corrects a leaked `demo` tenant instead of false-redding on a dirty-DB re-run.** The `internal/api/admindemo` integration suite uses a fixed `demo`-slug tenant for the seed/teardown happy path; `TestSeed_EnvUnsetGets503AndDoesNotSeed` (and the non-admin path) assert `!demoTenantExists("demo")` as a correctness invariant (env unset / non-admin ⇒ no seed ⇒ no demo tenant). The cleanup helper previously registered ONLY a deferred `t.Cleanup` removal, so when a prior run left a `demo` tenant behind — either because a different package `t.Fatal`'d and killed the `go test` process before admindemo's cleanups ran (the abort scenario), or because `demoseed.Seeder.Teardown` itself left the `tenants` row even on a passing run (observed this slice) — the next run saw the stale tenant and false-redded at `handler_integration_test.go:261` ("demo tenant exists after 503"), blaming the env-unset path for a row it never created. CI never hit it (fresh DB per run + curated package order), but a local re-run against a non-fresh DB did. **Root-cause fix (mirrors slice 461's "setup self-corrects, does not assume" philosophy, for the `tenants` table rather than `scf_anchors`):** a new test-only helper `removeDemoTenant(t, slug)` removes the demo tenant best-effort and is now called SYNCHRONOUSLY at the top of each demo-dependent test (establishing a clean precondition regardless of prior aborted/leaky state) AND retained as the deferred `t.Cleanup` (so this run's tenant does not leak forward even on a failed assertion). The removal first tries `demoseed.Seeder.Teardown` (the clean path for a fully-seeded, forensically-marked leftover) then runs an unconditional FK-ordered raw sweep + `DELETE FROM tenants` keyed on id — the catch-all for a bare/partial leftover that `Seeder.Teardown` refuses (it declines to delete a tenant lacking the slice-205 forensic mark) or cannot fully clean. **Proof:** with a leaked `demo` tenant inserted, the pre-fix test FAILS at line 261 and the post-fix test passes; three consecutive `-p 1` runs against the same DB without cleaning between them are all green. The env-unset assertion's intent is unchanged — it still requires 503 + no seed; only the precondition is now established rather than assumed. Test-harness only; no production code, no schema, no handler slug change. **Spillover surfaced:** `demoseed.Seeder.Teardown` can leave the `tenants` row behind even on a passing run — recorded in the decisions log as a potential PRODUCT teardown bug for a focused follow-up, NOT fixed here. **Type: JUDGMENT.** Decisions log: `docs/audit-log/462-admindemo-tenant-leak-cleanup-decisions.md`.
