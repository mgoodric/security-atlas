- **feat(mapping-overlays): overlay edges join the SCF remap queue (#1804).** `catalog import-scf` now also queues every tenant's active overlay edge left on an older SCF release's anchor in `scf_overlay_remap_proposals`, in that edge's own tenant. Each is classified with the same lineage rule as control and catalog-edge proposals (`scfimport.ClassifyLineage`), and the import prints the counts per class. The tenant's own writers (admin, grc_engineer) decide them at `/v1/mapping-overlays/remap-proposals`: list, approve, reject or keep-legacy. No super-admin is needed. Approval creates the overlay edge on the chosen anchor in the target release with the same requirement, relationship, strength, rationale and source, and retires the old one with reason `remapped`. Every decision appends to `scf_overlay_remap_decisions`. Both tables are under FORCE RLS with composite `(tenant_id, …)` foreign keys, and decisions run as the app role under the caller's tenant with no SECURITY DEFINER function. Decisions: `docs/audit-log/1804-overlay-edge-remap-decisions.md`.
