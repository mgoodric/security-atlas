- **fix(security): slice 466 — replace the `TRUST_FORWARDED_HEADERS` boolean with a `TRUSTED_PROXY_CIDRS` allowlist + right-to-left `X-Forwarded-For` walk.** Closes the client-IP-spoofing vector left open by slice 465's blunt boolean (which trusted the left-most `X-Forwarded-For` IP unconditionally, so a deployment not actually behind a header-scrubbing proxy let any client forge its source IP — poisoning the slice-162 session-row client-IP capture that feeds the audit log and the admin-demo per-IP rate limiter). The structurally-correct design ships: `internal/api/auth/clientip.go` now parses `TRUSTED_PROXY_CIDRS` (comma-separated CIDRs) into a validated set **once at boot** (`InitTrustedProxiesFromEnv`, called from `cmd/atlas/main.go`; a malformed CIDR fails loud with `os.Exit(1)` rather than silently per-request — AC-1), then resolves the client IP by walking `X-Forwarded-For` **right-to-left**, accepting a hop only while the immediately-connecting peer is inside an allowed CIDR and stopping at the first untrusted hop (the real client — AC-2), so a client-forged XFF prefix is never reached. Empty/unset `TRUSTED_PROXY_CIDRS` ⇒ direct TCP peer (`r.RemoteAddr`), byte-identical to today's unset behavior (AC-3, proven via `docker compose config` diff). `TRUST_FORWARDED_HEADERS=1` is retained as a **documented deprecated alias** that maps to trust-any-proxy (`0.0.0.0/0` + `::/0`) with a boot-time deprecation warning, superseded when `TRUSTED_PROXY_CIDRS` is set (AC-4). The `internal/api/admindemo/handler.go` rate-limiter `clientIP` was de-duplicated to delegate to the new exported `auth.ClientIP`, so both IP-capture surfaces share ONE implementation (no drift). A per-request hop cap (`maxForwardedHops=50`) bounds the walk against a pathological-header CPU sink (threat-model D). Plumbed through `deploy/docker/.env.example` (commented-off with the spoofing warning) + `docker-compose.yml` (`TRUSTED_PROXY_CIDRS: ${TRUSTED_PROXY_CIDRS:-}`, empty default) + the slice-430 config reference (`docs-site/docs/configuration.md` row + security-critical bullet; `config-reference-drift-check` green). Load-bearing unit tests (AC-5) cover forged-prefix-rejected (direct + prepended-through-proxy), single/multiple trusted hops, empty allowlist = direct peer, malformed header, malformed-CIDR-fails-at-boot, and the hop cap; two wire-level tests drive the resolver over a real TCP connection (`internal/api/auth/clientip_server_test.go`).
