- **fix(authz)!: a free-text role label derives nothing at OPA; a canonical one derives its role (#2596).** **Breaking** for machine integrations that relied on a free-text label: an unbound API key, a client_credentials machine token or a legacy credential whose `owner_roles` label names no canonical role (`admin`, `grc_engineer`, `control_owner`, `auditor`, `viewer`) used to act as `control_owner`, and now holds no role, so OPA refuses it what the handler gates already refused since #2595. Give such a credential a canonical role. **Security: widening.** A label of `admin` or `grc_engineer` now derives that role at OPA (it derived `control_owner`), matching the handler gates, which have counted it since #2428: an admin-labelled unbound key now passes OPA on admin routes such as `POST /v1/admin/users`. This is latent on HTTP today (API keys reach only gRPC, #2541 D5; machine tokens carry no role claim). The admin, approver and control_owner gates now read a machine token's label as `TenantRoleLabels` does. A bare credential (no label) keeps `grc_engineer`, and a key bound to a user is unchanged (#2431 ceiling). Decisions log: `docs/audit-log/2596-free-text-labels-derive-nothing-decisions.md`.
