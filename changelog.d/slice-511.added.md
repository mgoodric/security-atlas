- **feat(oscal): slice 511 — OSCAL profile import + resolution (resolve direction of invariant #8).** Slice 492 shipped OSCAL _catalog_ import; this slice adds _profile_ import — resolving an OSCAL profile's `import` / `merge` / `modify` directives against a supplied catalog into a concrete control baseline (the FedRAMP Low/Moderate/High shape: each is a profile over the NIST 800-53 catalog), then persisting that resolved set as a provenance-labeled imported baseline mapped requirement → SCF anchor (invariant #7). A new `ImportProfile` RPC extends the existing `oscal-bridge` (never a second process — P0-511-6); the bridge resolves via compliance-trestle's `ProfileResolver` (import-control selection, `merge`, `set-parameters` value substitution, and `alters`) **inside an isolated, ephemeral trestle workspace whose only catalogs are the ones the caller supplied**. **The load-bearing security property (P0-511-1 / threat-model I — information disclosure): the resolver NEVER dereferences an external `import.href`.** Every href is rewritten to a sandboxed `trestle://` path pointing at a supplied catalog before resolution; an `https://` / `sftp://` / `file://` / bare-path href is rejected as a structured error **with no fetch** (the external-href gate runs _before_ any positional catalog match, so a single-catalog import cannot smuggle an external reference through), and an href that maps to no supplied catalog errors the same way. Caps bound the expansion-attack surface (threat-model D / AC-3): a 16 MiB byte cap on the profile and on each supplied catalog (Go-side before the wire + bridge-side), a 10,000 resolved-control cap, a ≤16 supplied-catalog cap, and import-chain depth bounded to a single profile→catalog level by construction (a supplied document that is itself a profile fails the catalog parse). A Go `internal/oscal/profileimport` caller persists the resolved baseline **transactionally** (a resolution/validation failure commits nothing — AC-5 / P0-511-3) into the slice-492 tables, distinguished by a new `imported_catalogs.kind` discriminator (`'catalog'` | `'profile'`) + a `profile_title` provenance column (migration `20260608000000_oscal_imported_profiles.sql`, purely additive), `tenant`-scoped + `grc_engineer`-gated (P0-511-5), with an append-only audit row (`profile_imported` / `profile_import_rejected` — AC-7). The bundled SCF spine (`scf_anchors`) is never touched (P0-511-4) and SCF reconciliation reuses slice-492's deterministic crosswalk. CLI `atlas-oscal import-profile <profile-file> --catalog <file>... [--json]` (AC-8). The Go-side reconciliation logic is testable WITHOUT the bridge (pure-Go `helpers_test.go`); the end-to-end resolve + the no-external-fetch guard + cap enforcement are proven at both the bridge unit tier (pytest, monkeypatched socket asserts no network) and the Go integration tier (real Postgres + real bridge, self-skipping when the compliance-trestle bridge subprocess is unavailable — slice-030 D2). Component-definition import remains a separate follow-on (slice 512). **Type: JUDGMENT** — profile-resolution semantics (delegated to compliance-trestle vs done in Go), the sandboxed-no-deref design, the SCF reconciliation, and the persistence-shape call (`kind` discriminator vs a sibling table) recorded with detection-tier in `docs/audit-log/511-oscal-profile-import-decisions.md`.
