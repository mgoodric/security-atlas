- **feat(web): slice 479 — admin user-management UI: assign users to tenants + roles (incl. self).** Wires the slice-060 `/admin/users` scaffold (which rendered the role-permission matrix plus a placeholder table and documented a missing-endpoint gap) to the just-merged slice-478 API, giving a super-admin a supported, audited replacement for the hand-DB-surgery that was otherwise required to manage who belongs to which tenant. **User list (AC-1):** binds to `GET /v1/admin/users` via a new BFF route (`web/app/api/admin/users/route.ts`); a super-admin gets the cross-tenant shape (each row tagged with `tenant_id`) and a tenant-admin gets the within-tenant shape. The page derives a `cross_tenant` flag from the response **shape** (every row carrying a non-empty `tenant_id`) rather than a second probe, so the server stays the single source of authority truth. The slice-060 role-permission matrix is retained below the table as the canonical role reference. **Assign (AC-2):** a labelled dialog (user UUID + tenant UUID + a checkbox per canonical role, sourced from the slice-060 `ROLES` constant) POSTs to `/v1/admin/users/assign`; success/error render inline and the list refetches via TanStack Query invalidation. **Revoke (AC-3):** a per-row action behind a confirm dialog → `POST /v1/admin/users/revoke` (the within-tenant shape, which carries no row `tenant_id`, falls back to the session tenant from `/api/me`). **Self-assign (AC-4):** an "Add me to a tenant" affordance for super-admins; on success a notice explains that the current session token predates the new membership, so a full re-login (linked to `/login?from=/admin/users`) is required before the tenant appears in the switcher — we do **NOT** auto-switch (P0-479-3) and do not attempt a token-exchange that would fail on a not-yet-available tenant. **Authz-honest (AC-5 / P0-479-1 / P0-479-2):** authority is enforced **server-side** (478 is the gate); the BFF forwards the bearer and passes the upstream status + error through verbatim. A tenant-admin's within-tenant response shows **no** cross-tenant controls (no Tenant column, no self-assign button); a 403 from any mutation renders as a clear inline message, never a dead button or a silent failure. **Accessible (AC-6):** the assign dialog inputs are `<label htmlFor>`-associated, the role group is a `<fieldset>`/`<legend>`, error alerts carry `aria-live` + a stable id, per the slice-331 / slice-363 a11y lineage. **Scope:** UI over 478's API only — NO backend behavior (478 owns it), NO invitation/email/SCIM UI (P0-479-4), NO change to the membership-bounded switcher for normal users (P0-479-5). **Tests (AC-7):** vitest for both new BFF route handlers + their pure validation helpers (`route.test.ts`, `revoke/route.test.ts` — 24 cases, neutral `test-bearer-479` fixtures, per-file coverage floors added to `web/coverage-thresholds.json` per the slice-347 ratchet); a Playwright e2e (`web/e2e/admin-users.spec.ts`) mirroring `admin-tenants.spec.ts` (BFF mocked via `page.route()` — the 478 cross-tenant write is a BYPASSRLS platform-global row the harness cannot clean up; 478's Go integration tests own the real DB behaviour) covering the super-admin list + assign + self-assign re-auth notice + revoke confirm + the authz-honest tenant-admin case + the inline-403 case + the a11y labelling. **Type: JUDGMENT** — role-picker shape, response-shape-derived super-admin scope, re-login (not token-exchange) for self-assign, BFF-mock e2e, and the within-tenant revoke tenant_id fallback recorded in `docs/audit-log/479-user-mgmt-ui-decisions.md`.
