- **fix(frameworkscope): the predicate of an activated or superseded framework scope is frozen (#1965, follow-up to #1943).** `PATCH /v1/framework-scopes/{id}` on an `activated` or `superseded` revision now returns **409** instead of editing it in place; a BEFORE UPDATE trigger (`framework_scopes_predicate_frozen`) refuses the same write off the API path. It also freezes every other column of such a row except `name`, `superseded_by`, `superseded_at` and `updated_at`. That includes `effective_from`, `framework_version_id` and the approval provenance. The only state move it allows is `activated → superseded`. Before this, an in-place edit changed what `as_of` reads reported as the predicate in force at an earlier time. To change an activated scope, create a new revision from it: `POST /v1/framework-scopes` now accepts `from_scope_id`, and `framework_version_id`, `name` and `predicate` become optional with it. The new draft takes the source's version, name and predicate unless you pass new ones, and copies every applicability decision from it. Activating the draft supersedes the source. The framework-scope page shows activated and superseded predicates read-only, with a "New revision" button. **API change:** clients that PATCHed an activated scope's predicate must switch to the new-revision flow.
