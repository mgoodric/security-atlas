- **feat(connectors): slice 520 — Azure NSG / firewall rule evidence.** Adds a fourth evidence surface to the slice-486 Azure connector: `azure.nsg_rules.v1`, the Network Security Group (NSG) firewall-rule posture read read-only via Azure Resource Manager (the SAME ARM **Reader** role the storage + AKS kinds use — no new Azure scope, P0-520-1). A new `connectors/azure/internal/nsg` collector + ARM client lists `Microsoft.Network/networkSecurityGroups` and emits, per NSG, the operator-authored inbound/outbound security rules (`name`, `direction`, `access` allow/deny, `protocol`, source/destination address-prefix, source/destination port range, `priority`) plus summary counts of subnet / NIC associations — the minimum that demonstrates the network-segmentation control (e.g. "no NSG allows 0.0.0.0/0 inbound on management ports 22/3389"). The ARM default security rules (platform boilerplate) are deliberately excluded. The kind ships a JSON Schema with `x-default-scf-anchors: ["NET-04", "NET-01"]` (Boundary Protection + Network Security), wired into `schemaregistry.DefaultSeed` (the schema-drift bijection passes with the new kind). **Over-collection guard (structural):** the `nsg.GroupConfig` / `nsg.SecurityRule` / `nsg.RawGroup` structs carry RULE metadata ONLY — there is no field for flow logs, packet captures, traffic contents, secrets, or PII — and the ARM client issues a `GET` to the NSG **list** surface ONLY, never a mutate (P0-520-2 / P0-520-3). A reflection test over the structs fails the build on any flow-log/packet/traffic-content/secret field name; the client test asserts the read is GET-only; the integration no-PII test enforces a per-kind payload allow-list that descends into the NSG rule list. The connector verdicts the deterministic segmentation posture: `FAIL` when a rule allows inbound from the whole Internet to a management port (SSH 22 / RDP 3389), `INCONCLUSIVE` on a per-NSG read error, `PASS` otherwise — descriptive only; the evaluator owns the binding decision. New `run` subcommand flags `--nsg-control` (default `scf:NET-04`) + `--skip-nsg`; `register` now announces four `supported_kinds`. NO platform API route, NO migration — evidence flows through the slice-013 ledger via the single `IngestEvidence` push RPC (invariant #3); `profiles_supported` stays `[pull]` with an honestly-named operator-scheduled interval. New package enrolled in `cmd/scripts/coverage-thresholds.json` at a 90% floor (measured 92.0%). **Type: JUDGMENT** — evidence-kind shape, rule field set, SCF anchors, scope minimum, and the structural over-collection boundary recorded with detection-tier in `docs/audit-log/520-azure-nsg-firewall-evidence-decisions.md`.
