- **feat(board): slice 501 — full multi-section board narrative + reusable numeric-verification library + systematic banned-phrase enforcement.** Scales the slice-440 four-gate board-narrative machinery from ONE section to the rollup-grounded section SET, with NO new guardrails and none weakened (P0-501-6). The board narrative is now a numbered set of AI-drafted sections — `control_coverage_summary` (slice 440, unchanged), `risk_posture_summary` (grounded in `board.Brief.TopRisks`: open-risk count, worst residual severity, oldest age), and `drift_activity_summary` (grounded in `board.Brief.Drift`: window days, net delta, controls drifted out — the audit-period-progress / KPI-movement signal). Every section projects the SAME frozen `board.Brief` the templated board pack already consumes (slice 031), so the slice invents no number and adds no source-of-truth read; freestyle commentary / asks-of-the-board stay HUMAN-authored (P0-501-7). Each section is a `SectionDef` (heading + item count + rollup-builder + per-section system/user prompt) consumed by a now section-agnostic `Service.GenerateSection` / `GenerateAll`; the slice-440 `Generate` is a one-line wrapper. The slice-182 **numeric-verification library** is extracted as the reusable `boardnarrative.VerifyNumbers(text, allowed, periodEnd)` — it finds every integer claim in a draft and auto-rejects on ANY mismatch against that section's deterministic pre-computation BEFORE the operator sees the draft (P0-501-2); every section consumes it with its own per-section `AllowedNumbers()`. The slice-182 **banned-phrase list** is wired into EVERY section's system prompt + a generalized post-generation check that rejects Section-1 exact-match phrases AND Section-3 context-sensitive filler forms (`robust program`, `strong posture`, …) while HONORING the Section-3 permitted-phrase allow-list (`robust against unauthorized merges` is NOT false-rejected — P0-501-3/P0-501-4; Go RE2 has no lookaround, so filler patterns enumerate the illegitimate constructions). Per-section approval is unchanged: each section is its own `board_narrative_sections` row, `ai_assisted=TRUE` until a one-click `Approve` records `human_approver` and flips `human_approved=TRUE` (slice-498 DB guard enforces `ai_assisted ⇒ human_approver` per section — P0-501-1/P0-501-8); every section writes an `ai_generations` audit row. The new `Store.ApprovedNarrative` (`human_approved=TRUE` under RLS) is the board-pack assembly read — an unapproved or suppressed section is structurally excluded, so the pack ships ONLY approved sections (AC-13). New route `POST /v1/board/narrative/generate-all` (board-reporting gated, grc_engineer role); `/generate` gains an optional `section` selector. Cross-tenant bleed proven absent across ALL sections against live Postgres (AC-12 / P0-501-5); local-Ollama default via the slice-499 per-tenant inference client. No migration (extends the slice-440 schema; adds one read query).
