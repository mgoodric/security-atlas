- **feat(connectors): slice 534 — Grafana SAML/RBAC config evidence.** Adds a second evidence kind `grafana.access_config.v1` to the slice-488 Grafana connector — the authn/authz configuration surface 488 deliberately deferred (P0-488-7) because SSO settings _embed_ secrets (SAML private key, OAuth client secret, LDAP bind password). A new `connectors/grafana/internal/ssoconfig` collector + read-only HTTP client reads `GET /api/v1/sso-settings`, `GET /api/teams/search`, and `GET /api/access-control/assignments` and emits, per Grafana instance, the auditor CONFIG + COUNTS ONLY: whether SSO is enabled (`sso_enabled`), the per-provider posture (`provider_type` + `enabled` + org-role mapping RULE names), aggregate team counts (`team_count` + `total_team_memberships`), and the RBAC role-assignment COUNTS rolled up by scope (`user_role_assignments` / `team_role_assignments` / `builtin_role_assignments`). This proves SSO is enforced and access is role-based for SOC 2 CC6.1/CC6.2/CC6.3. **JUDGMENT — sibling kind, NOT the monitoring kind:** this is an IAM surface, not a monitoring surface, so it gets its own kind rather than widening `monitoring.alert_config.v1`. **JUDGMENT — the over-collection / secret + PII boundary (DOMINANT, load-bearing):** the connector NEVER collects a SAML private key, an OAuth client secret, an LDAP bind password, a signing certificate, or any individual user / team-member / role-assignment identity (name / email / login). The boundary is enforced **structurally**: the record types (`RawProvider` / `RawTeamStats` / `RawRoleStats` / `Provider` / `AccessConfig`) have NO field that can hold a secret or an identity BY CONSTRUCTION, the decode structs in `client.go` omit every secret/identity JSON key so `json.Decode` discards them (the SAML `settings` blob and team-member rows are never materialized), and a reflection guard (`TestStructuralOverCollectionGuard`) FAILS THE BUILD the moment a secret/identity-named field is added. A drop test (`TestClient_NeverLeaksSecretOrPII`) feeds a fake API response that deliberately embeds a SAML private key, OAuth client secret, LDAP bind password, signing cert, and a user email/login/name, and asserts none reaches a record. The schema carries `x-default-scf-anchors=[IAC-06, IAC-22]` (Authenticator Management + Least Privilege) and is registered in `DefaultSeed` (the schema-drift bijection passes with the new kind). **JUDGMENT — auth-scope minimum + Admin warning (this slice owns it):** reading SSO settings needs MORE than 488's Viewer role; the precise additional read-only fixed-role permissions (`fixed:settings:reader` = `settings:read` on `settings:auth.*`; `fixed:roles:reader` = `roles:read` + `users.roles:read` + `teams.roles:read`) are documented in `grafanaauth.RequiredAccessConfigScopes()` and surfaced by the `permissions` subcommand, which WARNS against granting Admin "to be safe". **Anti-criteria (P0):** push only — no platform-side wire change (invariant #3); read-only API only — NO write/admin scope; the token is never logged or placed into a record; `profiles_supported=[pull]` named honestly (NOT continuous monitoring). **Bounded (DoS guard):** per-endpoint decode cap (`maxItems`) + bounded body read + run timeout. sha256 content-hash per record; hour-truncated `observed_at`; register-per-run; stable `actor_id=connector:grafana:ssoconfig@<version>`. Neutral fixtures only (obviously-fake `FAKE-*` keys/secrets; no real-looking Grafana tokens or SAML keys). New shared-package lines (`grafanaauth.RequiredAccessConfigScopes` + permission constants) ship fully tested — `grafanaauth` holds its 98% ratchet (measures 100%). Tests: collector unit (normalize/dedup/clamp/drop-empty/error-propagation), client unit (the secret+PII drop test + collect-shape + role-mappings-captured + bounded-cap + HTTP-error), the structural over-collection guard, the record-builder unit (kind/idempotency/payload allow-list/omit-empty-providers-and-mappings), the `run`-seam push/collect/error tests, and the schemaregistry drift/bijection test.
