- **feat(calendar): slice 668 — highlight today in the month grid.** The compliance calendar month grid (`/calendar?view=month`) did **not** visually mark the current day — a standard calendar affordance was missing (audit **ATLAS-014**, 2026-06-10 empty-tenant UI audit). The today cell now carries a distinct treatment: a subtle `bg-primary/10` tint plus an emphasized `text-primary font-semibold` day number, kept visually separate from hover (muted background) and selection (the stronger popover-open ring). A new pure helper (`web/components/calendar/is-today.ts`, extracted so vitest can pin it without the React tree) exposes `isSameLocalDay` / `isToday(cell, reference)`; the reference "now" is injected (a single `new Date()` captured once per render at the view call-site), so the detection logic is deterministic under test. The today computation compares LOCAL calendar dates — matching how the grid already keys its day cells — so it never mis-marks for users east/west of UTC near midnight. **AC-1** the current day's cell is visually highlighted, distinct from selection/hover; **AC-2** the today cell carries `aria-current="date"` for assistive tech (slice-331 a11y discipline); **AC-3** the highlight tracks the actual current date (injected reference, not a hardcoded value). **Anti-criterion honored:** zero change to calendar data, event rendering, or the week/agenda views beyond the today marker. New vitest pin (`is-today.test.ts`, 8 cases) + a per-file coverage floor in `web/coverage-thresholds.json`; a live Playwright assertion (`web/e2e/calendar.spec.ts`, needs no seed data) asserts the month grid marks today with `aria-current="date"` and the real day-of-month. **Type: AFK.** Slice doc: `docs/issues/668-calendar-month-highlight-today.md`.
