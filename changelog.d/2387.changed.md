- **fix(connectors): the Slack retention record defaults to `scf:DCH-27` Media & Data Retention (#2387, follow-up to #1977).** **Upgrade note:** the Slack connector's `--retention-control-id` default moves from `scf:DCH-04` (Data & Asset Classification, carried over by the #1977 remap) to `scf:DCH-27`, the retention control. The `slack.retention_settings.v1` schema's `x-default-scf-anchors` is now `["DCH-27"]`, down from `["DCH-04", "DCH-27"]`. A connector run on its defaults stamps the new code once you upgrade it. If you pass `--retention-control-id scf:DCH-04` by hand, or in a scheduler or manifest, change it to `scf:DCH-27`, or keep it on purpose. Evidence already ingested keeps the `control_id` it was pushed with, so records from before and after the change sit under different controls, and carrying evidence across is a manual step. An install that has already registered `slack.retention_settings` 1.0.0 keeps its stored default anchors, because the boot import skips a kind and version that is already present. The table is in the upgrade guide. Crosswalk rationales that quoted the pre-2026.3 title "Data Retention" (two ISO 27001, one SOC 2) and one PCI DSS rationale that misnamed `DCH-27` now say "Media & Data Retention".
