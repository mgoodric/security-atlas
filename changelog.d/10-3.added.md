- **feat(oscal): slice 494 — Assessment-Results export carries the drawn sample evidence + walkthrough attachment refs.** Canvas §8.2 defines the OSCAL Assessment-Results artifact as "sampled evidence records + auditor annotations" and §8.3/§8.5 define a walkthrough as a narrative **plus** attachments exported as observation evidence — but two pieces shipped unwired in the AR exporter (`internal/oscal/aggregate.go`, `assessmentInput()`): the `SampledEvidenceIds: nil` placeholder meant the AR told an auditor "we drew N of M" but **not which N**, and the walkthrough loop had no attachment handling so the captured screen-grabs/transcripts were absent. An AR that omits the sampled records sends the auditor back to a spreadsheet — the gap most likely to break the v1 "the auditor works in our tool" promise. This slice wires both. **(1) Drawn sample (AC-1/AC-2/AC-3):** each `SamplePopulation` now carries its `sampled_evidence_ids[]`, **read from the persisted `sample_evidence` rows** (slice 026 materializes the realized Fisher-Yates draw at draw-time over the frozen population) rather than recomputing at export — the slice's compute-vs-persist JUDGMENT call, resolved to "read the persisted draw" because the seed lives on `samples` not `populations`, the persisted rows are frozen-correct **by construction** (invariant #10), and reading them is cheaper than re-shuffling (slice-028 spirit, D1). A new join query `ListSampledEvidenceForPeriod` (populations → most-recent sample → sample_evidence, ordered by ordinal = shuffle order) carries the draw; the `nil` placeholder + comment are removed; a never-sampled population honestly carries an empty set. **(2) Walkthrough attachments (AC-4/AC-5):** each `Walkthrough` carries its attachment refs (id, filename, content hash, content type, annotation ref, storage URI) via a new `ListWalkthroughAttachmentsForPeriod` query and a new `WalkthroughAttachment` proto message; the Python bridge maps them onto the walkthrough's **`observation.relevant-evidence[]`** (`href` = object-storage URI, content hash/type/annotation as props) — the OSCAL-native, single-hop home that co-locates the evidence with the walkthrough it evidences and round-trips cleanly through compliance-trestle (D2, vs. back-matter resources). The attachment **bytes are never embedded** — referenced by hash + URI only (P0-494-2); the signed bundle is the integrity layer. A per-walkthrough cap of 50 refs with an honest "N additional attachment(s) not shown" overflow note bounds AR size without ever silently dropping evidence (threat-model D, D3). **Invariant #10 (the load-bearing concern):** the draw runs over the frozen population, never live data — proven by an integration test that freezes a period, adds post-`frozen_at` evidence, exports, and asserts the post-freeze record **never** appears in the sampled set (AC-7, P0-494-1). **Tenant isolation (invariant #6):** both new reads run under the same tenant `app.current_tenant` RLS context + transaction as the rest of the aggregate; an integration test proves Tenant A's sampled evidence + attachment hashes never appear in Tenant B's AR (AC-8, P0-494-3). **Reproducibility (§8.3):** re-running `audit/sample.Sample` with the persisted seed against the frozen population yields the exact AR draw (AC-9). **Tests:** fast proto-conversion unit branches (sampled-ids, attachment refs, cap + overflow, filename/annotation helpers) run on every CI run; the load-bearing AC-6/7/8/9 integration tests run through the **real DB read path with a capturing fake bridge** so they execute on every CI integration shard, not only when the optional Python oscal-bridge is present (slice-493 D-test pattern); a separate bridge-gated round-trip test proves wire fidelity (sampled-id props + relevant-evidence survive trestle) and skips when the bridge is unavailable. Extended the bridge pytest's AR test to assert the new sampled-id props + relevant-evidence emission. Does **not** change the AP/SSP/POA&M serializers (P0-494-5), does **not** alter the cosign signing path (P0-494-6), does **not** change the slice-026 sampler determinism contract — it **consumes** the existing draw (P0-494-4), and adds **no** new floored package or integration-shard entry (extends the already-enrolled `internal/oscal`). **Type: JUDGMENT** — the read-persisted-vs-recompute call, the `relevant-evidence`-vs-back-matter OSCAL mapping, the attachment-ref cap, and the additive proto-field shape recorded with confidence + detection-tier in `docs/audit-log/494-ar-sampled-evidence-decisions.md`.
