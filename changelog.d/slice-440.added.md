- **feat(board): slice 440 — board-narrative AI v0 (cited, numeric-verified, per-section approval) (closes 440).** The platform's **highest-risk AI-assist surface** — an AI-drafted board-report section consumed by non-technical board members who take the output at face value, so the hallucination cost is asymmetric. Implements ONE numbered section (`control_coverage_summary`, the most rollup-grounded — every claim numeric and citable) end-to-end against local **Ollama** with **all seven guardrails** wired: **(1) hybrid input** — the LLM sees the deterministic `board.Brief` rollup PLUS bounded, tenant-owned cited control/evidence excerpts (never raw evidence, never pure rollup); **(2) per-section approval** — one section flips at a time; **(3) full prompt+response audit** — every generation writes the slice-498 append-only `ai_generations` row (system prompt + context inputs + raw draft + provenance); **(4) mandatory citations** — every cited id is validated to be in the grounding set AND resolve to a real tenant-owned row under RLS **before** the operator sees the draft, a single unresolvable citation rejecting the whole draft; **(5) numeric-claim verification** — THE defining guardrail: every number in the draft is matched against the deterministic rollup and a single fabricated statistic **auto-rejects** the draft (with the numbered-list markers, cited UUIDs, and the period-end label stripped before extraction, and signed deltas magnitude-matched so the model phrases direction in prose); **(6) section-shape enforcement** — the draft must conform to the numbered template (exact heading + four numbered items in order), freestyle rejected; **(7) editor-mode UX + tone** — the operator cannot approve a section with an unresolved citation, and the slice-182 banned-phrase list is wired INTO the system prompt with a deterministic post-generation banned-phrase gate as the safety net. The deterministic rollup **REUSES the slice-031 brief data path** via a new read-only `board.Generator.Assemble` (no `board_briefs` write), so a coverage number the narrative states is byte-identical to the templated brief's. Migration `20260612050000_board_narrative_ai.sql` adds `board_narrative_sections` carrying the AI-assist approval triple + the four provenance columns (`prompt_version`/`model_name`/`model_version`/`model_provider`) and **ADOPTS the slice-498 shared `ai_assist_human_approver_guard` CHECK** (predicate reused, not re-authored), under four-policy FORCE RLS (invariant #6); the immutable forensic history lives in the `ai_generations` ledger while this table is the editable current-state record. A suppressed draft persists **nothing** (P0-440-4); there is **no auto-approve** path and `human_approved=TRUE` is impossible without a `human_approver` (P0-440-2); generation routes to **local Ollama only** (P0-440-5, cloud opt-in plumbed-but-false). New role-gated verbs `POST /v1/board/narrative/generate` + `POST /v1/board/narrative/approve` (board-report role, gated with the board module under `board.reporting`) + their BFFs. **Cross-tenant isolation proven** by integration tests against real Postgres — a Tenant-B generation citing a Tenant-A control is suppressed (the id is RLS-invisible), the DB CHECK rejects approval without an approver, and each of the four guardrail rejections is proven at the integration tier.
