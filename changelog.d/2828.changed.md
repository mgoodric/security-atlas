- **feat(controls): Okta app assignments carry a classification and whether the app's sign-in policy requires MFA, and cc6_6 MFA on admin apps checks them in SQL (#2828, #1860).** The Okta connector now pushes `okta.app_assignment.v1` at schema 1.1.0. The schema adds `classification` (`admin`, `infrastructure` or `standard`, from the new `--admin-apps` and `--infrastructure-apps` lists of Okta app ids), `sign_on_policy_id`, `sign_on_mfa_required` and `reason`. `sign_on_mfa_required` is read from the app sign-in policy named by the app's `_links.accessPolicy`. It is true when every active rule denies access or requires 2FA, false when any active rule allows 1FA, and otherwise omitted with a reason. `soc2_cc6_6_mfa_external_threats` was a roll-up of the connector's always-inconclusive verdicts. It now fails when an active admin or infrastructure app does not require MFA, and is inconclusive when an in-scope app's MFA could not be read or no app is in scope. An unclassified app passes only if it requires MFA. The connector token now also reads `GET /api/v1/policies/{id}/rules` under its existing `okta.policies.read` scope. **Upgrade note:** the query changed, so on the next boot the stock bundle is superseded by a new version. Owners, evidence, exceptions and risk links stay with the old version and have to be moved by hand. Upgrade the Okta connector with the platform and pass `--admin-apps` / `--infrastructure-apps`. Until then, 1.0.0 records carry neither field and the control stays inconclusive. Classic Engine orgs have no app sign-in policy, so the control stays inconclusive for them.
