- **fix(sso): sign-in no longer tells an unauthenticated caller why the SSO config is unusable; one issuer policy; the OIDC secret key is checked in every mode and has a Helm mount (#2609).** `/auth/oidc/login` and `/auth/oidc/callback` now answer an unusable saved SSO config with a generic 503 ("single sign-on is not available for this organisation"). The reason, such as a non-https issuer or a secret that does not decrypt, goes to the server log only. Saving, preflighting and signing in now check the issuer against one policy, so a config that saves is one that signs in. A set but malformed `ATLAS_OIDC_SECRET_KEY` now stops the server at boot even with `ATLAS_OIDC_LOCAL_MODE=true`. The Helm chart gains `oidc.secretKey.existingSecret`, mounted read-only as `ATLAS_OIDC_SECRET_KEY_FILE`, and `secrets.oidcSecretKey` for dev. The SSO page now explains that the "Link SCIM users when the IdP does not report email_verified" option also lets such an address pass the allowed email domains.
