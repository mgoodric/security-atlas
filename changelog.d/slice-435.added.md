- **test(dbtest): slice 435 — shared integration-test DB/tenant harness package `internal/dbtest` (closes 435).** Extracts the integration-test pool/DSN/tenant-seed/context boilerplate that ~80 suites under `internal/` each re-derived (the slice-353 Q-2 rediscovery cost) into a shared harness, then migrates a representative subset to it. **No production (`!_test.go`) code changes** — test scaffolding only. Three primitives, each `t`-scoped with `t.Cleanup`: `NewAppPool(t)` (the `atlas_app`, NOSUPERUSER NOBYPASSRLS, RLS-enforcing **default** pool), `NewMigratePool(t)` (the privileged BYPASSRLS pool, for append-only cleanup + cross-tenant seeding), `SeedTenant(t, migrate, tables…)` (fresh tenant UUID + FK-safe cleanup), and `WithTenantCtx(t, tenant)` (tenant-tagged context via `tenancy.WithTenant`). **The load-bearing guard is the two separately-named constructors with an RLS-enforcing default and opt-in privilege (AC-3 / EoP):** the harness never silently hands back a privileged pool where an app-role pool is expected — there is deliberately no single `NewTestPool(role)` seam that could default to the BYPASSRLS pool. **RLS-fidelity is re-proven, not assumed (AC-7 / Information-disclosure):** a negative test writes a row under tenant A through a `NewAppPool` pool, switches context to tenant B via `WithTenantCtx`, and asserts the cross-tenant read returns **zero** rows; the **deliberate-weakening sanity check** confirmed the test FAILS ("tenant B saw 1 rows… RLS bypassed") when `WithTenantCtx` is weakened, so it is not a tautological green. The representative subset migrated — `internal/scope`, `internal/risk` (all four integration files), `internal/freshnessdrift` — spans the three real call shapes (RLS-bound read, tenant-seed, append-only cleanup via the migrate pool); all pass under `go test -tags=integration -p 1` against a live Postgres. `internal/dbtest` is enrolled in `scripts/integration-shards.txt` (Leg A) per AC-8 (both enrolment checks pass); the convention is documented in `internal/dbtest/README.md` (AC-6). Big-bang migration of all ~80 suites is explicitly forbidden — the remaining ~80 are a documented follow-on drain (**slice 742**, mirroring the slice-390/402-408 enrolment drain). `-p 1` serialization and the integration no-retry policy are unchanged (AC-10).
