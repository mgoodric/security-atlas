- **fix(atlas): a failed core subsystem now stops the process instead of leaving it running half-dead (#2781).** Before, if the gRPC server failed to bind (or the HTTP server, the NATS evidence consumer, an event subscriber, or the eval, freshness/drift, metrics or staleness scheduler failed), `atlas` kept running without it and `/health` still answered. The first such failure now cancels the run loop, everything drains, and `atlas` exits 1 with all collected errors, so the supervisor restarts it (`restart: unless-stopped` in the compose bundles). Notification and housekeeping loops (exception expirer, overdue notifiers, roster sync, control-import sweeper, digest scheduler) still log and retry on their next tick. Decisions: `docs/audit-log/2781-fatal-subsystems-decisions.md`.
