- **feat(connectors): slice 652 — Kubernetes admission-webhook + policy-engine evidence.** Adds two evidence kinds to the Kubernetes connector (slice 487) — `k8s.admission_webhook.v1` + `k8s.admission_policy.v1` — the "is hardening enforced beyond namespace PSS labels?" surfaces an auditor asks about once PSS labels (slice 524) are covered. Unlike slice 524 (which reused the held `namespaces` grant), this slice **deliberately adds new read-only ClusterRole rules** — the **flagged scope expansion** it owns. A new `connectors/k8s/internal/admission` collector mirrors the slice-487/524/525 pattern (`admission.CollectWebhooks` / `admission.CollectPolicies` ↔ `pss.Assess`, `admission.WebhookClient` / `admission.PolicyClient` over the shared slice-621 `k8slist.ListAll` paginating reader + the slice-622 `Reader.Probe` CRD-presence probe, `idem.AdmissionWebhookKey` / `idem.AdmissionPolicyKey`, `buildAdmissionWebhookRecord` / `buildAdmissionPolicyRecord`). **Admission webhooks** (`k8s.admission_webhook.v1`): the new `admissionregistration.k8s.io` `validatingwebhookconfigurations` + `mutatingwebhookconfigurations` `get,list` rule (`k8sauth.AdmissionWebhookRule`). Per webhook entry the record carries CONFIG metadata — `webhook_kind` (validating/mutating), config + entry names, `failure_policy` + derived `fail_closed`, `side_effects`, `has_namespace_selector` / `has_object_selector` (selector **presence**, never the match expressions), `target_service` (the dispatch `namespace/name`, never the raw URL), and the deduped+sorted `intercepted_resources` / `intercepted_operations` sets. **Third-party policy engines** (`k8s.admission_policy.v1`): OPA/Gatekeeper (`templates.gatekeeper.sh constrainttemplates`) and Kyverno (`kyverno.io clusterpolicies` + `policies`), each detected by an **API-discovery probe** so an **absent engine is never an error** (the slice-622 pattern). Per policy the record carries `engine`, `policy_name`, `scope` (cluster/namespaced) + `namespace`, `policy_kind`, and `enforcement_action` + derived `enforcing`. **JUDGMENT — THE load-bearing config-metadata-only guard:** the webhook `.clientConfig.caBundle` / TLS client key and the policy Rego/CEL decision-logic body physically **cannot** enter a record. Enforced **structurally**: (1) the `RawWebhook` / `Webhook` / `RawPolicy` / `Policy` structs have no caBundle / TLS / body field; (2) the webhook client does not model `caBundle` / `url` / any TLS field, and the policy client does not model the Gatekeeper template `targets[]` (Rego) or the Kyverno `spec.rules[]` (CEL/JMESPath) — the json decoder discards them; (3) a reflection guard (`TestStruct_ConfigMetadataOnly_NoBodyOrTLSFields`) FAILS THE BUILD on any field name hinting at a caBundle / TLS key / rule body / intercepted payload; (4) `TestReduceWebhook_DropsCABundleAndURL` + `TestPolicyDecode_DropsRegoAndCELBody` feed fixtures with a REAL caBundle + URL + TLS key and a REAL Rego + CEL body, serialize the whole record, and assert none of those markers ever appears. **JUDGMENT — the ClusterRole grant:** `k8sauth.AdmissionWebhookRule()` adds the one webhook get/list rule; `k8sauth.PolicyEngineRules()` adds the optional `templates.gatekeeper.sh` + `kyverno.io` get/list rules; `AdmissionEvidenceClusterRole()` = base + webhook + policy rules. Every new rule stays `get,list`-only, names its resources EXPLICITLY (no wildcard), and never touches `secrets` — pinned by three new least-privilege tests; the base `DocumentedClusterRole()` is unchanged. `permissions --admission` prints the role WITH the new rules. **JUDGMENT — kind shape (D1):** TWO sibling kinds, not one combined kind (webhook configs and policy-engine policies have disjoint field sets — the slice-488→533 sibling-split precedent). **JUDGMENT — Gatekeeper catalog-only (D5):** v0 reads the static, NAMED `constrainttemplates` (which policies are DEFINED) and leaves the Gatekeeper `enforcement_action` unset — reading each constraint's action would require a **wildcard grant** over the dynamic per-template constraint CRDs, deliberately avoided to honor the no-wildcard anti-criterion (Kyverno's resources are static, so its action is read directly). **JUDGMENT — anchors:** both kinds `x-default-scf-anchors=[CFG-02]` — verified present in the bundled SCF catalog (the same configuration-hardening anchor the PSS + workload kinds use); `--webhook-control` / `--policy-control` default to `scf:CFG-02`. **Anti-criteria (P0):** push only — no platform-side wire change (invariant #3); `profiles_supported=[pull]`; config metadata only — never a caBundle / TLS key / Rego/CEL body / intercepted payload (the structural guard); `get,list` only — no write verb, no wildcard, no `secrets`; the `pull` interval is named honestly (NOT continuous monitoring). Both records are **descriptive** (`INCONCLUSIVE`); the evaluator owns the fail-open / coverage call. Both kinds run by default in `run` (no opt-in flag — they read no Secret material), skippable via `--skip-admission-webhooks` / `--skip-admission-policies`. sha256 content-hash per record; hour-truncated `observed_at`; register-per-run; stable `actor_id=connector:k8s:admission-webhook@<version>` / `connector:k8s:admission-policy@<version>`. Schemas (`k8s.admission_webhook/1.0.0.json` + `k8s.admission_policy/1.0.0.json`, `additionalProperties:false`, NO caBundle/body property) registered in `DefaultSeed` (the slice-068 drift bijection passes). Per-run caps (`maxWebhooks=5000`, `maxPolicies=20000`). Neutral fixtures only (`test-cabundle-should-be-dropped` / `test-rego-body-should-be-dropped`; no vendor-shaped PEM/cert literals).
