- **fix(edge): slice 676 — raise nginx worker_connections + upstream keepalive for RSC prefetch bursts (closes 676).** The 2026-06-10 demo-tenant UI audit (**ATLAS-026**) saw pervasive **HTTP 503** on Next.js App Router RSC requests (`?_rsc=...` GETs) across `/dashboard`, `/dashboards/metrics`, `/board-packs`, and metric-detail pages — dozens of `?_rsc=` GETs 503ing in a single session. A 2026-06-12 scout removed the confounders (the three data-error pages the 503s concentrated on — board-packs **673**, OSCAL component-definitions **659**, metrics **677** — are now ALL MERGED on `main`) and root-caused the residual: the 503s originate at the **edge nginx proxy** (`deploy/docker/proxy/nginx.conf`), NOT in app code. App Router prefetches the RSC payload of EVERY visible `<Link>` as it enters the viewport, so a single navigation to a link-dense page fans out into many concurrent `?_rsc=` GETs in one burst; the proxy was capped at **`worker_connections 64`** (sized for the slice-470 single-login XFF e2e) and opened a **fresh upstream socket per request** (no keepalive, no HTTP/1.1 upstream), so the burst exhausted the connection budget and nginx 503'd the overflow. **Fix (`nginx.conf` only — no app code, routes, or Next.js config touched):** raise `worker_connections` **64 → 1024** (a single deliberate value, comfortably above any realistic prefetch fan-out while staying inside the `nginx:alpine` image's default 1024 open-file budget); add `keepalive 32` to `upstream atlas_upstream` so the burst reuses warm upstream sockets instead of churning a fresh connect/teardown per request; and add `proxy_http_version 1.1` + `proxy_set_header Connection ""` in `location /` (both MANDATORY for the keepalive to take effect — nginx defaults to HTTP/1.0 to the upstream, and a forwarded client `Connection: close` would defeat reuse). The slice-470 hard X-Forwarded-For overwrite (`203.0.113.10`) and every other client-facing header are preserved verbatim — the keepalive directives are added alongside, never in place of them. **No rate-limiting, no caching layer** (out of scope). **Validated:** `nginx -t` against `nginx:1.27-alpine` (the image `docker-compose.proxy.yml` pins) confirms the full config — all four new directives in their correct contexts — is valid grammar (with the compose-DNS `atlas` upstream stubbed to a resolvable address; the real-name run's only error is the expected `host not found in upstream "atlas:8080"` outside the compose network, identical to the pre-slice config). The **end-to-end `?_rsc=` 503-rate re-measure (the AC)** needs a live edge stack + a real browser prefetch storm — out of scope for this bounded worktree fix and not fronted by any CI surface — so the maintainer re-measures it on the deployed edge box after Watchtower rolls the edge channel; the proxy capacity/keepalive fix is the deliverable. **Type: JUDGMENT** — the `worker_connections`/`keepalive` values, the minimal-safeguard scope (no `proxy_next_upstream`/cache), and the verified-vs-needs-live-stack split recorded in `docs/audit-log/676-rsc-503-nginx-tuning-decisions.md`.
