- **fix(catalog): stock controls re-bind on a title-only SCF anchor change (#2321, amends #1971 D3).** When a new SCF release keeps a code and only changes its title, the boot-time re-bind (`atlas-cli catalog import-scf`) now moves a stock control to the current release's anchor instead of flagging it. A control is stock when its stored `control.yaml` is byte-identical to a revision the platform shipped under `controls/soc2/` (sha256 list in `internal/api/scfimport/stock_manifests_gen.go`, regenerated by `scripts/gen-stock-control-hashes.sh`), so a tenant cannot mark its own control as stock. Tenant-authored controls are still flagged and listed by `GET /v1/controls/needs-reanchoring`; pinned controls are still never moved; a code SCF reused for another control, or one the remap table moves, is not a title-only change. An `open` remap proposal (#1775) for a control the re-run re-binds becomes `rebound`. **Upgrade note:** the stock `soc2_cc8_1_change_management` control, flagged on `CHG-02` after #1974, re-binds on the next boot and earns CC8.1 credit again.
