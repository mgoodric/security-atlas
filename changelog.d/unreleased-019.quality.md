- **test(auth): de-flake the `internal/auth` rotation-grace + session-TTL integration tests (surfaced by the 742 batch-3 CI run).** `TestAPIKeys_RotationGraceWindow` set a **real 50ms** `rotationGrace` and used `time.Sleep(75ms)` to cross the boundary; on a loaded CI runner the `Issue`→`Rotate`→`Authenticate(predecessor)` DB round-trips could outrun the 50ms window before the "within grace" assertion ran, expiring the predecessor early (`apikeystore: unknown key` at `integration_test.go:194`). The grace boundary is enforced **purely Go-side** (`Rotate` sets `retires_at = clock()+grace`; `Authenticate` rejects when `clock().After(retires_at)`; the SQL only fetches by hash), so the test now drives the existing **slice-371 `WithClock` seam** with a mutex-guarded virtual clock — advance by `grace/2` for the within-grace assertion, by a further `grace` for the post-grace rejection — making the boundary **deterministic with no `time.Sleep`** (verified 5× under `-race`). Same fix-class for `TestSessions_CreateReadRevoke`, which set a tight **100ms** session TTL but **never asserts expiry** (it covers create/read/revoke); the TTL is widened to `time.Hour` so a slow CI `Create`→`Read` can no longer outrun it. Test-only, no production code, no behavior change to the grace/TTL semantics. The package stays on integration shard leg B1 (`scripts/integration-shards.txt` unchanged).
