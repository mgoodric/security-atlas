- **feat(web): names in place of user IDs (#2085).** A `<Person>` component (`web/components/ui/person.tsx`) and resolver (`web/lib/person.ts`) turn a user ID, a `user:` subject or an API key ID into a person: an active user reads as their name (with initials where an avatar fits), a disabled user as "Former user", an API key as "API key (owner: <name>)", and anything unresolvable as "Unknown" with the ID in the tooltip only. Action plans (list owner and detail owner), audit periods ("Created by" on the list, "Frozen by" on the detail page) and personnel checklist items ("completed by") use it. It reads a new `GET /v1/people`, which every signed-in role may call: the caller's tenant's users (id, display name, status) and API keys (id, owner), under RLS on the app pool, so a super-admin sees only the tenant they are signed in to. It returns no email address (a blank display name falls back to the email's local part on the server), and no token, prefix or last four characters of a key. The admin user and credential endpoints are unchanged. The remaining pages follow in a follow-up issue.
