- **feat(connectors/1password): the 1Password connector emits `1password.org_policy.v2` from documented APIs, and stock control cc6_3 privileged account management reads it (#2968).** v1 read `GET /v1/account`, which no 1Password documentation describes, so its two-factor, password-length and domain-restriction fields had no verifiable source. v2 drops them. It reads the Events API introspect endpoint for `org_id` (the account UUID) and `audit_events_enabled` (the Events Reporting integration is authorized for audit events), and the Users API for `active_members` and `suspended_members`. The connector needs two credentials, both from the environment only: `ONEPASSWORD_EVENTS_TOKEN`, and `ONEPASSWORD_USERS_CLIENT_ID` / `ONEPASSWORD_USERS_CLIENT_SECRET` for an OAuth application granted `users.view`. The `--token` flag and `ONEPASSWORD_SERVICE_ACCOUNT_TOKEN` are removed. Requests refuse redirects to another host or scheme. Accounts outside 1password.com set `--events-base-url` and `--users-base-url`. cc6_3 now fails when the audit-event stream is off and is otherwise inconclusive. It never passes, because no documented 1Password API reports 2FA or password rules. The v1 schema stays registered for existing records. **Upgrade note:** cc6_3's query changed, so on the next boot the stock bundle is superseded by a new version. Owners, evidence, exceptions and risk links stay with the old version and have to be moved by hand. Upgrade the 1Password connector and give it the new credentials; until then cc6_3 receives no v2 records and is inconclusive.
