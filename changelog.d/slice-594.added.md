- **feat(web): slice 594 — Slack + webhook per-kind notification settings toggles.** Slice 583 widened the backend per-`(event, channel)` filter to admit the slice-543 `slack` + `webhook` delivery channels (migration `20260608020000_userprefs_slack_webhook_channels.sql` + `internal/auth/userprefs.Channels`), and the generic `GET/PATCH /v1/me/preferences` endpoint already accepts + returns those new cells — but the web Settings → Notifications matrix only rendered `in_app` + `email` columns, so a user could set a Slack/webhook per-kind opt-out only via the API. This slice adds the `slack` + `webhook` columns to that per-event matrix, mirroring the existing `in_app` / `email` columns exactly: each `NotificationRow` now renders four channel checkboxes, toggling a cell PATCHes `/v1/me/preferences` with the `{event:{slack|webhook:bool}}` shape (no new BFF route — the existing slice-108 preferences proxy is a verbatim passthrough that already carries the channels 583 widened), and a cell with no stored row renders enabled (the same slice-108 default-on-missing-row read the email column already uses). The per-kind slack/webhook cell reuses the slice-585 `configured` PRESENCE signal: when the operator has not configured a channel (`configured === false`), that channel's per-kind cells render **disabled** (setting a per-kind opt-out is meaningless if the channel can never deliver), mirroring the master toggle's disabled state; the `configured` reads share the `ChannelMasterToggle` query keys so TanStack Query dedupes (no extra round-trip), and a missing/undefined `configured` keeps the cell interactive (backward-tolerant). The master opt-in remains the OUTER runtime gate (the 583 filter); the per-kind grid mirrors the email column's independent editability (a master-OFF state does NOT disable the per-kind cell). **Anti-criteria (P0):** does NOT expose or accept a user-typed Slack/webhook URL or token — the matrix is a boolean opt-out grid only; the channel target stays operator-configured env (slice-543 P0-543-2 / SSRF boundary, unchanged); does NOT change the master opt-in toggle rows (slice 584 owns those); WEB-ONLY (no `internal/notify` or `internal/api/me` Go change). vitest covers the new column wire shape (`web/lib/api/me.test.ts`: `get/patchMyPreferences` round-trip slack + webhook cells verbatim); the Playwright settings spec asserts the slack/webhook columns render on every event row and that toggling a slack cell PATCHes `/v1/me/preferences`. **Type: code.** Parent: slice 583 (the backend filter); composes with slice 584 (the master toggle rows) + slice 108 (the per-event matrix this extends).
