- **fix(authz): an API key bound to a user acts with no more than its label and its owner allow (#2431).** A bound key (`issued_by` set) acted with its owner's full live role assignments whatever its `owner_roles` label said, so a `viewer` key minted for an admin acted as admin, both in OPA and at the handler gates. The `owner_roles` label (not the `api_keys.label` display name from #2384) is now a ceiling: the key holds the owner's live roles that its label names (a free-text owner-role label counts as `control_owner`), and an owner holding live `admin` gets the whole label. An unlabelled bound key now holds exactly its owner's live roles, and no longer the `grc_engineer` it used to derive. So a connector or push key minted by a `viewer`, `auditor` or `control_owner` owner loses evidence pushes and the other `grc_engineer` writes. An owner with no live role, or a disabled owner, gives no access. Unbound keys, admin- or approver-flagged keys, JWT sessions and OAuth clients are unchanged. Upgrade note: `scripts/dry-run-2431-bound-key-ceiling.sql` counts, per tenant, the bound keys that lose roles, unlabelled ones included. Re-mint any key that needs a role its label doesn't name, and grant `grc_engineer` to the owner of any unlabelled connector key that must keep pushing (or re-mint it unbound).
