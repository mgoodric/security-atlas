- **fix(authz): an API key bound to a user acts with no more than its label allows (#2431).** A bound key (`issued_by` set) acted with its owner's full live role assignments whatever its `owner_roles` label said, so a `viewer` key minted for an admin acted as admin, both in OPA and at the handler gates. The label is now a ceiling: the key holds the owner's live roles that its label names (a free-text owner-role label counts as `control_owner`), and an owner holding live `admin` gets the whole label. An owner with no live role, or a disabled owner, gives no access. Unlabelled bound keys, unbound keys, admin- or approver-flagged keys, JWT sessions and OAuth clients are unchanged. Upgrade note: `scripts/dry-run-2431-bound-key-ceiling.sql` counts, per tenant, the bound keys that lose roles. Re-mint any key that needs a role its label doesn't name.
