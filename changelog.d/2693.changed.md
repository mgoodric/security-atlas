- **fix(risks): `GET /v1/risks` refuses an inverted review-due range (#2693).** A `review_due_from` after its `review_due_to` is now a 400 (`review_due_from must not be after review_due_to`) instead of an empty page, which matches what saving a view already refused (#2692). The check lives in the endpoint's filter parser, so the register and saved-view validation use the same rule. A view stored before #2692 with an inverted range loses both ends of the range when it is read; its other filters still apply. **Upgrade note:** an API client that sent an inverted range and relied on the empty result now gets a 400.
