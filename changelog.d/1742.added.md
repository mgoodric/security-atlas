- **feat(evidence): import historical evidence with its real date (#1742).** `POST /v1/evidence:import` and `atlas-cli evidence import --historical <file.jsonl> --source "<origin>"` load prior-period evidence (last year's audit results, history from another tool) with its real `observed_at`. Admin credentials only; any other credential gets `403` and writes nothing. The batch is all or nothing and runs each record through the normal ingest pipeline; the past skew limit is lifted for this path only, and a record more than 24h in the future is still refused. Push, pull, subscribe, webhook, attest and upload keep the symmetric 24h check. Imported records carry `ingestion_path = import` and the batch (`import_batch_id`, source, importer) in their provenance, and every accepted and refused attempt writes an `evidence_audit_log` row with the new `import_batch_id` column. `ingested_at` is the real write time. A record dated inside an open audit period joins it. One dated inside a frozen period fails the whole import and names the period, unless the period is named with `--amend-frozen <id>` (`amend_frozen` in the API); then the period is re-frozen as a new freeze revision: the original `frozen_at` and `frozen_hash` are unchanged and replayable, the new `revision_hash` covers the added records, both hashes are written to the period's audit log, and the period reads `amended_by_import` in the API and **Amended by import** on its page. Control state, sample draws, the frozen evidence summary and auditor access read the latest revision. `manual.attestation.v1` schema 1.3.0 adds optional `period_start`, `period_end` and `report_reference`. New docs page: "Onboarding a past audit". Migration `20261306000000_evidence_historical_import` adds `audit_period_freeze_revisions`, `evidence_audit_log.import_batch_id` and the `import` ingestion path.
