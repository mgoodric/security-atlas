- **feat(policies): synced policies keep their page's version history, and unbumped edits are caught as drift (#2851).** On `POST /v1/policies:sync`, a page whose declared version changed becomes the next version of its policy. The new version is published with the previous synced row as its predecessor, and that row is superseded in the same transaction. The new version keeps the previous version's control links. Staff are asked to acknowledge it afresh, and the superseded version can no longer be acknowledged. A page whose body changed without a version bump writes no version and no audit row. Instead the drift is recorded on the policy: when it was first seen, and the hash of the body the page holds now. The policy API returns this as `sync_drift` on `GET /v1/policies/{id}` and `GET /v1/policies`. Drift clears when a later run's body matches the published version again, or when the page arrives with a new version. The run report now distinguishes `created`, `new_version`, `unchanged`, `drift` and `skipped`, with a count of each. A `new_version` result names its `predecessor_id` and a `drift` result its `drift_detected_at`. Migration `20261281000000_policy_sync_drift` adds the two drift columns, under a CHECK that allows them only on synced rows and only together.
