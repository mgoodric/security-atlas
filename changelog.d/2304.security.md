- **fix(notify): webhook and Slack delivery re-check the SSRF deny list at dial time and never follow redirects (#2304).** The webhook target was checked only when configured, so a hostname that later resolved to an internal address (DNS rebinding) got past it, and a 307/308 from a permitted endpoint re-sent the body and HMAC signature to wherever it pointed. Both channels now use one hardened client: every dialled address is checked against the same deny list (loopback, link-local incl. 169.254.169.254, RFC1918, ULA, CGNAT), no environment proxy, redirects refused, and a backstop timeout. **Upgrade note:** a receiver that answers with a redirect now fails every delivery with `post status 3xx: redirect not followed`; configure the final URL. The Slack channel gains the dial-time guard it previously lacked. Decisions log: `docs/audit-log/2304-webhook-ssrf-dial-time-decisions.md`.
