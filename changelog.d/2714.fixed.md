- **fix(exceptions): expired Idempotency-Keys are swept, and equivalent request bodies hash the same (#2714).** `exception_idempotency_keys` rows older than the 24h window are now deleted hourly, per tenant under RLS. Before, a key sent once was kept forever. The request hash no longer depends on the predicate's JSON key order, or on whether `compensating_controls` is omitted, `null` or `[]`. A key recorded before the upgrade still replays, because a request is also checked against its pre-upgrade hash. The API docs now say that a replay returns the exception's current state. Upgrade note: one migration grants the app role DELETE on `exception_idempotency_keys`, limited to keys past the 24h window.
