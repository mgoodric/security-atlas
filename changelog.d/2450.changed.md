- **feat(owners): vendor owner changes get their own audit log; MCP risk tools take `owner_user_id`; exports name the owner (#2450).** A vendor's owner change is now written to the new append-only `vendor_audit_log` (migration `20261260000000`), naming the caller's principal (a person's user id, else the key or client id, never the nil uuid), and shows in Activity as kind `vendor`, with its before/after visible to anyone who can read vendors. Changes written by #2129 stay in `me_audit_log` until a separate, approved copy (`scripts/dry-run-2450-vendor-owner-audit.sql` counts them). The MCP `create_risk` and `update_risk_treatment` tools take `owner_user_id`, refused unless it names an active user of the organisation, as the REST API refuses it. The risk-register export appends `owner_user_id` and `owner_name` (the name `/v1/people` shows); the vendor export appends `owner_user_id` and `owner_name` (display name only, so no email local-part is exported).
