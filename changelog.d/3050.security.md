- **fix(audit): the original freeze of an audit period is immutable in the database (#3050).** Once `frozen_at`, `frozen_hash` or `frozen_by` is set on an `audit_periods` row, a trigger refuses any UPDATE that changes it, for every role, including a reset to NULL; the single NULL-to-value transition at Freeze still works, and so does an INSERT of an already-frozen row (demo seed, fixtures). A second trigger keeps `audit_period_freeze_revisions` an unbroken chain: revision N is accepted only on a frozen period whose latest revision is N - 1, with `previous_hash` equal to that revision's hash. Migration `20261307000000_audit_period_freeze_immutable` (with down file). **Upgrade note:** a frozen period can no longer be reopened by a direct UPDATE; a deliberate recovery has to disable `audit_periods_freeze_immutable_trg` as the table owner in its own transaction.
