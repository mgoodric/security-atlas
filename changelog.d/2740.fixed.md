- **fix(credstore): two concurrent revokes of one API key write one `api_key_revoke` audit row, not two (#2740).** Both revoke paths, the gRPC `AdminCredentialsService` (`apikeystore.Persister.RevokeAudited`) and the HTTP admin route (`apikeystore.Store.Revoke`), now read the key with the new `GetAPIKeyByIDForUpdate` (`SELECT ... FOR UPDATE`), so a second replica waits for the first to commit, sees `revoked_at` set and writes nothing. Revoking an already revoked key over HTTP no longer moves `revoked_at` later. Integration tests force the race with an outside transaction holding the row lock and assert exactly one row on each path, with `revoked_at` equal to that row's `occurred_at`.
