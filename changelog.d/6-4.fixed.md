- **fix(search): slice 661 — index SCF anchors so an empty tenant's controls are findable (closes 661).** Global header search returned NOTHING for control / SCF-anchor queries (`encryption`, exact `CRY-04`) on a fresh tenant even though the anchors are present in `/controls` + `/catalog/scf` (UI-audit ATLAS-002). **Root cause:** `internal/api/search/search.go` searched only the tenant-scoped `controls` (instantiated controls), `risks`, and `evidence` tables — there was no `scf_anchors` (catalog) branch. On an empty tenant there are zero instantiated controls; the ~53 bundled SCF anchors live in the catalog and were unindexed, so the operator's most natural query returned nothing. **Fix:** a new `anchors` result type + `searchAnchors` branch matches the bundled `scf_anchors` catalog against `scf_id` (so `CRY-04` matches by code) AND `title` + `description` (so `encryption` matches by name), returning `"<scf_id> — <title>"` hits that link to `/catalog/scf/{id}`. The anchor query reads the catalog via a plain pool query (`queryCatalog`), NOT the RLS-bound tenant path (`queryInTenantTx`): `scf_anchors` is platform-bundled, tenant-AGNOSTIC reference data (no tenant_id, no RLS — migration `20260511000001_scf_anchors.sql` line 24), so this is **invariant-#6-safe by construction** — there is no tenant column to leak across. The controls/risks/evidence branches stay RLS-tenant-scoped exactly as before. Latest-version dedup mirrors `ListSCFAnchorsLatest` (`slug='scf' AND status='current' AND tenant_id IS NULL`) so a multi-version catalog returns each anchor once. The `anchors` type is wired end-to-end: backend result `Type` + `parseTypes` admit-map, the BFF passthrough (`web/app/api/search/route.ts` — no whitelist; the upstream owns validation), and the ⌘K popover (`web/components/shell/global-search.tsx` — new "SCF anchors" group rendered first, linking to the catalog detail page). The `anchors` OPA resource-type is already a public catalog read (`policies/authz/defaults.rego` `catalog_resources`), so no policy change was needed. **AC-5 latency:** the reported multi-second `CRY-04` hang was NOT the anchor query — `EXPLAIN ANALYZE` measures 0.14 ms over a bounded (~62 sample / ~1,400 full) catalog seq scan; a leading-wildcard `ILIKE` cannot use a btree index and the row count does not justify `pg_trgm` GIN infra (slice 268 P0-A2 defers full-text). The hang was cold-start + the sequential per-type fan-out (4 round trips on the first request to a fresh server); **no index, no migration** added. Integration test `TestSlice661_AnchorSearch_EmptyTenant` (real Postgres) seeds the bundled catalog + a zero-control tenant and asserts `q=CRY-04` and `q=encryption` return anchor hits while a second tenant's matching control is NEVER returned (invariant #6); it fails decisively without the fix (`got hits=[]`).
