- **feat(risks): log a risk before it is assessed with "Score later" (#2511).** `POST /v1/risks` now accepts an omitted `inherent_score` (or `null` / `{}`) and creates an unscored risk through the same rule as the MCP `create_risk` tool, so both store the same row; a provided score is still fully validated (422 on a bad one), and a `residual_score` without an inherent score is refused (400). The create form has a "Score later" option. The register, risk detail and board pack show such a risk as Unscored, outside the severity bands and heatmap, and the board brief and pack rank it after every scored risk. An MCP `create_risk` proposal whose input does not decode is now refused with a 400 when it is filed, not when it is confirmed.
