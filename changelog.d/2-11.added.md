- **feat(cli): slice 464 — `atlas evidence verify` ledger-wide integrity walk (+ `SELF_HOSTING.md` migrate-prose fix).** Slice 432's restore drill surfaced that `atlas evidence verify` — referenced by the BCP/DR plan, `SELF_HOSTING.md`, and the restore runbook — **did not ship**: only `evidence push` existed. This slice adds the operator-facing verb. `atlas evidence verify` walks the append-only evidence ledger (keyset-paginated, `--page-size`, streaming for large ledgers), recomputes each record's canonical hash from its persisted columns via the **same `canonjson` primitive** the ingest path uses, and reports any record whose stored `hash` no longer matches — a silently-corrupted or tampered record. **READ-ONLY** (canvas invariant #2 — never mutates the ledger). **Role-correct (AC-2):** a tenant-scoped walk (`--tenant <uuid>`) runs as `atlas_app` under RLS (transaction-scoped `app.current_tenant` GUC); the cross-tenant walk (`--all-tenants`, super-admin) uses the documented `SET LOCAL ROLE atlas_service_account` path (BYPASSRLS, reachable only from `atlas_app`), **never a superuser connection**. A new migration grants `atlas_service_account` **SELECT-only** on `evidence_records` so the cross-tenant read works without a write grant. **Exit codes:** 0 = clean (zero mismatches), 1 = mismatches found, 2 = operational error. **Load-bearing design call (D1):** the ingest hash covers the full `EvidenceRecord` proto **including `scope`**, but the wire `scope` is **not persisted** in the ledger (only the empty `scope_id` column) — so the original scope-inclusive ingest hash is provably **not reproducible** from a ledger row (confirmed empirically). The verify contract is therefore "the stored `hash` equals the canonical hash of the record **as reconstructable from the ledger**"; this faithfully detects any mutation of the persisted columns (payload, result, kind, …) — the dominant tamper surface. Aligning the ingest hash to be ledger-reproducible (persist canonical scope) is filed as a follow-up. **AC-3 proven on a live Postgres:** an integration test in the (coverage-excluded, already-shard-enrolled) `internal/evidence/ingest` package pushes a record via the real `Process`, asserts a clean walk reports zero mismatches, then **deliberately corrupts the `payload` column out-of-band** and asserts the walk detects the hash divergence (stored=`ee07b0c0…` recomputed=`cb2a577b…`); the CLI's four exit paths were exercised end-to-end against the live binary. **Secondary fix (AC-5):** `docs/SELF_HOSTING.md` step 5 documented `docker compose exec atlas atlas migrate up`, a subcommand the platform binary does **not** expose; corrected to the real `atlas-bootstrap` one-shot. **Docs (AC-4):** `docs-site/docs/backup-restore.md` drill now runs `atlas evidence verify --all-tenants` alongside the signed-OSCAL-export verify; the "not yet present" admonition is removed. **AC-6** (`docs/governance/business-continuity.md`, slice-373-owned) references now resolve to the real command — left to that doc's owner per the BCP/DR plan §11 annual-review reconciliation (not edited unilaterally).
