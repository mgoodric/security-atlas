- **fix(eval): slice 495 — control-as-code `sql` and `jsonpath` evidence queries now actually evaluate (were silently ignored).** The control-bundle format accepts three evidence-query languages (`rego | sql | jsonpath`) at upload and persists them, but the evaluation engine only ran `rego` — `internal/eval/engine.go` filtered to `q.Language == "rego"` and silently dropped `sql`/`jsonpath`. A control authored entirely in SQL or JSON-path uploaded successfully and then evaluated to **no state** (the worst failure mode for a GRC tool: a control that looks configured but does nothing). **Fix:** the engine now dispatches EVERY declared evidence query and rolls the per-query results up through the existing precedence (any `fail` → `fail`; else any `pass` → `pass`; else `inconclusive`; else `na`). **SQL** runs read-only and evidence-only — against a single tenant-scoped `evidence` CTE materialised from the in-window record set (NOT a raw DB handle), inside a `READ ONLY` transaction with an empty `search_path` and a `statement_timeout`; a static guard rejects multi-statement input, any write/DDL/DML keyword, and any schema-qualified reference other than the `evidence` CTE — so the query cannot reach another tenant's evidence or any non-evidence table (constitutional invariants #2 read-only evaluation + #6 RLS tenant isolation). **JSON-path** runs in-process (no DB reach) against each in-window record's JSONB payload under a per-query timeout. A query whose language is unsupported or unparseable now **fails loudly** (inconclusive + surfaced error), never the prior silent no-op. **Proof:** integration tests prove a `sql`-only and a `jsonpath`-only control each evaluate to a real pass/fail state (was: no state), a malicious SQL query attempting to read `evidence_records` / `users` / another tenant **errors** (load-bearing cross-tenant test), a SQL query exceeding `statement_timeout` returns `inconclusive` rather than hanging, and a mixed rego+jsonpath control rolls up consistently; pure-Go unit tests cover the JSON-path classification, the SQL static guard, and the mixed-language rollup. `internal/eval` merged coverage 79.2% (floor ratcheted 73 → 77).
