- **feat(connectors/datadog): host memory, 5-minute CPU p95 and disk use from Datadog; a1_1 checks them (#2935).** The Datadog connector run with `--capacity-production-scope <tags>` (e.g. `env:production`) reads the metrics query API (`GET /api/v1/query`, which needs the `timeseries_query` permission on the Application key). It pushes one `monitoring.host_capacity.v1` record per host in that scope, with `memory_used_percent`, `cpu_p95_5m_percent` (computed by the connector from `system.cpu.idle` at a 15-second rollup) and `disk_used_percent` (the fullest device). The new kind is routed by type; `--capacity-control` defaults to empty. Without the flag the surface is skipped, so existing keys keep working. Every Datadog request now refuses a redirect to another host or scheme. `soc2_a1_1_capacity_monitoring` gains a second SQL query over the new kind that checks all three readings at the same bounds; its osquery query is unchanged. The control fails when either query fails and passes when either passes, so Fleet's disk reading alone is still never a pass. The fixtures are built to Datadog's documented response shape and nothing was verified against a live tenant. **Upgrade note:** a1_1 is superseded on the next start.
