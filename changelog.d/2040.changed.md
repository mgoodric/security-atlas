- **fix(web): per-browser login throttling; web vets `X-Forwarded-For` (#2040, follow-up to #1913).** The web container now loads `web/peer-chain.cjs` (`node --require`), which replaces the `X-Forwarded-For` on every inbound request and WebSocket upgrade with the client IP it resolves from its own socket peer and the new `WEB_TRUSTED_PROXY_CIDRS`. The login BFF forwards that address to atlas, and so do the `/v1`, `/health` and `/metrics` rewrites, upgrades included. A malformed `WEB_TRUSTED_PROXY_CIDRS` stops web at boot. **Upgrade note (compose):** `web` has left the implicit `default` network and now sits only on a new `bffnet` (`10.125.0.0/29`, web `10.125.0.2`, atlas `10.125.0.3`; override with `ATLAS_BFF_SUBNET` / `WEB_BFF_IP` / `ATLAS_BFF_IP` if that range collides with a host network, or `docker compose up` fails with a pool-overlap error). atlas's `TRUSTED_PROXY_CIDRS` now defaults to web's address; if you set it yourself, add `10.125.0.2/32` (or your `WEB_BFF_IP`). Anything you attached to web over the default network must now reach it through its published port. **Helm:** set `atlas.trustedProxyCIDRs` and `web.trustedProxyCIDRs` (usually the pod CIDR) to get per-browser buckets; both default empty.
