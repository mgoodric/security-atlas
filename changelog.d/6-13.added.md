- **feat(infra): slice 510 — automated backup + scheduled restore-verification (operationalizing the slice-432 runbook).** Slice 432 documented the _manual_ backup/restore procedure and explicitly scoped automation out ("that would be a code slice" — P0-432-4); slice 373's BCP/DR RTO/RPO tiers cannot be met by a runbook a solo operator might forget to run. **This is that code slice.** A new `internal/backup` package + two **in-process tick-loop schedulers** (mirroring the exception-expiry / metrics schedulers — **no external cron** for the single-VM self-host target — D1) turn the documented procedure into a running feature, with **zero new docker-compose services** so the four self-host-bundle CI legs (bundled / external / proxy / migrate) keep their exact topology. **What runs each cycle (defaults: daily):** (1) **AC-1 scheduled backup** — a **pure-Go logical dump** (`pg_dump` is deliberately NOT shelled out: the atlas runtime is `distroless/static` — no shell, no psql, no pg*dump — D2) writes a self-contained schema-+data SQL stream; (2) **AC-2 pluggable backup-target** — one `Target` interface (`Put/Get/List/Delete`), a `LocalTarget` (default volume) + an `S3Target` (off-host durability, integration-tested against MinIO), mirroring the evidence object-storage abstraction (D3); (3) **AC-3 retention/rotation** — operator-configurable keep-N-daily + M-weekly (default 7+4), old backups rotate out so storage never grows unbounded (P0-510-3); (4) **AC-4 the load-bearing half — scheduled restore-verification** — restores the latest backup into an **ephemeral throwaway database**, runs a smoke check (schema lands, a sentinel query returns), then **DROPs the ephemeral DB in a `defer` on every path including failure** (P0-510-2: no standing second copy — an integration test asserts zero `atlas_restore_verify*%`databases remain); (5) **AC-5 integrity** — every backup carries a **sha256** recomputed-and-checked **before** any replay, so a corrupted artifact **fails verification loudly** and is never restored (integration test tampers an artifact → hash-mismatch fail); (6) **AC-6 status + alerting** — every run writes an **append-only`backup_runs`status record**, and a FAILURE raises an **in-app notification composing with the slice-445 email channel**. **The load-bearing security boundary (AC-7 / P0-510-1, enforced at the DB grant layer — not application code):** a backup is a **full cross-tenant copy** that deliberately crosses the RLS boundary (invariant #6), so it is a **deployment-privileged operation** — the backup scheduler runs as the BYPASSRLS migrator role, and the new **deployment-scope`backup_runs`table is granted to`atlas_migrate`ONLY, never`atlas_app`** (the RLS-enforced tenant-reachable role). A tenant-facing handler therefore *cannot* read or trigger a backup: its role has zero privilege on the table — proven by an integration test asserting `permission denied`for`atlas_app`on both SELECT and INSERT. The crown-jewel dump is contained at the deployment tier, integrity-checked before any restore, and the restore lands only in a disposable DB. **Scope discipline (out):** PITR/WAL archiving (logical-dump is the v1 RPO mechanism), Helm/K8s backup operators, cross-region replication, and rewriting the slice-432 runbook / slice-373 BCP/DR plan (this operationalizes + cross-links only — P0-510-4).
