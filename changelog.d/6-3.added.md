- **feat(auth): slice 509 — IdP group-to-role mapping (closes 509).** The authorization-derivation sibling of slice 508: 508 provisions the user, 509 maps their IdP **groups** to atlas **roles** — so a single IdP group change reprovisions access. Because it ASSIGNS ROLES (the thing 508 deferred per P0-508-3), the **security model is the load-bearing part**. New `internal/auth/grouprole` ships ONE resolver fed by TWO **already-validated** sources (AC-2): the OIDC `groups` claim (read in `oidc.HandleCallback` ONLY after signature/issuer/audience/nonce verification — P0-509-2; surfaced on `CallbackResult.Groups`) and the SCIM-Group path; both call `Resolver.Derive` so the mapping logic cannot diverge (an integration test drives both sources through it and asserts identical derivation). Migration `20260612030000_idp_group_role_mappings.sql` adds `oidc_idp_group_mappings` (keyed `(tenant, idp_config_id, group_ref, role)` — `idp_config_id` NULLABLE: NULL = the SCIM/IdP-agnostic source, non-NULL = a specific OIDC config, so a tenant's two IdPs map independently per AC-6; idempotent via a `COALESCE`-the-NULL unique index, AC-1) + an append-only `group_role_audit_log` (every group-derived grant/revoke records the triggering group + source, AC-7) + an additive `user_roles.origin` column (`'manual'` | `'group-derived'`, DEFAULT `'manual'` so existing rows/fixtures need no backfill), all under four-policy FORCE / append-only RLS (invariant #6). **Fail-closed (P0-509-1 / AC-3):** an unmapped group has no mapping row, so it grants NOTHING — the table IS the allow-list; a user in multiple mapped groups gets the **union**. **Manual roles survive re-derivation (AC-4):** re-derivation only DELETEs/INSERTs `origin='group-derived'` rows (the DELETE carries an `AND origin='group-derived'` safety belt), never a manual row. **Last-admin guard (AC-5 / P0-509-3):** a re-derivation that would remove the tenant's final admin is **suppressed** (the user keeps the group-derived admin), so an IdP membership change can never lock a tenant out. **No auto-created roles (P0-509-4):** a mapping may only target one of the 5 canonical atlas roles — the CRUD handler + store validate via `authz.IsCanonical` before the INSERT, with the DB CHECK as backstop. Admin-gated CRUD (AC-8): `POST`/`GET /v1/admin/group-role-mappings` + `DELETE …/{id}` (403 below admin; `internal/api/admingroupmappings`). The intricate precedence/conflict/guard JUDGMENT is a pure function (`planReconcile`, 11-case table test); the resolver applies it in one transaction. **Cross-tenant isolation, fail-closed, manual-survival, and the guard are all proven by integration tests against real Postgres.** Coverage floors: `internal/auth/grouprole` 77, `internal/api/admingroupmappings` 72. **Deferred (named honestly):** the live session-mint `Resolver.Derive` call after user upsert + a full SCIM `/Groups` REST resource are thin follow-on adapters over the proven resolver. **Type: JUDGMENT** — the nullable-source key, the manual/group-derived precedence, the manual-survival contract, the suppress-don't-error last-admin guard, and the validated-source contract recorded in `docs/audit-log/509-idp-group-role-mapping-decisions.md`.
