# #2534 — OIDC issuer requests through one shared SSRF guard

detection_tier_actual: manual_review
detection_tier_target: unit

Found while fixing #2304. A tenant admin's SSO issuer URL was checked only by
the adminsso preflight at save time. At sign-in, go-oidc and oauth2 used
`http.DefaultClient` for discovery, JWKS and the token exchange: no dial-time
IP check, redirects followed, environment proxy honoured. The JWKS and token
URLs come from the discovery document, so they were never checked at all.

## Decisions

| #   | Decision                                                                                                                                                                                                                                                  | Why                                                                                                                                                                                                                                                           |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | The deny list, `DialControl` and `NewHTTPClient` move to a new neutral package `internal/netguard`. `notify.SSRFPolicy` keeps its API and delegates; adminsso's `isUnsafeIP` and hand-rolled dialler are deleted.                                         | One deny list for webhook, Slack, preflight and sign-in, so a range added once covers every outbound surface. Keeping `notify.SSRFPolicy` stable leaves webhook and Slack behaviour and tests untouched.                                                      |
| D2  | The Authenticator builds its client once (`netguard.Policy.NewHTTPClient`, 30 s backstop) and passes it through `oidc.ClientContext` for discovery and `oauth2.HTTPClient` for the exchange. The provider keeps the discovery client for JWKS.            | go-oidc v3.21 stores the discovery context's client on the Provider and uses it for `remoteKeySet`, so one injection covers JWKS. Verified by `TestJWKSFetchGoesThroughGuard`.                                                                                |
| D3  | Redirects are never followed on any IdP request (`ErrUseLastResponse`).                                                                                                                                                                                   | OIDC Discovery §4 serves the document at the issuer path; no step of the code flow the RP drives needs the RP to follow a redirect. Re-validating hops was not needed.                                                                                        |
| D4  | Opt-in is `ATLAS_OIDC_ALLOW_PRIVATE_ISSUERS`, deployment-level only. It permits loopback, RFC1918, ULA and CGNAT; link-local (cloud metadata) and every other reserved range stay denied. Values other than `true`/`false`/unset stop the server at boot. | Dispatcher: super-admin or deployment level, never a tenant admin. No per-tenant column exists, and adding one would need a super-admin surface. An env var is the smallest fail-closed control. Metadata is never a legitimate IdP.                          |
| D5  | adminsso's existing `AllowPrivateIPs` maps to the same policy and is set from the same env var. Previously it disabled every check, link-local included.                                                                                                  | Preflight and sign-in now agree. The opt-in no longer reaches cloud metadata.                                                                                                                                                                                 |
| D6  | NAT64 `64:ff9b::/96` and 6to4 `2002::/16` are judged by the IPv4 they embed, not denied outright.                                                                                                                                                         | DNS64 on an IPv6-only network maps every public IPv4 destination into `64:ff9b::/96`; a blanket deny would break real Slack and webhook delivery there. The ticket comment's concern is that they "can embed private IPv4", which the embedded check refuses. |
| D7  | New reserved ranges: 0.0.0.0/8, 198.18.0.0/15, 240.0.0.0/4 (covers 255.255.255.255).                                                                                                                                                                      | Ticket comment from the #2536 review. None is a routable public destination.                                                                                                                                                                                  |
| D8  | Upgrade note: a deployment whose IdP resolves to a loopback or private address must set `ATLAS_OIDC_ALLOW_PRIVATE_ISSUERS=true`, or OIDC sign-in fails as "provider unavailable".                                                                         | Fail closed is the point of the change. Changelog and configuration docs carry it.                                                                                                                                                                            |
