# #3038 — live ingest under the freeze lock: build-time decisions log

detection_tier_actual: manual_review
detection_tier_target: integration

Written in #3060, from the #3058 review's non-blocking findings (N1-N7). Two of those were defects the PR review caught and no test did:

- domain writers answered 500 on `ErrConcurrentFreeze` (N1);
- the eval clock test passed with the database clock reverted to the app clock (N5).

Both are now pinned at the integration tier, plus unit tests for the HTTP mappings. Each was mutated and observed failing before being restored:

- `TestProcessInTx_FreezeBetweenBeginAndLockRefuses`: with the audit mapping removed, `decision rejected_internal_error`.
- `TestProcessInTx_RefusesAboveReadCommitted`: with the isolation check removed, `repeatable read: err <nil>`.
- `TestEvaluateControl_EvaluatedAtIsTheDatabaseClock`: with the engine on `time.Now`, `evaluated_at ... is 5.167ms behind now; want about 30m0s`.
- `TestWriteErr_ConcurrentFreezeIs409` (incidents) and `TestWriteCompleteErr_ConcurrentFreezeIs409` (personnel security): with the case removed, `status = 500`.

## Decisions

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                            | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | `Process` retries a write refused by `ErrConcurrentFreeze` in a new transaction, at most three attempts (`ingest.MaxFreezeAttempts`). The historical import shares the bound and the loop (`ingest.RetryConcurrentFreeze`).                                                                                                                                                                         | Each retry follows a freeze that committed during the previous attempt. Three freezes of the same tenant in a row, each inside one ingest's milliseconds-long window, is not a load the product produces, so a third refusal is reported rather than retried forever. A bound keeps a pathological freeze loop from pinning a connection.                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| D2  | `ProcessInTx` does not retry. It returns `ErrConcurrentFreeze`, and a domain writer's handler answers `409` with code `concurrent_freeze` (`httpresp.WriteConcurrentFreeze`). The historical import already answered that way. Every `Process` surface now does too once its three attempts are spent: push (HTTP 409, gRPC `ABORTED`), control attestation submit, and MCP write-proposal confirm. | The caller's transaction already holds the domain rows (an incident's close, a checklist completion), and ingest cannot restart it. Nothing was written, the request is sound and a retry succeeds, so it is a conflict and not a server fault. A 500 would also hide the body (`httperr.WriteInternal`), so the client could not tell a retryable conflict from a crash. `ABORTED` is gRPC's code for a concurrency conflict to retry at a higher level.                                                                                                                                                                                                                                                                                                                              |
| D3  | The refusal is audited as `rejected_concurrent_freeze`, a new `evidence_audit_log` decision (migration `20261310000000` widens `evidence_audit_log_decision_chk`). Both the widened CHECK and the down migration's narrow one are added `NOT VALID`.                                                                                                                                                | `rejected_internal_error` reads as a platform fault, and an operator triaging "why didn't my write land" would chase a bug that is not there. The only readers of the token set are the CHECK, `Decision.String` and the docs page, all updated; the admin audit-log view builds `evidence.<decision>` without enumerating it. The audit log is append-only, so a rollback cannot rewrite rows already written; `NOT VALID` binds new rows only. Up is `NOT VALID` too (review N-2): the widened set contains the old one, so every existing row already passes, and validating would only scan the whole log under the ALTER's ACCESS EXCLUSIVE lock and stall every ingest. A quiet-window note was the alternative, but it asks an operator to schedule a scan that proves nothing. |
| D4  | Live evaluation does not take the tenant evidence-freeze lock. A row whose transaction began before an evaluation's T and committed after its ledger read is missed by the live result at T. The `eval.Scheduler` sweep is the backstop (hourly by default).                                                                                                                                        | Taking the lock would serialise every evaluation against every ingest in the tenant. A live evaluation is a current-state view that the next evaluation supersedes, not a stored commitment like a freeze hash, so a miss is temporary. The first head said the row's own ingest would trigger a later evaluation. That holds only for rows on the JetStream stream: domain-writer, MCP-applied and direct-publisher rows publish nothing, so for them the sweep is the only backstop (N2).                                                                                                                                                                                                                                                                                            |
| D5  | The concurrent-freeze check fails closed outside READ COMMITTED (`ingest.ErrIsolationLevel`, a 500). The level is read in the same statement as the count, so it costs no extra round trip.                                                                                                                                                                                                         | The check needs a snapshot taken after the lock is granted, and only READ COMMITTED takes a fresh one per statement. Under REPEATABLE READ the snapshot comes from the transaction's first statement, which for `Process` is the idempotency lookup, before the lock. A freeze committed in between would read as zero, and the row would join a population its hash never covered. No caller uses another level today (pgx defaults to READ COMMITTED). A doc comment alone would not stop a future caller or a server-side `default_transaction_isolation` (N4).                                                                                                                                                                                                                     |
| D6  | `Freeze` sets no `lock_timeout`. ADR 0003 records that new ingests in the tenant stall while a freeze waits for the exclusive lock (N3), and for a historical import's whole batch (up to 10,000 records), which holds that lock in exclusive mode.                                                                                                                                                 | The stall is bounded by the longest open ingest transaction plus the freeze's own hash and UPDATE. Ingest takes the shared lock just before its INSERT, so both are short. A `lock_timeout` would turn that brief stall into a failed freeze the admin must retry, plus a new error mapping, The hazard it would bound is a hung transaction holding the shared lock, which is better bounded database-wide (`idle_in_transaction_session_timeout`, not set by this change) than per freeze. Revisit if a freeze is seen waiting in production.                                                                                                                                                                                                                                        |
| D7  | The eval clock test shadows `clock_timestamp()` with a function 30 minutes behind, in a schema at the head of the test pool's `search_path`. The engine must then report an `evaluated_at` about 30 minutes in the past and count neither the live nor the replayed row.                                                                                                                            | When the two clocks agree they cannot be told apart, so the old assertion passed against a revert to the app clock (N5). The engine's clock query (`DBClockNow`) calls `clock_timestamp()` unqualified, and `pg_catalog` is searched where `search_path` lists it, so the shadow wins only for that pool. `ingested_at`'s `DEFAULT now()` is unaffected.                                                                                                                                                                                                                                                                                                                                                                                                                               |
| D8  | `historicalimport.ErrConcurrentFreeze` wraps `ingest.ErrConcurrentFreeze`, and both call sites use `ingest.CheckNoFreezeSinceTxStart`.                                                                                                                                                                                                                                                              | One sentinel to match and one check, so the isolation assertion (D5) covers the import as well (N6). The lock-waiter filter by `objid = hashtext(tenant)` that N6 also asked for landed in #3067.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
