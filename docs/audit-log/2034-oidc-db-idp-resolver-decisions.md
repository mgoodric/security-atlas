# #2034 — OIDC sign-in reads the saved SSO config

detection_tier_actual: manual_review
detection_tier_target: integration

## Behaviour on main before this change (confirmed)

`cmd/atlas/main.go` built the Authenticator with `localModeIdpResolver{}`,
whose `ResolveIdp` returned `oidc.ErrUnknownIdp` for every tenant and name.
Nothing in the production binary read `oidc_idp_configs`, so:

- `/auth/oidc/login` answered 400 "unknown IdP" for every tenant. The
  production binary did no OIDC sign-in at all, which is the #2007 review's
  finding, not just one that ignored saved settings.
- What `PATCH /v1/admin/sso` saved (issuer, client, secret, domains,
  `trust_unverified_email_for_link`) reached no sign-in.
- `client_secret_enc` held the raw secret bytes. The handler comment called
  encryption "a v1.x follow-up".
- There was no env-configured IdP. "Local mode" meant password login at
  `/auth/local/login` plus that no-op resolver.

Shown by `TestSavedSSOConfig_*` (`internal/api/auth`): with the resolver
swapped back to the no-op, `AppliesAtSignIn`, `EnforcesAllowedDomains`,
`TrustFlagGovernsAbsentClaimLinking` and `UnknownIssuerRefused` fail. The two
refusal tests pass either way, by design.

## Decisions

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                     | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | `internal/auth/idpconfig.Resolver` is the production `oidc.IdpResolver`. It reads the `(tenant_id, name)` row through `GetOidcIdpConfigByName` in a transaction carrying that tenant's RLS GUC. It refuses with `ErrUnknownIdp` when the context's tenant differs from the argument, and when the row's `tenant_id` differs from the one asked for.                                                          | The flow already binds tenant and IdP name to the state HMAC (#1968, #2177). `(tenant_id, name)` is UNIQUE, so a lookup matches at most one row and cannot be ambiguous. RLS keeps another tenant's row out of reach, and the two equality checks still hold if a policy regresses.                                                                                                                                                                                  |
| D2  | The lookup key is the flow's IdP name, not the token's `iss`. The token is then bound to the row: go-oidc refuses a discovery document whose `issuer` is not the configured URL and checks `iss` and `aud` (`client_id`). `HandleCallback` also compares `idTok.Issuer` to `cfg.IssuerURL` exactly.                                                                                                          | The row is chosen before any token exists, so it cannot be chosen by matching `iss`. Exact string equality against one row leaves no prefix or substring match anywhere. `TestSavedSSOConfig_UnknownIssuerRefused` sends a token from another issuer through the saved IdP's endpoints, and it is refused.                                                                                                                                                           |
| D3  | No row means `ErrUnknownIdp` (400 at login). A row that exists but cannot be used is `ErrConfigUnusable`: a non-https issuer, an empty client or redirect, no secret key on the deployment, or a secret that does not decrypt. Nothing falls back to another row, tenant or resolver.                                                                                                                        | Fail closed. The table has no `disabled` column, so "disabled" is not a state to check. The refusal is logged with tenant, config id and reason. The reason strings are fixed text and never hold the secret.                                                                                                                                                                                                                                                        |
| D4  | Client secrets are sealed with AES-256-GCM (`idpconfig.SecretCrypter`). The key comes from `ATLAS_OIDC_SECRET_KEY` or `ATLAS_OIDC_SECRET_KEY_FILE`. The additional data is the tenant id plus the length-prefixed IdP name, and stored values carry an `atlas-idp-secret-v1:` prefix.                                                                                                                        | Matt's decision: secrets are `op://` or encrypted references, never plaintext. The server has no `op` CLI or 1Password access at runtime, so an `op://` reference could not be resolved at sign-in; sealing is the option that works. The pattern matches `internal/llm/cloud.Crypter` (key from the deployment, never beside the ciphertext). The additional data means a value copied into another tenant's row does not open (`TestResolver_CrossTenantRefused`). |
| D5  | Secrets saved before #2034 (no prefix) are refused at sign-in, with the reason "re-enter it on the SSO settings page". They are not migrated.                                                                                                                                                                                                                                                                | Before this change no sign-in could use them, so nothing that worked breaks. A migration cannot seal them, because the key is not in the database. Re-saving takes one PATCH.                                                                                                                                                                                                                                                                                        |
| D6  | PATCH seals a non-empty secret, and an empty one still means leave-existing. With no key configured, PATCH refuses a secret with 503 and stores nothing. PATCH also runs the resolver's issuer check.                                                                                                                                                                                                        | Never store a secret the sign-in path cannot read or that is not sealed. If a config saves, the resolver accepts its issuer.                                                                                                                                                                                                                                                                                                                                         |
| D7  | Issuer rule: absolute `https` with a host, and no userinfo, query or fragment. `http` is accepted only on a loopback host, and only with `ATLAS_OIDC_ALLOW_PRIVATE_ISSUERS=true` (its `AllowLoopback`).                                                                                                                                                                                                      | This is the dispatcher's "non-https refused except loopback in dev", with no new switch. The SSRF guard (#2534) still governs every dial.                                                                                                                                                                                                                                                                                                                            |
| D8  | Discovery and JWKS caching are unchanged: the provider cache has a 30 s TTL (`ProviderCacheTTL`), keyed by issuer, and go-oidc's remote key set refreshes on an unknown `kid`.                                                                                                                                                                                                                               | It is already bounded. Keying by issuer cannot mix tenants: two tenants with the same issuer get the same discovery document, and each is still checked against its own `client_id` and secret.                                                                                                                                                                                                                                                                      |
| D9  | `allowed_email_domains` is matched exactly: the text after the last `@`, compared case-insensitively. Blank entries never match. With a non-empty list, the address must also be verified: `email_verified` true, or absent when `trust_unverified_email_for_link` is on. An explicit false is refused. A refusal returns `ErrEmailDomainNotAllowed`, and the callback answers 403 without naming the email. | The old `HasSuffix(email, "@"+d)` was already immune to `evil-example.com`, but it was a suffix test. The domain of an unverified address is whatever the user typed at the IdP, so it cannot gate the allowlist. An empty list allows every domain, which is the documented behaviour and stays unchanged.                                                                                                                                                          |
| D10 | `trust_unverified_email_for_link` is copied onto `oidc.IdpConfig`, and its column default stays false. When it is off, `users.UpsertOIDC` links only on a verified email, as before.                                                                                                                                                                                                                         | The ticket comment asks for exactly this copy. `TestSavedSSOConfig_TrustFlagGovernsAbsentClaimLinking` shows the saved flag deciding whether an absent claim links.                                                                                                                                                                                                                                                                                                  |
| D11 | Local mode is `ATLAS_OIDC_LOCAL_MODE=true`, for dev only. It wires `LocalModeResolver`, which knows no IdP, so saved configs are ignored and only local login works. Unset or `false` is the DB resolver. Any other value stops the boot.                                                                                                                                                                    | Matt: "keep local mode for dev only, behind an explicit flag." No env-configured IdP existed to keep. Which source wins is now simple: the DB config always, unless the flag turns OIDC off. Local password login works in both modes, and an install with no saved row behaves exactly as before.                                                                                                                                                                   |
| D12 | A missing secret key does not stop the boot, but a malformed one does. The boot line reports `oidc_idp_source=oidc_idp_configs (secret_key_configured=…)`.                                                                                                                                                                                                                                                   | The compose self-host default is local login with no key, and it must keep booting. A typo in the key fails loudly.                                                                                                                                                                                                                                                                                                                                                  |
| D13 | Deferred to the follow-up PR: auditing `PATCH /v1/admin/sso` to `me_audit_log` (it needs a migration widening the action CHECK) and the admin SSO page copy. Scoping email-linking to the IdP config SCIM is bound to (1944 D6) is noted, not done.                                                                                                                                                          | The dispatcher allowed a split, resolver first. Once the resolver is wired, the saved settings apply, so the page needs no "not applied yet" notice. The audit and the SCIM scoping are separate changes, each reviewable on its own.                                                                                                                                                                                                                                |
