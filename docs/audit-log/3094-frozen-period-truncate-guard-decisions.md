# #3094 — OwnerDelete hardening, retryable busy teardown, scoped status reset, TRUNCATE guards: build-time decisions log

detection_tier_actual: manual_review
detection_tier_target: integration

Non-blocking findings from the #3093 review (#3089), plus the `BEFORE TRUNCATE` guard #3089 D8 deferred.

## Decisions

| #   | Decision                                                                                                                                                                                                                                                                                                                                | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | #3089 D8's cascade path was wrong. `TRUNCATE TABLE tenants, users RESTART IDENTITY CASCADE` does not reach `audit_periods` or any frozen-guard table. The TRUNCATEs that do are `TRUNCATE controls ... CASCADE` (reaches `populations`) and `TRUNCATE framework_versions` / `frameworks ... CASCADE` (reaches all four guarded tables). | Measured on a migrated scratch database with the psql `truncate cascades to table` NOTICEs, in a rolled-back transaction, and with a recursive `pg_constraint` walk. The tenants/users truncate cascades to 26 tables (risks, vendors, sessions, ...), none of them period tables. It still wiped every other suite's tenants and users, so item 3 stands.                                                                                                                                                        |
| D2  | `period.OwnerDelete` takes a WHERE fragment and builds `DELETE FROM audit_periods WHERE <where>` itself. The in-place teardown's predicate now names the table (`to_jsonb("<table>".*)`) instead of the alias `t`, so `execTeardownDelete` builds every teardown DELETE from a WHERE fragment the same way.                             | The helper can no longer run arbitrary SQL. An alias in OwnerDelete's statement would have made the WHERE fragment depend on a name the caller cannot see.                                                                                                                                                                                                                                                                                                                                                        |
| D3  | OwnerDelete runs its body in a savepoint and rolls it back on any error.                                                                                                                                                                                                                                                                | A client-side pgx error (an unencodable argument) does not abort the transaction, so before this the transaction stayed usable with the trigger disabled. `TestOwnerDelete_ClientErrorLeavesTriggerEnabled` and the extended `TestOwnerDelete_LockTimeout` both failed with the savepoint removed (trigger state `D`; `25P02` on the next statement) and pass with it.                                                                                                                                            |
| D4  | A `lockTimeout` under 1ms rounds up to `1ms`, never down.                                                                                                                                                                                                                                                                               | `0ms` means no timeout to Postgres. Rounding up keeps the caller's intent (a bound) rather than rejecting a value that is merely small. Unit-tested in `TestLockTimeoutSetting_RoundsUp`.                                                                                                                                                                                                                                                                                                                         |
| D5  | A teardown that hits `lock_not_available` (55P03) on the `audit_periods` lock returns an error wrapping `demoseed.ErrTeardownBusy`. The route answers 503 with `Retry-After: 5` and `code: "teardown_busy"` through `httperr.WriteCodedStatus`; the CLI prints `audit_periods is busy; retry` before the error chain.                   | 503 rather than 409: the request is valid and the conflict is with transient load, not with the resource's state. `WriteCodedStatus` keeps the body generic (no error detail, the #2730 rule) and gives clients a stable code to branch on. Retry-After 5s: the teardown waits 2s for the lock. The web BFF already forwards the upstream status; it does not forward `Retry-After`.                                                                                                                              |
| D6  | The status tests get private copies of `tenants` and `users` through a new `dbtest.NewShadowMigratePool`: a schema of their own, `LIKE ... INCLUDING ALL` copies, and a pool whose `search_path` puts that schema first.                                                                                                                | Scoping the deletes to "own rows" cannot work for these tests: they assert install-wide facts (no bootstrap tenant, the oldest user, an exact tenant count). A separate database would need the whole migration chain per test. `platform.Status` reaches both tables unqualified through the pool it is handed, so the copies isolate it exactly. Shown by a sentinel tenant and user that survive the suite. `internal/api/install_reset_integration_test.go` has the same TRUNCATE; it is outside this ticket. |
| D7  | The TRUNCATE guard refuses only while the table holds a frozen audit's rows: a frozen period, a population with `frozen_at` set or attached to a frozen period, or any freeze revision or control snapshot.                                                                                                                             | An unconditional refusal would fail every integration helper that truncates controls or the catalog, on any database, frozen audit or not. The conditional form refuses exactly the truncate that would destroy a freeze. A TRUNCATE ... CASCADE fires every reached table's trigger first, so one frozen period anywhere refuses the whole statement and nothing is truncated (`TestFrozenNoTruncate_Refused`).                                                                                                  |
| D8  | The guard is on `audit_period_frozen_controls` (#3066) as well as #3050's three tables.                                                                                                                                                                                                                                                 | The snapshot is part of what a freeze commits to; its write-once trigger has the same TRUNCATE gap.                                                                                                                                                                                                                                                                                                                                                                                                               |
| D9  | No Go helper wraps the owner path past the TRUNCATE guard. The path is `ALTER TABLE ... DISABLE TRIGGER audit_period_frozen_no_truncate_trg` in the owner's own transaction, the same as #3081's DELETE path; `TestFrozenNoTruncate_OwnerPathAndOpenRowsOnly` exercises it.                                                             | No product code and no integration helper needs to truncate a table holding frozen rows (see the Leg A run below), so a helper would have no caller.                                                                                                                                                                                                                                                                                                                                                              |
| D10 | The guard function is SECURITY DEFINER, owned by `atlas_migrate`, with a pinned `search_path`, and PUBLIC holds no EXECUTE.                                                                                                                                                                                                             | Same reason as #3085 N-a: it must see every tenant's rows whatever the truncating session's role or tenant context. `TestFrozenNoTruncate_FunctionNotPublic` pins the grant.                                                                                                                                                                                                                                                                                                                                      |
| D11 | `TestFrozenNoTruncate_*` has no behavioural case for a freeze-revision row; it checks the trigger is attached to that table and relies on the shared function.                                                                                                                                                                          | A revision row needs an import batch and evidence records; the cascade cases already show the trigger fires for every table reached.                                                                                                                                                                                                                                                                                                                                                                              |
| D12 | In `unboundrows.go` the SQL column is `retained_kind`, the map is `selfRetained`, and `LedgerTables` is `SelfRetainedTables` (its tests renamed to match). `ledgerTotals` and its helpers keep their names.                                                                                                                             | Since #3089 D5 the map holds both ledger and delete-trigger reasons. The ticket named three identifiers; the totals helpers' error text is pinned by a unit test and their behaviour is unchanged.                                                                                                                                                                                                                                                                                                                |

- `go test -tags=integration ./internal/api/admindemo/`: pass, including `TestTeardown_BusyAuditPeriodsGets503WithRetryAfter`.
- `go test -tags=integration ./internal/platform/`: pass; a sentinel tenant and user in the shared tables survive it.
