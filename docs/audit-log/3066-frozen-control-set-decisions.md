# #3066 — the freeze hash's control set is recorded at freeze: build-time decisions log

detection_tier_actual: manual_review
detection_tier_target: integration

Found in the #3062 re-review (#3050). Freeze and every replay read `control_ids` from the tenant's live catalog, so creating or deleting a control after a freeze broke replay of every revision. No test froze a period and then changed the catalog. `TestFrozenControls_CatalogChangesDoNotBreakReplay` now does. With `revisionHash` reverted to `ListControlIDsForPeriodHash` it fails with `after catalog change: ReplayHash(1) = 7585…, want frozen_hash 9fca…`. With the fix restored it passes.

The #3077 review's guards were each mutated and observed failing before being restored:

- `TestFrozenControls_CommitRefusesFrozenPeriodWithoutSnapshot`: with `audit_periods_frozen_has_controls_trg` disabled, `old-binary freeze at commit: want check_violation (23514), got <nil>`.
- `TestFrozenControls_InsertGuard`: with `audit_period_frozen_controls_insert_guard_trg` disabled, `app snapshot for an open period: want check_violation (23514), got <nil>`.
- `TestOnlyFreezeReadsLiveControlCatalog`: with a second `ListControlIDsForPeriodHash` call added to `revision.go`, it lists both callers.

The approach (record the set; backfill already-frozen periods; hash bytes unchanged) was approved by Matt on 2026-11-24 before the build.

## Decisions

| #   | Decision                                                                                                                                                                                                                                                                                                                               | Why                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | One row per period with a `UUID[]`, not one row per (period, control).                                                                                                                                                                                                                                                                 | The set is read whole and only ever written once. One row makes "no snapshot" a single absent key (fail closed), keeps an empty catalog representable (an empty array), and mirrors `audit_period_freeze_revisions.evidence_record_ids`.                                                                                                                                                                                                  |
| D2  | `source` gained a third value, `seed`, beyond the approved `freeze` and `migration_backfill`.                                                                                                                                                                                                                                          | The demo seed and SQL fixtures insert frozen periods without calling Freeze, with placeholder hashes. Labelling their rows `freeze` would claim a freeze-time commitment that never happened.                                                                                                                                                                                                                                             |
| D3  | The trigger refuses DELETE only while the period exists. `ON DELETE CASCADE` from `audit_periods` removes the row.                                                                                                                                                                                                                     | `atlas_app` holds DELETE on `audit_periods`, and test cleanups, demo-seed teardown and the whole-tenant teardown delete periods. With RESTRICT, or with a trigger refusing every DELETE, each of those would need to disable the trigger. With the period gone there is nothing left to verify.                                                                                                                                           |
| D4  | The demo seed's in-place recording and the legacy-tenant probe skip `audit_period_frozen_controls` (`demoseed.cascadeOwnedTables`).                                                                                                                                                                                                    | In-place teardown deletes recorded rows by key, and a direct DELETE of this table is refused while the period exists. The period's own deletion cascades, so recording the row would only make the removed-rows count disagree with the recorded count.                                                                                                                                                                                   |
| D5  | The owner-only reopen runbook, and the test helper that follows it, remove the snapshot with the trigger disabled in the same transaction.                                                                                                                                                                                             | Freeze inserts exactly one row per period. Without the removal a re-freeze after a reopen fails on the primary key. Keeping the old row would be worse: the new freeze's hash would be replayed against the old set.                                                                                                                                                                                                                      |
| D6  | The backfill (section 6) calls `audit_period_record_catalog_controls(..., 'migration_backfill')` for every frozen period, as `atlas_migrate` (BYPASSRLS). The function's `ON CONFLICT DO NOTHING` makes it idempotent. The integration tests run that section of the migration file verbatim, and the runbook uses it as the recovery. | Idempotent, so the test can run it against a live database that already holds other periods' rows, and an operator can re-run it safely. The tests exercise the exact SQL that ships, not a copy of it.                                                                                                                                                                                                                                   |
| D7  | An empty catalog is recorded as `'{}'`, not NULL (`control_ids` is NOT NULL). Freeze coerces sqlc's nil slice.                                                                                                                                                                                                                         | Caught by the existing period and lifecycle integration tests, which freeze in tenants with no controls. `computeFreezeHash` renders a nil and an empty list identically (`make([]string, 0)`), so the hash was never at risk. Only the insert was.                                                                                                                                                                                       |
| D8  | A `DEFERRABLE INITIALLY DEFERRED` constraint trigger on `audit_periods` refuses any commit leaving a frozen period without its row (#3077 review B1, Matt 2026-11-24). It re-reads the row at commit.                                                                                                                                  | A binary older than the migration keeps serving while the migration applies (Helm `pre-upgrade`, Compose's old `atlas` container). Its freeze would otherwise leave a period that can never be replayed. Refusing at commit keeps the period open and retryable. Re-reading the row means a period reopened or deleted later in the same transaction is not refused. Deferred, so writers may insert the period first and its row second. |
| D9  | A BEFORE INSERT guard accepts a row only for a frozen period, and a `source` other than `freeze` only from a superuser or BYPASSRLS role (#3077 review N1).                                                                                                                                                                            | Matt accepted `seed` with this guard. The role test is `rolsuper OR rolbypassrls` and not the literal name `atlas_app`, so any role bound by RLS is held to `freeze`. The seed (the BYPASSRLS auth pool), the e2e fixtures (CI's `postgres` superuser) and the walkthrough fixtures (`psql -U postgres`) are unaffected.                                                                                                                  |
| D10 | One SQL function, `audit_period_record_catalog_controls`, records a period's current catalog for the backfill, the demo seed and the three fixtures. Freeze keeps its own INSERT.                                                                                                                                                      | It replaces five copies of the same INSERT shape (review, Standards). Freeze must record the exact list it hashed, read once in its transaction, not a second catalog read.                                                                                                                                                                                                                                                               |
| D11 | Every trigger function stays SECURITY INVOKER, with the RLS assumption commented at each check (#3077 review N4).                                                                                                                                                                                                                      | Each checked row belongs to the tenant the writer's RLS context already admits (the WITH CHECK policies require it), and a BYPASSRLS writer sees every row. DEFINER would widen what a caller can read for no gain.                                                                                                                                                                                                                       |
| D12 | DELETE of a frozen period is out of scope.                                                                                                                                                                                                                                                                                             | Matt is filing it as a separate follow-up (2026-11-24). The cascade added here loses nothing extra.                                                                                                                                                                                                                                                                                                                                       |
