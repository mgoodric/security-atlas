# #2177 — OIDC flow: signed state, `__Host-` cookies, clear on mismatch

detection_tier_actual: manual_review
detection_tier_target: unit

Follow-up from the review of #2159 (#1968). The OIDC flow cookies were
unsigned double-submit cookies, so a sibling subdomain able to plant cookies
could assemble a flow the server never issued.

## Decisions

| #   | Decision                                                                                                                                                                                                      | Why                                                                                                                                                                                            |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Do both remedies the ticket offers: `state = rand "." HMAC-SHA256(k, rand, tenant, idp, nonce)` and `__Host-` flow cookie names when `ATLAS_SECURE_COOKIES=true`.                                             | Layered: `__Host-` stops the planting in the browser; the HMAC still binds the flow where the prefix cannot be used (plain-HTTP dev). Dispatcher call on the ticket.                           |
| D2  | Fields are length-prefixed and domain-separated (`atlas-oidc-state-v1`); the MAC is compared with `hmac.Equal`.                                                                                               | No two field lists encode to the same bytes; constant-time comparison.                                                                                                                         |
| D3  | Key: `ATLAS_OIDC_STATE_KEY` (≥ 32 bytes) when set, else `HMAC-SHA256(BEARER_HASH_KEY, "atlas-oidc-state-key-v1")`. A set but short value stops the boot.                                                      | Never per-process: production runs several replicas and a callback may land on another one. `BEARER_HASH_KEY` is already mandatory and shared, so existing deploys need no new secret to boot. |
| D4  | An `Authenticator` without a ≥ 32-byte key refuses `BeginLogin` and `HandleCallback` (`ErrStateKeyInvalid`).                                                                                                  | Fail closed rather than issue an unsigned state.                                                                                                                                               |
| D5  | With secure cookies the callback reads only the `__Host-` names; bare cookies are ignored. Flows begun before the deploy fail once with a 400.                                                                | Accepting the bare names as a fallback would reopen the planting path. A flow lives at most 10 minutes.                                                                                        |
| D6  | Plain-HTTP (`ATLAS_SECURE_COOKIES=false`) keeps bare names on `Path=/auth/oidc`. Documented as the dev fallback in `docs-site/docs/configuration.md`.                                                         | A browser drops a non-`Secure` `__Host-` cookie, so the prefix cannot apply there. The switch is the existing operator flag, not a silent per-request downgrade.                               |
| D7  | The `ErrStateMismatch` and `ErrTenantMismatch` 400s clear the flow cookies; other callback errors are unchanged.                                                                                              | Scope of the ticket. A refused flow cannot complete, so its cookies have no further use.                                                                                                       |
| D8  | The tenant check runs before the HMAC check, so a tenant mismatch with the query still reports `ErrTenantMismatch`; a tenant cookie altered to match a hand-edited query fails the HMAC (`ErrStateMismatch`). | Keeps #1968's distinct signal for the common case.                                                                                                                                             |
| D9  | Helm values are not changed; the derived key covers Helm deploys.                                                                                                                                             | Smallest change. An operator who wants a key independent of `BEARER_HASH_KEY` sets `ATLAS_OIDC_STATE_KEY` in the secret.                                                                       |
