# #2115 framework-scope wizard: decisions log

detection_tier_actual: none
detection_tier_target: none

| #   | Decision                                                                                                                                                                                                                           | Why                                                                                                                                                                       |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | The wizard is its own route, `/framework-scopes/new`, reached from the index (**New scope**) and from a version's page (header **New scope** and the empty state's **Create a scope**, both pre-filling `?framework_version_id=`). | Step 1 picks the framework version, so the wizard cannot live on a page keyed by one. Same shape as `/exceptions/new`.                                                    |
| D2  | Submit for approval is two calls: create the draft, then the existing `submit` transition. If submit fails, the draft is kept and the page lands on it with a toast saying so.                                                     | No new route. The UI goes through the same routes as the API.                                                                                                             |
| D3  | The version page's header acts on the working revision: the newest draft, review or approved revision. Row-level Submit / Approve / Activate / New revision buttons are gone.                                                      | A single lifecycle action per page, as the shared header (#2102) expects. Two buttons both named "Approve" would also be ambiguous to a screen reader and to `getByRole`. |
| D4  | "Submit for review" is renamed "Submit for approval".                                                                                                                                                                              | The ticket's wording; the state is still `review`.                                                                                                                        |
| D5  | Approve and the other transitions show the platform's error message instead of a fixed "Approver role required" line.                                                                                                              | A 403 can mean self-approval, a machine credential or a missing role, and only the platform knows which.                                                                  |
| D6  | The row-level JSON editor uses the same `parseAdvanced` as the wizard, so `null` is refused there too.                                                                                                                             | The owner's comment on the ticket: a stored null predicate matches every cell.                                                                                            |
| D7  | The Playwright spec mocks the BFFs with a shared store across two browser contexts (the exception and risk-acceptance specs' pattern).                                                                                             | The demo tenant keeps Allow self-approval on for the seeded scope specs, so the platform would not refuse the submitter. The Go tier covers the rule against Postgres.    |
