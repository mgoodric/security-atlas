# #1699 — replay and freeze reads bound ingested_at: build-time decisions log

detection_tier_actual: manual_review
detection_tier_target: integration

ISC-3 ("any past date is reconstructible from the evidence ledger") and
invariant #10 (audit-period freezing) were both falsified by a record written
to the ledger after the horizon with a backdated `observed_at`. The original
defect was caught by the `isa/probes/ledger-replay.sh` probe (#1698). Two
further gaps in the first version of this fix, the Go copy of the population
bound in the auditor authz hydrator and the demo seed's `ingested_at = now()`,
were caught by PR review. Both belonged in the integration tier. The new
freeze test now asserts the hydrator, and `TestApply_Happy` asserts the demo
seed.

## Decisions

| #   | Decision                                                                                                                                                                                                                         | Why                                                                                                                                                                                                                                                                                                                                                            |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Bound `ingested_at` by the same horizon as `observed_at` in every as-of and freeze-horizon read of `evidence_records`, rather than adding a separate "ledger as of" parameter.                                                   | The horizon is one instant: what the platform knew at T. A record belongs to T only if it was observed and also written by T. One parameter keeps every call site unchanged (the sqlc params structs did not change) and makes live reads (`FarFuture`, `infinity`) pass every row as before.                                                                  |
| D2  | Mirror the bound in Go where the population bound is re-implemented (`internal/audit/authz_attrs.go` `populationHeldAtFreeze`), applying it only to a record (`EvidencePeriods`) and not to a control window (`ControlPeriods`). | `ControlPeriods` asks whether a date range lies inside a frozen population, not whether a record does. There is no ingestion time to compare.                                                                                                                                                                                                                  |
| D3  | Bring the freshness-window fix into scope: `computeRow` measures the window from the evaluation instant (`queryInstant`, the horizon on replay) instead of the wall clock.                                                       | Matt's triage said to fix it here if it could be tested here. A pure-Go unit test (`TestComputeRow_ReplayWindowAnchorsOnInstant`) covers it. Live evaluation's instant is the wall clock, so live behaviour is unchanged.                                                                                                                                      |
| D4  | Leave exceptions as they are: `exceptedIn` still uses the wall clock and today's active set during a replay.                                                                                                                     | Fixing it needs the exception set as of T, which is a different query and outside #1699's acceptance. Filed as #3037.                                                                                                                                                                                                                                          |
| D5  | No migration and no index.                                                                                                                                                                                                       | The existing indexes are `(tenant_id, control_id, observed_at DESC)` and `(tenant_id, evidence_kind, observed_at DESC)`. `ingested_at <= $h` filters heap rows those plans already fetch, and on the live path the bound is `infinity`.                                                                                                                        |
| D6  | Seed fixtures and the demo seeder ingest a past record at its `observed_at` (`LEAST(now(), observed_at)` where a fixture can be future-dated), not at `now()`.                                                                   | Those fixtures model a history: a record observed months ago and a freeze or replay of months ago. Under D1, `ingested_at = now()` would put every seeded record after every past horizon, so the tests and the demo tenant would read an empty frozen period. `LEAST` keeps future-dated records (the ingest skew window) at `now()`, as ingest itself would. |
| D7  | Keep the freeze horizon on the app clock (`time.Now()` in the handler).                                                                                                                                                          | Stamping it from the database inside the freeze transaction would close both the clock-skew gap and the transaction-start gap of `now()`, but it changes the freeze contract. Filed as #3038.                                                                                                                                                                  |
| D8  | Amend ADR 0003 in place with the `ingested_at` bound and the upgrade argument, rather than writing a superseding ADR.                                                                                                            | The decision (content-only hash inputs) is unchanged. Only the definition of the evidence set is corrected, and the ADR is the contract a reimplemented verifier reads.                                                                                                                                                                                        |
| D9  | Leave `AGENTS.md` invariant #10's wording unchanged.                                                                                                                                                                             | The change narrows the invariant in keeping with its intent, but rewording a constitutional invariant is Matt's call.                                                                                                                                                                                                                                          |

## Upgrade note

No stored `frozen_hash` changes. Only `Freeze` calls `ListEvidenceIDsForPeriodHash`, and the product never recomputes or rewrites a stored hash. For an external verifier, a recompute at `frozen_at` reproduces the frozen set, except for a row whose DB-clock `ingested_at` falls after an app-clock `frozen_at` (#3038). Before this change, the stored hash stopped being reproducible as soon as any late, backdated row arrived. See ADR 0003, "Amendment: the ingested_at bound".
